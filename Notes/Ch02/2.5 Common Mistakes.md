Ошибки этого уровня — не про смысл программы, а про чтение грамматики и разбор токенов. Ниже — характерные случаи в формате «проблема → код → как правильно».

## Reading Optionality as a Default

Проблема: `[Throws]` воспринимают как команду подставить отсутствующий раздел. Ниже показана одна альтернатива `MethodHeader` из JLS SE 25 — без параметров типа:

```
MethodHeader:
    Result MethodDeclarator [Throws]
```

Объявления внутри тела класса:

```java
void f() {}                              // раздел throws отсутствует
void g() throws java.io.IOException {}  // раздел throws присутствует
// void h() throws {}                   // ошибка: написано throws, но нет типа
```

Как правильно: `[Throws]` разрешает отсутствие всего раздела. Если `throws` написано, требуется список типов исключений. Полная продукция содержит также альтернативу с параметрами типа; модификаторы относятся к `MethodDeclaration`. Правила объявления методов — Part I, Ch. 8.

## Confusing Grammar Metasymbols with Java Syntax

Проблема: обязательные скобки Java принимают за метасимволы необязательности. В продукции JLS SE 25 терминалы выделены моноширинным шрифтом, а нетерминал — курсивом:

```
*Dims*:

{*Annotation*} `[` `]` {{*Annotation*} `[` `]`}
```

В объявлениях поля класса это различие видно на примерах:

```java
int[] values; // допустимо: обязательная пара скобок присутствует
// int[ values; // ошибка синтаксиса: нет закрывающей скобки
```

Как правильно: первая обязательная пара `[` `]` задаёт одну размерность; внешние фигурные скобки допускают дополнительные пары, а `{Annotation}` — необязательное повторение аннотаций. Полные правила массивов — [[Chapter 13. Arrays]].

## Expecting else to Bind to the Outer if

Проблема: считают, что `else` относится к внешнему `if` по отступам.

```java
if (a)
    if (b) doB();
else doElse();   // на деле else относится к внутреннему if (b)
```

Как правильно: `else` относится к ближайшему допустимому внутреннему `if`. Если нужен `else` внешнего `if`, используйте блок. Фрагмент тела метода; `a` и `b` — доступные переменные типа `boolean`, `doB()` и `doElse()` — доступные методы без аргументов:

```java
if (a) {
    if (b) doB();
} else {
    doElse();
}
```

При `a == false` исходный вариант не вызывает ни один метод, а исправленный вызывает `doElse()`. Полные правила — Part I, Ch. 14.

## Mismatched > in Nested Generics

Проблема: лишний закрывающий `>` во вложенных аргументах типа. Ниже — независимые объявления поля; используется импорт `java.util.List`.

```java
List<List<Integer>>> x = null; // ошибка синтаксиса: лишний >

List<List<Integer>> x = null; // исправление
```

Как правильно: проверьте вложенность аргументов типа. В типовом контексте соседние `>` обрабатываются отдельно, поэтому лишний знак не поглощается оператором сдвига. Правило токенизации — [[3.5 Input Elements and Tokens]]; теория generics — Part I, Ch. 20.
