# 4.2.11 Operations on Primitive Types

Этот раздел — карта того, какие группы операций применимы к каким примитивам; полная семантика операторов (приоритеты, порядок вычисления, все тонкости) — Ch. 15, здесь она не дублируется. Смысл держать карту здесь в том, что «что можно с типом» — часть определения самого типа, и здесь же живёт один неочевидный подвох compound-присваивания.

## Which operations apply to which primitives

Арифметические (`+ - * / %`) — ко всем числовым типам (`byte`, `short`, `int`, `long`, `char`, `float`, `double`), но не к `boolean`; поведение `/` и `%` у целых и вещественных различается (усечение против IEEE 754 — см. [[4.2.1 Integral Types]] и [[4.2.7 Floating-Point Types]]).

Сравнения (`< <= > >=`) — к числовым типам и `char`; равенство (`== !=`) — ко всем примитивам, но у вещественных `==` почти всегда ошибка (см. [[4.2.7 Floating-Point Types]]).

Побитовые и сдвиги (`& | ^ ~ << >> >>>`) — только к целочисленным; `& | ^` работают и над `boolean` как логические без короткого замыкания.

Логические с коротким замыканием (`&& || !`) — только к `boolean`.

Во всех арифметических и побитовых операциях операнды уже `int` продвигаются по правилам числового продвижения ([[4.2.1 Integral Types]], подробно — [[4.2.12 Promotions and Conversions]]).

## The compound-assignment hidden cast

Есть тонкость, которая выглядит как противоречие. Обычное `b = b + 1` для `byte` не компилируется (результат `b + 1` имеет тип `int`), а составное `b += 1` — компилируется. Причина: составные операторы (`+=`, `-=`, `*=`, …) по спецификации содержат **неявное сужающее приведение** к типу левого операнда. Это удобно, но и опасно — приведение может молча срезать биты.

```java
byte b = 10;
b = b + 1;   // compile-time error: int не влезает в byte без приведения
b += 1;      // ок: += втихую приводит результат обратно к byte

byte x = 100;
x += 50;     // компилируется, но 150 не влезает в byte → -106 (тихое переполнение)
```
Правильно: помнить, что `+=` прячет приведение; при риске переполнения считать в `int`/`long` и сужать осознанно.

## Common Mistakes

- Применить `%` к `double`, ожидая «остаток как у целых».

```java
System.out.println(5.5 % 2);   // 1.5 — остаток определён и для вещественных, но это не целое
```
  Правильно: помнить, что `%` работает и на `double`, возвращая вещественный остаток.

- Считать `b += x` безопаснее, чем `b = b + x`. Правильно: это одно и то же по риску переполнения; `+=` лишь прячет обязательное приведение.
