# 4.4 Where Types Are Used

Тип в Java появляется не только слева от имени переменной. Умение узнавать все позиции, где стоит тип, — часть навыка читать чужой код: одно и то же имя типа в разных местах играет разные роли, и в некоторых позициях действуют ограничения, которых нет в других. JLS (§4.11) организует эти позиции в две группы — **контексты объявлений** и **контексты выражений**, — аннотации типов размечают разрешённые грамматикой позиции и не образуют третью независимую группу type contexts. Раздел даёт эту модель и разбирает ограничения, на которые чаще всего натыкаются; правила, специфичные для generics (вывод, wildcards, границы), — Ch. 20, семантика исключений — Ch. 17.

## Declaration contexts

В объявлениях тип задаёт форму объявляемой сущности:

- заголовок класса/интерфейса — типы в `extends` и `implements`;
- границы типовых переменных — `<T extends Number>`;
- типы полей и компонентов записи;
- в методе — тип возврата (в том числе тип элемента annotation interface), типы параметров, throws и receiver-параметр;
- в конструкторе — типы параметров и throws;
- тип явно объявленного параметра лямбды;
- тип локальной переменной, в том числе объявляемой в for, ресурсе try-with-resources или образце;
- тип параметра catch.

Имена типов встречаются также в permits; это полезная позиция для чтения кода, но не самостоятельный type context в каталоге JLS §4.11.

```java
class Box<T extends Number> {              // граница типовой переменной
    private T value;                       // тип поля
    Box(T value) { this.value = value; }   // тип параметра конструктора
    List<T> asList() {                     // тип возврата + аргумент типа
        return List.of(value);
    }
}
```

## Expression contexts

В выражениях тип участвует в вычислении или проверке:

- создание объекта — `new String(...)`;
- создание массива — `new int[10]`;
- явные аргументы типа: в вызове конструктора (`<String>this(...)` или `<String>super(...)`), создании экземпляра (`new <String>Box(...)`), вызове метода (`obj.<String>method()`) и ссылке на метод/конструктор (`Type::<String>method` или `Type::<String>new`). Это схематические формы позиций, требующие подходящего generic-объявления;
- приведение — `(String) o`;
- проверка `instanceof` — `o instanceof String`;
- ссылочные типы в method/constructor references: String::length, String::new, int[]::new;
- литерал класса — String.class: дополнительное упоминание типа, не отдельный type context из перечня JLS §4.11.

В этих позициях используются также элементные типы массивов, аргументы параметризованных типов и границы wildcard-аргументов. `Unbounded wildcard`, многоточие `varargs` и имя типа в объявлении конструктора — специальные синтаксические способы обозначить использование типа. Аннотируемость каждой позиции определяется её грамматикой, а не наличием имени типа.

```java
List<String> xs = Collections.<String>emptyList(); // type witness: явный аргумент типа
List<?> any = new ArrayList<String>();              // wildcard как аргумент типа
Object o = "x";
if (o instanceof String s) { }                      // проверка типа
```

Type witness (`.<String>`) нужен редко — обычно тип аргумента компилятор выводит сам; но когда вывод не справляется, аргумент типа указывают явно, и тогда он должен быть задан полностью (Mughal).

## Type-annotation positions

TYPE_USE-аннотации применяются в разрешённых грамматикой позициях типа, в том числе к элементу и отдельно к измерениям массива. Это не означает, что аннотацию можно вставить перед любым упоминанием имени типа: например, перед `String.class` или именем в `permits` она так не записывается. Определения `@NonNull` и `@Nullable` в примере ниже предполагаются аннотациями с `@Target(ElementType.TYPE_USE)`.

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Target;

@Target(ElementType.TYPE_USE)
@interface NonNull {}
@Target(ElementType.TYPE_USE)
@interface Nullable {}

class AnnotatedArrayDemo {
    @NonNull String @Nullable [] arr;
}
```

## Restrictions that the model enforces

Позиция определяет не только роль типа, но и что там **нельзя** поставить. Четыре ограничения встречаются на практике постоянно.

**Wildcards — только как аргумент типа.** `?` не самостоятельный тип: им нельзя объявить переменную, нельзя создать объект.

```java
List<?> ok = new ArrayList<String>();  // ок: аргумент типа
// var bad = new ArrayList<?>();        // compile-time error: по wildcard нельзя создать объект
```

**Создание массива и instanceof.** Создание массива требует реифицируемого элементного типа. У instanceof другое условие: проверка должна быть разрешена правилами оператора без требуемой `unchecked conversion`. Например, проверка `Object` на `List<String>` запрещена, а `List<String>` на `List<String>` разрешена. Подробности — [[4.3 Reference Types and Values]] и Ch. 20.

```java
class Holder<T> {
    // T[] a = new T[10];                  // compile-time error: generic array creation
    // List<String>[] b = new List<String>[3]; // compile-time error: то же
}
Object o = "x";
// boolean b = o instanceof List<String>;  // compile-time error: проверка Object на List<String> потребовала бы unchecked conversion
```

**Обобщённые типы и исключения.** По Mughal: обобщённый тип не может наследовать `Throwable`; параметризованный тип нельзя указать в `throws`; тип параметра `catch` обязан быть реифицируемым подтипом `Throwable`. Отсюда — обобщённых исключений в Java нет.

```java
// class MyException<T> extends Exception {} // compile-time error: generic не может extend Throwable
```

**Примитивы не идут в аргументы типа.** В generics-позициях тип обязан быть ссылочным: `List<int>` невозможен — нужна обёртка (см. [[4.2.13 Boxing and Unboxing]]).

## var is not a type here

Не всякая «типо-подобная» запись — тип. `var` в объявлении локальной переменной **не тип**, а указание вывести тип из инициализатора; в позициях полей, обычных параметров метода и возврата var недопустим; параметры лямбды допускают отдельную форму с var. Практика `var` — [[4.5 Variables]], полностью вывод типов — Ch. 20.

## Common Mistakes

- Пытаться использовать `var` не как локальную переменную.

```java
var x = 10;              // ок: локальная переменная
// var field;            // compile-time error: var нельзя без инициализатора и не как поле
// void m(var p) { }     // compile-time error: не для параметров
```

Правильно: обычное локальное объявление var требует допустимого инициализатора; формы enhanced for и параметров лямбды перечислены в [[4.5 Variables]].

- Ставить примитив в позицию аргумента типа.

```java
Map<int, String> m;      // compile-time error
```
  Правильно: обёртка — `Map<Integer, String>`.

- Пытаться сделать обобщённое исключение или создать generic-массив.

```java
// class Fail<T> extends RuntimeException {}  // compile-time error
// T[] arr = (T[]) new Object[10];            // компилируется, но с unchecked-предупреждением
```

Правильно: исключение объявлять непараметризованным. Для набора элементов `T` обычно использовать `List<T>`; если необходим массив, обеспечить корректный runtime-компонентный тип. (`T[]) new Object[n]` не является общим исправлением: оно может привести к `ClassCastException` при использовании результата как `String[]`. Полные способы создания generic-массивов — Ch. 20.
