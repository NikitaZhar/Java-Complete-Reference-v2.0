# 4.12 Variables

Переменная — именованная ячейка хранения с объявленным типом. В Java таких ячеек несколько видов, и различаются они не синтаксисом объявления, а тем, где живут, когда инициализируются и как долго существуют. Раздел перечисляет виды переменных и разбирает `final`; значения по умолчанию подробно уже в [[4.2.14 Default Values and Initialization]], а формальные правила обязательной инициализации (definite assignment) — дом Ch. 16.

## The kinds of variables

Переменных семь видов. **Поля класса** (`static`) принадлежат самому классу и существуют всё время его загрузки. **Поля экземпляра** живут в объекте и создаются с ним. **Компоненты массива** — ячейки внутри массива-объекта. **Параметры метода** и **параметры конструктора** получают значение при вызове. **Параметры лямбды** — при её применении. **Параметр исключения** (`catch (E e)`) связывается пойманным исключением. **Локальные переменные** объявляются в теле метода/блока. Отдельно стоят **переменные образца** (pattern variables), вводимые `instanceof`-паттернами и `switch` (их семантика — Ch. 14.7).

Ключевое различие, определяющее поведение, — между полями (и компонентами массива), которые при создании получают значение по умолчанию, и локальными переменными и параметрами, которые дефолта не получают.

```java
class User {
    static int count;      // поле класса: по умолчанию 0
    String name;           // поле экземпляра: по умолчанию null
    void greet() {
        int shown;         // локальная: без значения по умолчанию
        System.out.println(shown); // compile-time error: might not have been initialized
    }
}
```

Значения по умолчанию по типам и причину, почему у локальных их нет, разбирает [[4.2.14 Default Values and Initialization]].

## final and effectively final

Модификатор `final` фиксирует переменную: после первого присваивания её нельзя переприсвоить. Для примитива это неизменное значение, для ссылки — неизменная ссылка (но **не** неизменный объект — см. [[4.1.7 Runtime Representation of Values]]).

```java
final int MAX = 100;
// MAX = 200;            // compile-time error

final List<Integer> xs = new ArrayList<>();
xs.add(1);              // ок: объект изменяем
// xs = List.of();      // compile-time error: ссылку переприсвоить нельзя
```

Переменная, которую фактически не переприсваивают после инициализации, называется **фактически финальной** (effectively final), даже без слова `final`. Это важно для лямбд и локальных классов: захватывать можно только `final` или фактически финальные локальные переменные. Полностью тема захвата и definite assignment — Ch. 16.

```java
int base = 10;          // не меняется дальше → фактически финальная
Runnable r = () -> System.out.println(base); // ок: захват разрешён
// base = 20;           // если раскомментировать — лямбда выше перестанет компилироваться
```

## Common Mistakes

- Считать `final`-ссылку гарантией неизменяемости объекта (см. пример выше). Правильно: `final` про ссылку; неизменяемость объекта — это `List.copyOf`, `record`, неизменяемые классы.

- Пытаться захватить в лямбде изменяемую локальную переменную.

```java
int sum = 0;
list.forEach(x -> sum += x);  // compile-time error: sum не (effectively) final
```
  Правильно: не мутировать захваченную переменную; использовать поток-редукцию (`list.stream().mapToInt(...).sum()`) или аккумулятор-поле.
