Целочисленный литерал записывает значение типа `int` или `long`. Тип по умолчанию — `int`; суффикс `L` (или `l`) делает литерал `long`.

```java
int  x = 42;    // литерал типа int
long y = 42L;   // тот же 42, но уже long — из-за суффикса L
long z = 42;    // тоже ок: int-литерал расширяется до long при присваивании
```

Всегда пишите заглавную `L`: строчная `l` визуально сливается с цифрой `1`.

```java
long a = 100l;  // компилируется, но 100l читается как «100 один» — опасно
long b = 100L;  // так однозначно
```

## Forms

Литерал можно записать в четырёх системах счисления.

```java
int dec = 42;          // десятичная
int hex = 0x2A;        // шестнадцатеричная (0x), цифры 0–9 и A–F
int bin = 0b101010;    // двоичная (0b), с Java 7
int oct = 052;         // восьмеричная: ведущий 0, цифры 0–7
```

Все четыре записи выше — это одно и то же число 42. Шестнадцатеричная запись регистронезависима: `0xFF`, `0xff` и `0XfF` эквивалентны. Обратите внимание на восьмеричную форму: ведущий ноль меняет систему счисления, и это частый источник ошибок.

```java
int t = 010;           // это НЕ 10, а 8 (восьмеричное)
System.out.println(t); // 8
```

Цифры должны соответствовать системе: за префиксом обязана быть хотя бы одна допустимая цифра.

```java
int bad1 = 0x;         // ошибка компиляции: нет цифр после 0x
int bad2 = 0b12;       // ошибка компиляции: 2 недопустима в двоичной записи
int bad3 = 09;         // ошибка компиляции: 9 недопустима в восьмеричной записи
```

## Underscores

С Java 7 между цифрами допускается `_` для читаемости. Но не в начале, конце и не рядом с префиксом, суффиксом или точкой.

```java
int  million = 1_000_000;      // ок
int  card    = 0xCAFE_BABE;    // ок: между шестнадцатеричными цифрами
long big     = 9_223_372L;     // ок
int  ugly    = 1__________2;   // компилируется (несколько _ подряд), но так не пишут

int e1 = _100;    // ошибка: подчёркивание в начале
int e2 = 100_;    // ошибка: подчёркивание в конце
int e3 = 0_x10;   // ошибка: подчёркивание внутри префикса
int e4 = 10_L;    // ошибка: подчёркивание перед суффиксом
```

Тонкость с восьмеричной записью: ведущий `0` — это уже первая цифра литерала, а не отдельный префикс, поэтому `_` сразу после него допустимо. Подчёркивания компилятор просто игнорирует: `2_0_2_2` и `20__22` — один и тот же `2022`.

```java
int oct = 0_377;   // ок: 0 — первая цифра восьмеричного литерала
int bad = _0377;   // ошибка: подчёркивание перед первой цифрой
```

## Range, Suffix, and Negative Values

Значение литерала должно помещаться в его тип. Если число больше `Integer.MAX_VALUE`, но это `int`-литерал (нет `L`), — ошибка компиляции, а не «переполнение».

```java
long ok  = 10_000_000_000L;  // ок: это long-литерал
long err = 10_000_000_000;   // ошибка компиляции: слишком велик для int
```

Отрицательного целочисленного литерала как токена нет: минус — это унарный оператор над положительным литералом. Отсюда единственная тонкость на границе диапазона — `Long.MIN_VALUE`/`Integer.MIN_VALUE` записываются только вместе с минусом, потому что модуль в виде литерала уже вне диапазона.

```java
long min = -9223372036854775808L;   // ок: минус + литерал
long bad = 9223372036854775808L;    // ошибка: 9223372036854775808 вне диапазона long
```

## Common Mistakes

1. **Строчная `l` путается с `1`.** `long v = 1111l;` → визуально неоднозначно. Правильно: `long v = 1111L;`.
2. **Ведущий ноль — это восьмеричная запись.** `int minutes = 060;` даёт 48, а не 60. Правильно: `int minutes = 60;`.
3. **Слишком большой литерал без `L`.** `long id = 3_000_000_000;` → ошибка компиляции. Правильно: `long id = 3_000_000_000L;`.
4. **Подчёркивание не между цифрами.** `int x = 0x_FF;` → ошибка. Правильно: `int x = 0xFF;` или `0x_FF` только между цифрами: `0xF_F`.
5. **Недопустимая цифра для системы счисления.** `int b = 0b102;` → ошибка. Правильно: только `0` и `1` в двоичной записи.
