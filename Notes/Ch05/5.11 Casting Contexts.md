# 5.11 Casting Contexts

Контекст каста (casting context) — это оператор `(Type) expression`. Он самый широкий из всех: разрешает не только всё, что делают присваивание и вызов, но и то, чего те не делают неявно, — **сужения примитивов, `byte`→`char` и сужения ссылок**, — а также **составные цепочки** из нескольких родов. Каст — это способ сказать компилятору «я беру ответственность за это преобразование». Но широта не означает вседозволенность: между несовместимыми типами каст запрещён на этапе компиляции, а сужение ссылок и распаковка проверяются во время выполнения. Раздел разграничивает исходы каста и разбирает цепочки, из-за которых даже каст с примитивной целью может бросить исключение.

## Casting is the widest context

Всё, что доступно в присваивании и вызове (тождество, расширение примитива, упаковка/распаковка, расширение ссылки), доступно и в касте. Сверх того каст добавляет сужение примитива, `byte`→`char` и сужение ссылки, и разрешает комбинировать роды по фиксированным шаблонам (§5.5).

```java
long l = 10L;
int i = (int) l;                // narrowing primitive — только каст
double d = 9.99;
int t = (int) d;                // narrowing primitive: → 9 (к нулю)
byte bt = 65;
char ch = (char) bt;            // widening-and-narrowing primitive (byte→char)

Object o = "text";
String s = (String) o;          // narrowing reference — проверка в runtime
Integer boxed = (Integer) 5;    // boxing (обычно избыточен)
int back = (int) boxed;         // unboxing
```

Часто каст стоит не ради самого преобразования, а чтобы направить арифметику или разрешение перегрузки; в `(double) total / count` каст меняет тип операнда до деления (см. [[5.2 Identity and Widening Primitive Conversion]]).

## Composite chains: a primitive target is not always safe

Ключевая тонкость: каст с **примитивной** целью не обязан быть простым сужением примитива. Если источник — ссылка, каст разворачивается в **цепочку** «сужение ссылки → распаковка», и каждое звено может отказать в runtime. То есть «примитив-в-примитив сужение не бросает» **не** переносится на всякий каст с примитивной целью.

```java
Object o = Integer.valueOf(5);
int i = (int) o;                // цепочка: narrowing ref Object→Integer, затем unboxing → 5
```

Но та же запись падает, если фактический тип не тот или `null`:

```java
Object bad = "x";
int j = (int) bad;              // ClassCastException: String нельзя привести к Integer
Object nul = null;
int k = (int) nul;              // NullPointerException: распаковка null после narrowing ref
```

Обратите внимание и на выбор обёртки: `(int) obj` распаковывается через `Integer`, а `(long) obj` — через `Long`. Поэтому `(long) (Object) Integer.valueOf(5)` бросит `ClassCastException` («Integer cannot be cast to Long»), а не «распакует Integer и расширит до long». Цепочка идёт через обёртку целевого примитива, а не через арифметическое расширение.

## Three outcomes of a cast

Каст **примитив→примитив** никогда не бросает исключение: результат может быть испорчен переполнением или усечением (см. [[5.3 Narrowing Primitive Conversion]]), но выполнение продолжится. Каст **ссылок вниз** по иерархии (в том числе как звено цепочки) проверяется в runtime: несовместимость даёт `ClassCastException`, `null` при последующей распаковке — `NullPointerException`. Каст между заведомо несовместимыми типами компилятор **отвергает сразу**.

```java
int x = (int) 3_000_000_000L;   // (1) примитивное сужение: молча → -1294967296
Object o = Integer.valueOf(7);
String bad = (String) o;        // (2) ссылочное сужение: ClassCastException в runtime
String s = "x";
// Integer n = (Integer) s;     // (3) DOES NOT COMPILE: inconvertible types
```

Разница между (1) и (2) существенна для отладки: испорченный примитив не выдаёт себя ничем, а неверный downcast честно падает с `ClassCastException`, называя классы. Детали checked / partially / completely unchecked сужения ссылок — [[5.5 Widening and Narrowing Reference Conversion]].

## Intersection casts

Каст может задавать **intersection type** — `(A & B)`, — утверждая, что значение реализует сразу несколько типов. Это нужно, например, чтобы придать лямбде дополнительный интерфейс-маркер.

```java
var x = (Comparable<String> & java.io.Serializable) "hi"; // строка и Comparable, и Serializable
```

## Cast as a target type for lambdas and method references

Лямбда и ссылка на метод — poly-выражения: без целевого типа их тип неизвестен. Каст к функциональному интерфейсу **задаёт** этот целевой тип, поэтому каст здесь не «преобразует значение», а определяет, каким функциональным интерфейсом стать выражению.

```java
Object r = (Runnable) () -> System.out.println("run"); // без каста тип лямбды не вывести
```

Полная семантика лямбд и функциональных интерфейсов — Ch. 15.6.

## What casting still cannot do

Каст не соединяет принципиально несовместимые миры: нельзя кастовать `boolean` в число и обратно; нельзя кастовать примитив в несвязанный ссылочный тип (кроме упаковки) и наоборот; нельзя кастовать между несвязанными финальными классами. Литерал `null` кастуется к любому ссылочному типу, и downcast с `null` не бросает исключения — проверять нечего.

```java
boolean flag = true;
// int n = (int) flag;          // DOES NOT COMPILE: boolean и int несовместимы
Object o = null;
String s = (String) o;          // ок: null → любой ссылочный тип, без CCE
```

## Common Mistakes

- Использовать каст примитива как «безопасное укорачивание», не думая о переполнении.

```java
int millis = (int) System.currentTimeMillis(); // молча переполнится
```
  Правильно: `Math.toIntExact(...)` — бросит `ArithmeticException` вместо тихой порчи.

- Считать каст с примитивной целью заведомо безопасным: `(int) someObject` — это цепочка через распаковку и может бросить `ClassCastException`/`NullPointerException`.

- Делать downcast без проверки, полагаясь на «здесь точно нужный тип».

```java
Object o = queue.poll();
Message m = (Message) o;        // ClassCastException, если в очереди оказалось иное
```
  Правильно: `if (o instanceof Message m) { … }` (см. [[5.14 Testing Contexts and Pattern Compatibility]]).

- Пытаться кастом обойти несовместимость типов вместо преобразования значением.

```java
Object o = 42;
// String s = (String) o;       // ClassCastException: Integer не String
String s = String.valueOf(o);   // правильно
```
