# 4.1.1 Definition of Type

Тип — это формальное описание данных, которое отвечает на три вопроса: какие значения допустимы, какие операции над ними разрешены и с какими другими типами эти значения совместимы. Сам тип значением не является: он описывает свойства значений, а не хранит их. Здесь фиксируется, что такое тип и как он работает на компиляции; различие статического и исполняемого типа вынесено в [[4.1.5 Static vs Runtime Type]], отношение подтипов — в [[4.1.6 Subtypes and Supertypes]].

## What a type constrains

Тип ограничивает три вещи: множество допустимых значений (у `int` — целые из фиксированного диапазона, у `String` — ссылки на строковые объекты или `null`), набор операций (нельзя вызвать метод, не объявленный типом, или применить арифметику к типу, её не поддерживающему) и совместимость при присваивании и передаче аргументов.

```java
int a = 5;
int b = a + 1;          // ок: тип int поддерживает +

String s = "x";
String t = s + "y";     // ок: String поддерживает конкатенацию через +
```

Нарушение любого из ограничений — ошибка компиляции, а не runtime:

```java
String s = "x";
int n = s + 1;          // compile-time error: String + int даёт String, не int
boolean f = s.isBlank(); // ок: метод объявлен в String
s.sqrt();               // compile-time error: у String нет метода sqrt()
```

Статическая проверка отклоняет операции, недопустимые для известных компилятору типов. Некоторые разрешённые операции требуют дополнительных проверок во время выполнения: приведение ссылки может дать ClassCastException, запись в ковариантный массив — ArrayStoreException. Unchecked-операции создают отдельный риск heap pollution; подробности — [[4.1.5 Static vs Runtime Type]] и Ch. 20.

## The compile-time role

Тип выражения всегда известен компилятору и используется им для проверки корректности выражений, выбора перегруженного метода и контроля совместимости при присваивании и вызове. Для ссылочных типов у объекта во время выполнения есть ещё и фактический тип — это отдельная тема [[4.1.5 Static vs Runtime Type]].

Все ссылочные типы неявно восходят к `java.lang.Object` — общему корню иерархии; это гарантирует, что у любого объекта есть `equals`, `hashCode`, `toString`. Примитивные типы в эту иерархию не входят.

## Type identity: name plus class loader

На уровне исходного кода идентичность типов учитывает объявления, аргументы параметризованных типов и компонентные типы массивов. В JVM класс определяется бинарным именем и определяющим загрузчиком (defining class loader). Разные инициирующие загрузчики могут делегировать одному определяющему загрузчику и получить один класс. Одно бинарное имя с разными определяющими загрузчиками означает разные классы; попытка приведения между их экземплярами может дать ClassCastException.

```java
// Плагин, загруженный двумя разными загрузчиками:
Object a = loaderA.loadClass("com.example.Plugin").getConstructor().newInstance();
com.example.Plugin p = (com.example.Plugin) a; // ClassCastException,
// если текущий класс Plugin загружен другим загрузчиком, чем loaderA
```

Раздельные определяющие загрузчики позволяют изолировать типы плагинов и объясняют ClassCastException вида «Plugin cannot be cast to Plugin». Принадлежность разным модулям сама по себе не означает разные загрузчики. Детали — Ch. 18 и Part II.

Отдельно: `void` — не тип значений, а обозначение отсутствия результата в сигнатуре метода; `java.lang.Void` — ссылочный тип-маркер, применяемый как аргумент типа там, где значение не нужно (`Callable<Void>`). Подробнее — [[4.3 Reference Types and Values]].

## Common Mistakes

Считать, что runtime-класс хранит конкретные аргументы типа каждого generic-объекта. Class представляет класс во время выполнения, но getClass() обычного ArrayList<String> не сообщает тип элементов. При этом метаданные generic-объявлений могут сохраняться и доступны рефлексии; подробности — Ch. 20.

```java
List<String> list = new ArrayList<>();
System.out.println(list.getClass()); // class java.util.ArrayList — без <String>
```
  Правильно: рассчитывать на runtime-тип объекта, а не на статический тип переменной или аргумент generics.

- Ловить `ClassCastException` «Plugin cannot be cast to Plugin» и искать опечатку. Причина — разные загрузчики, а не имя. Правильно: сверить `getClassLoader()` обоих типов и грузить общий контракт одним загрузчиком.
