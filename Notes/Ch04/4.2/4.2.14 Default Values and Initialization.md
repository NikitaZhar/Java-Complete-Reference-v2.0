# 4.2.14 Default Values and Initialization

У примитивных (и ссылочных) полей есть значения по умолчанию, а у локальных переменных — нет, и путаница между этими двумя правилами — источник как ошибок компиляции, так и тихих логических багов. Здесь — что и когда инициализируется автоматически; формальные правила обязательной инициализации (definite assignment) — дом Ch. 16, сюда вынесены ссылкой.

## Fields and array components get defaults

Поля класса и экземпляра, а также элементы массивов при создании автоматически получают значение по умолчанию — «нулевое» для своего типа.

| Тип | Значение по умолчанию |
|---|---|
| `byte`, `short`, `int`, `long` | `0` / `0L` |
| `float`, `double` | `0.0f` / `0.0` |
| `char` | `'\u0000'` (NUL, код 0) |
| `boolean` | `false` |
| любой ссылочный | `null` |

```java
class Counter {
    int count;         // 0 автоматически
    boolean active;    // false
    String name;       // null
}
int[] a = new int[3];  // {0, 0, 0} — элементы тоже получают дефолт
```

## Local variables get nothing

Локальная переменная значения по умолчанию **не получает**: компилятор требует присвоить ей значение до первого чтения, иначе — ошибка компиляции, а не мусор в runtime.

```java
void m() {
    int x;
    System.out.println(x); // compile-time error: variable x might not have been initialized
}
```

Почему разница? У поля есть чётко определённый момент инициализации — создание объекта или класса, — и туда естественно вписать «обнуление». У локальной переменной такого гарантированного момента нет: она живёт в кадре стека, путь исполнения до неё может ветвиться, и «нулевое» значение по умолчанию скрыло бы забытую инициализацию. Поэтому язык, вместо тихого дефолта, заставляет компилятор доказать, что переменная присвоена по всем путям, — это и есть определённое присваивание (definite assignment), полностью разбираемое в Ch. 16.

## Common Mistakes

- Полагаться на «дефолт» локальной переменной, как у поля.

```java
int total;
for (int i = 0; i < 10; i++) total += i; // compile-time error: total не инициализирована
```
  Правильно: явно `int total = 0;`.

- Считать значение по умолчанию `char`-поля пробелом. Оно `'\u0000'` (NUL, код 0), а не `' '` (пробел, код 32) — при выводе это невидимый символ, а не пустота. Правильно: инициализировать `char`-поля осмысленным значением.

- Забывать, что поле-ссылка по умолчанию `null`, и обращаться к нему до инициализации → `NullPointerException`. Правильно: инициализировать в объявлении или конструкторе.
