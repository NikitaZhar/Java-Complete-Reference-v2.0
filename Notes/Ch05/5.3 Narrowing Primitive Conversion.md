# 5.3 Narrowing Primitive Conversion

Сужающее преобразование (narrowing primitive conversion) — переход от более широкого числового типа к более узкому: `long`→`int`, `int`→`short`, `double`→`byte` и любой другой, который **не** является расширяющим по цепочке из [[5.2 Identity and Widening Primitive Conversion]]. В отличие от расширения, сужение может потерять и магнитуду, и точность, поэтому компилятор его неявно не выполняет: почти всегда нужен явный каст `(Type)`. Понять сужение — значит понять, **что именно** происходит с битами и с дробной частью, потому что результат часто выглядит бессмысленным, а исключения при этом не будет: сужающее преобразование, как и расширяющее, **никогда не бросает runtime-исключение**. Это и делает его опасным — ошибка молчит.

## What the cast actually does

Механика зависит от того, целочисленный источник или вещественный.

Из целого в более узкое целое (`long`/`int`→`short`/`byte`/`char`) отбрасываются старшие биты: остаются только младшие `n` бит целевого типа, и они интерпретируются как значение целевого типа (со знаком — для `byte`/`short`, без знака — для `char`). Отсюда и «переполнение при касте».

```java
int i = 260;
byte b = (byte) i;          // 260 = 0x104; в byte лезут младшие 8 бит 0x04 → 4
System.out.println(b);      // 4

int neg = -1;
char c = (char) neg;        // младшие 16 бит всех единиц → '￿' == 65535
System.out.println((int) c);// 65535 — знак не сохранился, char беззнаковый
```

Из вещественного в целое (`double`/`float`→`long`/`int` и уже потом, при необходимости, в `byte`/`short`/`char`) действует особая процедура: дробная часть **отбрасывается** (округление к нулю, не математическое), а затем, если результат не влезает, применяются граничные правила. `NaN` превращается в `0`; значения за пределами типа — в `Long.MAX_VALUE`/`MIN_VALUE` или `Integer.MAX_VALUE`/`MIN_VALUE`; `Infinity` — в соответствующую границу.

```java
double d = 3.99;
int x = (int) d;            // округление к нулю → 3 (не 4!)
System.out.println(x);

double huge = 1e20;
int y = (int) huge;         // за пределами int → Integer.MAX_VALUE
System.out.println(y);      // 2147483647

int nan = (int) Double.NaN; // NaN → 0
System.out.println(nan);    // 0

double neg = -2.7;
long z = (long) neg;        // к нулю → -2 (а не -3)
System.out.println(z);
```

## char is special on both ends

Все переходы между `char` и `byte`/`short` считаются сужающими в обе стороны, даже `byte`→`char`, хотя `byte` короче. Причина в знаке: `char` беззнаковый, `byte`/`short` знаковые, и перенос значения может исказить смысл. Поэтому такое преобразование идёт в два шага — сначала к `int`, затем к целевому типу — и требует каста.

```java
byte src = -1;
char ch = (char) src;       // narrowing byte → char через int: → '￿'
System.out.println((int) ch); // 65535, а не -1
```

## Silent overflow is the real danger

Ни один из примеров выше не бросает исключение — компилируется и «работает», выдавая тихо испорченное значение. Это принципиально: каст сужения — обещание компилятору «я знаю, что делаю». Если значение реально не влезает, ошибку обнаружит только тест или пользователь. Когда нужна защита от потери, используют явную проверку или `Math.toIntExact`, который бросит `ArithmeticException` при переполнении.

```java
long value = 3_000_000_000L;
int bad = (int) value;              // молча → -1294967296
int safe = Math.toIntExact(value);  // ArithmeticException: integer overflow
```

## Common Mistakes

- Ждать математического округления при касте вещественного к целому.

```java
int price = (int) 9.99;     // 9, а не 10 — дробь просто отброшена
```
  Правильно: округлять явно — `Math.round(9.99)` даёт `10` (тип `long`, при необходимости — каст).

- Сужать переменную «на всякий случай» кастом, пряча реальную потерю.

```java
int count = someLong;               // DOES NOT COMPILE — и это хорошо: заставляет задуматься
int count2 = (int) someLong;        // компилируется, но молча переполнится при больших значениях
```
  Правильно: `Math.toIntExact(someLong)` — падение вместо тихой порчи, если значение не помещается.

- Полагать, что каст `int`→`byte` «обрезает до диапазона» (клампит). На деле берутся младшие биты, и `130` превращается не в `127`, а в `-126`.

```java
byte b = (byte) 130;        // -126, а не 127
```
  Правильно: если нужен кламп — `(byte) Math.max(Byte.MIN_VALUE, Math.min(Byte.MAX_VALUE, v))`.
