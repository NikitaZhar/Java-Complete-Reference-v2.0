# 4.2.8 float

`float` — 32-битный вещественный тип IEEE 754, около 7 значащих десятичных цифр. Общие правила представления, NaN, бесконечностей и выбора стратегии сравнения — [[4.2.7 Floating-Point Types]]; здесь — специфика float и случаи его применения.

## When to use float instead of double

По умолчанию для вещественных вычислений берут `double`: он точнее и не требует суффикса. `float` осмыслен лишь там, где решает память или совместимость: большие массивы вещественных (миллионы точек, текстуры, сигналы, ML-тензоры), где вдвое меньший размер против `double[]` экономит память и пропускную способность кэша, а также точное соответствие 32-битным полям внешних форматов и графических API. Выигрыш скорости не гарантирован, а потерь точности больше.

Литерал `float` требует суффикса `f`/`F`; без него это `double`, и присваивание в `float` не скомпилируется:

```java
float f = 3.14f;        // f обязателен
// float bad = 3.14;    // compile-time error: double → float требует приведения
float sum = 0.1f + 0.2f; // приближённое значение
System.out.println(sum == 0.3f); // true: в этом случае округления совпали
double wider = f;        // float → double: неявное расширение
```

## Precision runs out faster

Семи цифр хватает не всегда, и `float` теряет точность заметно раньше `double` — уже при сложении чисел разного порядка мелкие слагаемые «исчезают». Поэтому `float` не годится не только для денег (как и `double` — см. [[4.2.7 Floating-Point Types]]), но и для длинных цепочек накопления.

```java
float acc = 0f;
for (int i = 0; i < 10_000_000; i++) acc += 1.1f;
System.out.println(acc);   // заметно «не то»: погрешность накопилась
```

Значение по умолчанию — `0.0f` ([[4.2.14 Default Values and Initialization]]); обёртка — `Float` ([[4.2.13 Boxing and Unboxing]]).

## Common Mistakes

- Забыть суффикс `f`. Правильно: вещественный литерал для `float` всегда с `f` (`1.5f`), иначе он `double`.

- Брать `float` «для скорости» в обычных расчётах.

```java
float rate = 0.1f, total = 0f;
for (int i = 0; i < 1000; i++) total += rate;  // накопленная погрешность больше, чем у double
```
  Правильно: по умолчанию `double`; `float` — только ради памяти в больших массивах или под внешний формат.
