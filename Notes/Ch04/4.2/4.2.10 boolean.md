# 4.2.10 boolean

`boolean` — логический примитив ровно с двумя значениями, `true` и `false`. Он стоит особняком среди примитивов: не участвует ни в какой числовой арифметике и не преобразуется в целые типы и обратно. Именно это ограничение, а не «размер» или «диапазон», — главное, что нужно про него понимать.

## boolean is not a number — and that is the point

В C и подобных языках условие — это число: `0` — ложь, всё остальное — истина, а `true`/`false` свободно смешиваются с целыми. Java намеренно разорвала эту связь. `boolean` не является целочисленным типом, не приводится к `int` (ни расширением, ни явным приведением), и условие `if`, `while`, `?:`, операнды `&&`, `||`, `!` обязаны иметь именно тип `boolean`.

```java
boolean flag = true;
int n = flag;          // compile-time error: boolean не конвертируется в int
if (1) { }             // compile-time error: требуется boolean, а не int
```

Зачем такое ограничение? Оно закрывает целый класс ошибок, живучих в C. Классическая опечатка `if (x = 0)` — присваивание вместо сравнения — там компилируется и всегда ложна; в Java `if (x = 0)` не пройдёт компиляцию, потому что `x = 0` имеет тип `int`, а не `boolean`. Язык обменивает пару «удобных» неявных преобразований на устранение тихого бага.

## The one trap the rule leaves open

Защита не абсолютна: если переменная сама `boolean`, то присваивание `=` внутри условия имеет тип `boolean` и компилируется — тогда `=` вместо `==` снова становится ловушкой.

```java
boolean done = false;
if (done = true) {     // компилируется! это присваивание, а не сравнение — всегда true
    // ветка выполнится всегда, а done молча станет true
}
```
Правильно: сравнивать через `==` (`if (done == true)`) или, чище, использовать переменную напрямую (`if (done)`); присваивание в условии почти всегда ошибка.

## Storage and defaults

Размер `boolean` спецификация JVM не фиксирует: в локальных переменных и полях он обычно занимает столько же, сколько `int`, а в массивах `boolean[]` — по байту на элемент. Полагаться на «один бит» нельзя, и для плотных наборов флагов берут не `boolean[]`, а битовые приёмы на `int`/`long` или `java.util.BitSet` (её дом — главы коллекций). Значение по умолчанию `boolean`-поля — `false` ([[4.2.14 Default Values and Initialization]]); обёртка — `Boolean` ([[4.2.13 Boxing and Unboxing]]).

Логические операторы (`&&`/`||` с коротким замыканием против небулевых `&`/`|`) — тема операторов, Ch. 15; здесь важно лишь, что все они требуют `boolean`.

## Common Mistakes

- Распаковка `Boolean`-обёртки со значением `null` в условии.

```java
Boolean flag = map.get("enabled");  // может вернуть null
if (flag) { }                       // NullPointerException при распаковке
```
  Правильно: сравнивать с объектом (`Boolean.TRUE.equals(flag)`) или проверять `null` заранее.

- `=` вместо `==` для `boolean`-переменной (см. пример выше). Правильно: `if (done)` или `if (done == true)`, никогда `if (done = true)`.
