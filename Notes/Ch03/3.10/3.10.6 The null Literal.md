`null` — единственный литерал, обозначающий отсутствие ссылки. Пишется строчными буквами.

```
NullLiteral:
    null
```

`null` принадлежит собственному «null type» — безымянному типу, совместимому со всеми ссылочными типами и несовместимому с примитивами. Поэтому его можно присвоить любой ссылочной переменной, но не переменной примитивного типа.

```java
String s = null;   // ок
Object o = null;   // ок для любого ссылочного типа
int    n = null;   // ошибка компиляции: примитив не принимает null
```

Java различает регистр: только `null` — литерал; `Null` и `NULL` компилятор воспринимает как идентификаторы и не находит.

```java
String bad = NULL;   // ошибка компиляции: cannot find symbol
String ok  = null;   // правильно
```

## Where null Bites at Runtime

Сравнение `==`/`!=` с `null` безопасно, но обращение к членам через `null`-ссылку даёт `NullPointerException` уже во время выполнения (не при компиляции).

```java
String s = null;
System.out.println(s == null);   // true — безопасно
System.out.println(s.length());  // NullPointerException во время выполнения
```

Отдельная ловушка — распаковка `null`: присвоить `null` обёртке можно, но её распаковка в примитив бросает `NullPointerException`.

```java
Integer i = null;   // ок
int x = i;          // NullPointerException при распаковке
```

## Common Mistakes

1. **`Null`/`NULL` вместо `null`.** `if (x == NULL)` → «cannot find symbol». Правильно: `null` строчными.
2. **`null` примитиву.** `int n = null;` → ошибка компиляции. Примитив не может быть «отсутствующим»; используйте обёртку `Integer` или значение по умолчанию.
3. **Вызов метода на `null`.** `s.length()` при `s == null` → `NullPointerException`. Проверяйте: `if (s != null) …`.
4. **Скрытая распаковка `null`.** `int x = map.get(key);`, где `get` вернул `null`, → `NullPointerException`. Правильно: работать с `Integer` и проверять на `null`.
