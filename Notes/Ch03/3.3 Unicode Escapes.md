Unicode-escape — это запись символа шестью ASCII-символами вида `\uXXXX`, где `XXXX` — четыре шестнадцатеричные цифры кода UTF-16-единицы. Механизм придуман, чтобы любую программу можно было записать одними ASCII-символами и обработать ASCII-инструментами. Ключевая и часто недооценённая деталь — escape разворачиваются на самом первом шаге лексической трансляции ([[3.2 Lexical Translations]]), до деления на строки, комментарии и токены. Это делает `\uXXXX` не «строковым escape», а полноценной заменой символа в любом месте исходника, и порождает несколько неожиданных эффектов.

## Form and Placement

Грамматика escape:

```
UnicodeEscape:  \ UnicodeMarker HexDigit HexDigit HexDigit HexDigit
UnicodeMarker:  u {u}
```

После `\` идёт один или более `u`, затем ровно четыре шестнадцатеричные цифры. Один escape покрывает диапазон `U+0000..U+FFFF`; дополнительный символ (`U+10000..U+10FFFF`) записывается двумя escape подряд (суррогатная пара). Если после последнего `u` нет четырёх шестнадцатеричных цифр — ошибка компиляции.

```java
char c = 'A';        // 'A' — escape в символьном литерале
int x = 5;           // имя переменной x: escape работает и в идентификаторе
System.out.println(x);    // 5

char bad  = '\u00G1';     // ошибка компиляции: G не шестнадцатеричная цифра
char bad2 = '\u041';      // ошибка компиляции: только три цифры после u
```

Множественные `u` (`\uu0041`) допустимы и означают тот же символ; они нужны стандартному преобразованию Unicode↔ASCII, которое при обратимой записи добавляет лишний `u`.

## Escapes Are Processed First — Anywhere

Поскольку escape разворачивается раньше разбора на комментарии и строки, он «работает везде», в том числе там, где это ломает код. Escape перевода строки `\u000A` внутри `//`-комментария завершает комментарий, а не остаётся его частью — в сыром исходнике ниже он развернётся в LF:

```java
// комментарий заканчивается здесь \u000A a = 5; — escape стал LF, «a = 5;» исполняется
```

По той же причине escape `\u000A` нельзя использовать как перевод строки внутри обычного строкового литерала: он развернётся в реальный LF ещё до лексера, и литерал окажется незакрытым.

```java
String bad = "line1\u000Aline2";  // ошибка: \u000A разворачивается в LF до лексера, литерал не закрыт
String ok  = "line1\nline2";      // правильно: \n — строковый escape (3.10.5), обрабатывается позже
```

Отсюда практическое правило: для переводов строк, табуляций и кавычек внутри строк используйте строковые escape-последовательности (`\n`, `\t`, `\"` — [[3.10.5 String Literals]]), а не Unicode-escape.

## The Even/Odd Backslash Rule

Escape начинается только с «правомочного» `\`. Правомочность определяется чётностью идущих подряд обратных косых: `\` начинает escape, если слева от него чётное число backslash (ноль тоже чётно); при нечётном — нет. Это исключение из правила longest match ([[3.2 Lexical Translations]]) не даёт `\\uXXXX` жадно распасться на `\` плюс escape.

```
Сырой ввод   →  результат шага 1
™       →  ™              (перед \ ноль backslash, чётно → escape)
\\u2122      →  \ u 2 1 2 2    (перед вторым \ один backslash, нечётно → не escape)
\\™     →  \ ™            (перед третьим \ два backslash, чётно → escape)
```

Символ, полученный из `escape`, дальше в escape не участвует: `escape` `\` даёт код `backslash`, но этот `\` не начинает новый `escape`. Поэтому `\` + `u005a` (то есть `\u005a`) даёт шесть символов `\ u 0 0 5 a`, а не букву `Z`.

Материал о лексических стадиях и переносе Unicode-трансляции консолидирован здесь и в [[3.2 Lexical Translations]]; значения и диапазоны символьного типа — глава 4; строковые escape-последовательности — [[3.10.5 String Literals]].
