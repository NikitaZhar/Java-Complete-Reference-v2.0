Идентификатор — это имя: класса, интерфейса, метода, переменной, параметра, метки. Формально это последовательность неограниченной длины из «букв Java» и «цифр Java», первый символ которой обязан быть буквой Java. Практически важны четыре вещи: какие символы допустимы, что `$` и `_` — особые случаи, что идентификатор нельзя назвать зарезервированным ключевым словом, и что имя чувствительно к регистру. Что именно считается ключевым словом (и почему контекстные ключевые слова можно использовать как имена) — соседний раздел [[3.9 Keywords]].

## What Characters Are Allowed

```
Identifier:       IdentifierChars, но не ReservedKeyword, BooleanLiteral или NullLiteral
IdentifierChars:  JavaLetter {JavaLetterOrDigit}
```

«Буква Java» — символ, для которого `Character.isJavaIdentifierStart(int)` возвращает `true`; «буква-или-цифра Java» — символ, для которого `true` возвращает `Character.isJavaIdentifierPart(int)`. В число букв Java входят латинские `A-Z` и `a-z`, а также — по историческим причинам — подчёркивание `_` (`\u005F`) и валютные символы: доллар `$` (`\u0024`), а равно `¥`, `£`, `€` и другие. Цифры Java — ASCII `0-9`. Буквы и цифры могут браться из всего Unicode, так что имена допустимо писать на национальных языках.

```java
int count;          // ок
int _value;         // ок: _ внутри имени длиной ≥ 2
long $generated;    // ок, но $ предназначен для сгенерированного кода
double αρετη;       // ок: не-ASCII буквы допустимы
int isLetter2;      // ок: цифра не в начале

int 2fast;          // ошибка: идентификатор не может начинаться с цифры
int my-var;         // ошибка: '-' не буква и не цифра Java
```

Тонкость в природе ошибки: `my-var` и `grand-sum` недопустимы как идентификаторы, но `-` — оператор, поэтому компилятор ещё может попытаться прочитать их как выражение вычитания (`grand - sum`); а вот `all@hands` — жёсткая ошибка, потому что `@` не является ни символом идентификатора, ни оператором, и осмыслить эту последовательность нельзя никак.

Знак доллара следует использовать только в машинно-сгенерированном коде или, редко, для доступа к именам в legacy-системах. Подчёркивание можно использовать в именах из двух и более символов, но не как односимвольное имя — одиночный `_` является ключевым словом ([[3.9 Keywords]]).

```java
int _;         // ошибка компиляции: одиночный '_' — ключевое слово, не идентификатор
int __;        // ок: два подчёркивания — допустимое имя
```

## Case Sensitivity and Unicode Identity

Идентификаторы чувствительны к регистру и сравниваются посимвольно по Unicode. Внешне одинаковые имена могут быть разными: латинская `A` (`\u0041`), греческая `Α` (`\u0391`) и кириллическая `А` (`\u0430` — строчная а) — три разных идентификатора. Составной символ и его каноническое разложение тоже различаются: буква с акутом одним символом (`\u00C1`) не равна букве `A` (`\u0041`) с последующим комбинируемым акутом (`\u0301`).

```java
int value = 1;
int Value = 2;      // другое имя: регистр важен
System.out.println(value + " " + Value);   // 1 2
```

Обратная тонкость: два идентификатора считаются одинаковыми, если совпадают после отбрасывания «игнорируемых» символов (ignorable characters — те, для которых `Character.isIdentifierIgnorable(int)` возвращает `true`; это управляющие символы формата, например zero-width). Поэтому невидимый символ, случайно попавший в имя, может как создать неотличимого на вид «двойника», так и слить два визуально разных имени — источник трудноуловимых багов при копировании кода.

## Identifiers vs Keywords

Идентификатор никогда не совпадает по написанию с зарезервированным ключевым словом, булевым литералом (`true`, `false`) или литералом `null` — это гарантируется правилами токенизации ([[3.5 Input Elements and Tokens]]). А вот с контекстным ключевым словом идентификатор совпасть может: одна и та же цепочка символов трактуется как имя или как контекстное ключевое слово в зависимости от места в программе (детали — [[3.9 Keywords]]).

Чтобы облегчить распознавание контекстных ключевых слов, синтаксис местами сужает множество допустимых идентификаторов. Имя типа (класса, интерфейса, параметра типа) не может быть `permits`, `record`, `sealed`, `var` или `yield`; имя метода при вызове не может быть `yield`.

```java
var x = 10;              // здесь var — контекстное ключевое слово (вывод типа)
int var = 5;             // а здесь var — обычное имя переменной: допустимо
class record {}          // ошибка компиляции: имя типа не может быть 'record'
int yield = 7;           // ок как имя переменной, но недопустимо как имя метода при вызове
```

Полный список зарезервированных и контекстных ключевых слов и правила их распознавания — [[3.9 Keywords]]. Соглашения об именах (camelCase, UPPER_SNAKE_CASE для констант) — стилевые, а не языковые правила.
