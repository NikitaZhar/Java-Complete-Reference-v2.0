# 4.1.7 Runtime Representation of Values

У значения во время выполнения есть наблюдаемая форма — но описывать её надо на уровне **семантики языка**, а не физического устройства памяти. Язык гарантирует ровно две вещи, и из них выводится всё поведение с общими объектами и передачей аргументов: примитивная переменная **содержит само значение**, ссылочная — **ссылку на объект** (или `null`); и при присваивании, и при передаче в метод это содержимое **копируется**. Всё остальное — где физически лежит объект, сколько байт занимает поле, когда его соберёт GC — деталь реализации JVM, а не контракт языка (см. ниже и Part II). Модель памяти для многопоточности (видимость, happens-before, роль `final` при публикации) — отдельная тема Ch. 19. Это **дом** темы передачи по значению.

## The language-level model

Язык обещает про значение немногое, но точно. Переменная — это ячейка, хранящая либо примитивное значение напрямую, либо ссылочное значение (handle к объекту). Присваивание и передача копируют **это содержимое ячейки**. Копирование ссылочного значения **не** копирует объект — копируется только «путь» к нему, поэтому несколько ссылок могут указывать на один объект.

```java
int x = 10;             // x содержит само значение 10
String s = "Java";      // s содержит ссылочное значение (handle к объекту String)

int[] a = {1, 2, 3};
int[] b = a;            // копируется ссылочное значение; a и b denote один массив
b[0] = 99;
System.out.println(a[0]); // 99 — объект общий
```

Обратите внимание, что это сформулировано без слов «куча», «стек» или «адрес»: модель верна независимо от того, как конкретная JVM разместит данные.

## Aliases: two references, one object

Копирование ссылочного значения создаёт **алиасы** (Mughal: «копирование reference values присваиванием создаёт aliases») — несколько переменных, обозначающих один и тот же объект. Изменение объекта видно через все алиасы; оператор `==` для ссылок как раз проверяет, что две переменные — алиасы (denote один объект), а не сравнивает состояние.

```java
StringBuilder sb1 = new StringBuilder("hi");
StringBuilder sb2 = sb1;   // копия ссылочного значения — алиас
sb2.append("!");
System.out.println(sb1);        // hi! — объект один
System.out.println(sb1 == sb2); // true — те же ссылки
```

## Copy on assignment, copy on call: Java is pass-by-value

Java всегда передаёт аргументы **по значению**: по формулировке Boyarsky, «делается копия переменной, и метод получает эту копию; присваивания внутри метода не влияют на вызывающего». Для примитива копируется само значение. Для ссылочного типа копируется **ссылка**, а не объект — поэтому через параметр можно изменить состояние переданного объекта, но нельзя заставить исходную переменную указывать на другой объект.

```java
class PrimitiveArgumentDemo {
    static void change(int x) { x = 9; }
    public static void main(String[] args) {
        int x = 1;
        change(x);
        System.out.println(x); // 1: изменён только параметр-копия
    }
}
```

```java
static void reassign(int[] arr) {
    arr = new int[] {0};   // переназначается только локальная копия ссылки
}
static void mutate(int[] arr) {
    arr[0] = 99;           // меняется общий объект
}

int[] data = {1, 2, 3};
reassign(data);
System.out.println(data[0]); // 1 — исходная ссылка не тронута

mutate(data);
System.out.println(data[0]); // 99 — состояние объекта изменено
```

Тот же принцип объясняет, почему метод не может «обнулить» чужую переменную: присваивание `param = null` внутри метода меняет лишь копию ссылки. Разница «вызвать метод на параметре» против «переприсвоить параметр» — ключевая: первое действует на общий объект, второе локально.

## final fixes the reference, not the object

`final` фиксирует **переменную** (ячейку): после первого присваивания её нельзя переприсвоить. Для ссылки это неизменная ссылка, но **не** неизменный объект — сам объект по-прежнему можно менять.

```java
final List<Integer> xs = new ArrayList<>();
xs.add(1);              // ок: сам объект изменяем
// xs = new ArrayList<>(); // compile-time error: нельзя переприсвоить ссылку
```

## What the language does not promise: physical layout

Всё, что касается физического представления, — **уровень реализации JVM, а не гарантия языка**, и его дом — Part II (представление в class-файле, constant pool) и главы про JVM. Часто встречающиеся, но нестрогие для Part I утверждения:

- «объект лежит в куче, примитив — на стеке»: на деле escape-анализ и scalar replacement могут вообще не размещать объект в куче;
- «поле `short` занимает машинное слово», «`boolean` — как `int`»: раскладка и выравнивание полей implementation-dependent;
- «объект живёт, пока на него есть ссылки»: точнее — пока он **достижим** от GC-roots; изолированная группа взаимных ссылок, ни на кого не достижимая, собирается;
- момент сборки мусора, компактизация, compressed oops.

Практически из всего этого следует одно: полагаться можно на **семантику значений** выше (что копируется, что общее, что фиксирует `final`), а не на предполагаемую физическую форму. Когда физическая раскладка действительно нужна (например, для понимания производительности), это материал Part II, а не правило языка.

## null is a value too

`null` занимает то же место, где была бы ссылка, но не указывает ни на какой объект. Вызов экземплярного метода, доступ к экземплярному полю, компоненту или длине массива через null даёт NullPointerException; обращение к static-члену через выражение со значением null само по себе этого исключения не вызывает. Подробнее о null-типе — [[4.3 Reference Types and Values]].

```java
String s = null;
System.out.println(s.length()); // NullPointerException
```

## Common Mistakes

- Ждать, что переприсваивание параметра-ссылки изменит переменную у вызывающего.

```java
static void clear(String s) { s = null; }
String name = "Nik";
clear(name);
System.out.println(name); // Nik — не null: менялась копия ссылки
```
 
 Правильно: вернуть значение из отдельного метода и присвоить его у вызывающего:

```java
static String cleared(String ignored) { return null; }
// В теле вызывающего метода:
name = cleared(name);
```

Метод clear из примера выше возвращает void, поэтому name = clear(name) не компилируется.

- Считать `final`-ссылку гарантией неизменяемости объекта.

Правильно: запрет переприсваивания переменной не запрещает изменение объекта. Пример и объяснение — в разделе final fixes the reference, not the object выше.

- Строить рассуждение на «объект в куче / примитив на стеке» как на правиле языка. Правильно: опираться на семантику значений; физическое размещение — деталь реализации (Part II), которую JIT волен менять.
