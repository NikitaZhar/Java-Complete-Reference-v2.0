Строковый литерал — последовательность символов в двойных кавычках; его тип — `String`.

```java
String s     = "Java";
String empty = "";      // корректный литерал длиной 0
```

Пустая строка `""` — это полноценный `String`, а не `null`: `null` — отдельный литерал ([[3.10.6 The null Literal]]), не являющийся строкой.

## Escapes and Line Breaks

В строковых литералах действуют те же escape-последовательности, что и в символьных ([[3.10.4 Character Literals]]). Внутренние двойные кавычки и обратную косую нужно экранировать, а «сырой» перевод строки в обычном литерале запрещён.

```java
String ok  = "say \"hi\"\nbye";  // экранированные " и перевод строки \n
String e1  = "say "hi"";          // ошибка: внутренние кавычки не экранированы
String e2  = "abc;                // ошибка: строка не закрыта
// String e3 = "line1<перевод строки>line2"; — перевод строки внутри "..." запрещён, нужен \n
```

Переводы строк в исходнике нормализуются к `\n`, поэтому одинаковый текст в файлах с разными окончаниями строк даёт одинаковую строку.

## Text Blocks

Текстовый блок (text block) — многострочный строковый литерал в тройных кавычках `"""`, тоже типа `String`. Он удобен для HTML, SQL, JSON без нагромождения `\n` и `\"`, и это ровно тот же `String`: к нему применимы все методы строки и его можно передавать в любой метод, принимающий `String`.

```java
String html = """
        <html>
          <body>Hello</body>
        </html>
        """;
```

Ключевое правило записи: после открывающих `"""` обязан идти перевод строки — содержимое начинается со следующей строки. Контент на строке открывающих кавычек — ошибка компиляции.

```java
String bad = """text""";   // ошибка: контент на строке открывающих """
String ok  = """
    text""";               // ок: содержимое с новой строки
```

## Incidental vs Essential Whitespace

Ведущие пробелы в текстовом блоке делятся на два вида. Значимый пробел (essential whitespace) — часть значения строки; случайный отступ (incidental whitespace) появляется лишь для выравнивания кода по левому краю и в значение не входит. Граница между ними — воображаемая вертикальная линия по самому левому непробельному символу среди всех строк контента и закрывающих `"""`: всё слева от неё отбрасывается, всё справа остаётся. Поэтому блок можно сдвигать вместе с кодом, не меняя значения; чтобы добавить в значение именно отступ, увеличивают его относительно этой линии (или используют `\s`).

```java
String block = """
    line1
      line2
    """;              // закрывающие """ задают левую границу
// значение: "line1\n  line2\n" — у line2 два значимых пробела (она правее границы)
```

Положение закрывающих `"""` управляет и левой границей, и финальным переводом строки. Если закрывающие кавычки на отдельной строке — в конце значения есть `\n`; если их дописать в конец последней строки контента — завершающего `\n` не будет.

```java
String withNL = """
    Hi
    """;                // закрывающие """ на отдельной строке → значение "Hi\n"
String noNL   = """
    Hi""";              // закрывающие """ в конце строки контента → значение "Hi"
```

Ещё одна практическая тонкость: хвостовые пробелы в каждой строке блока автоматически отбрасываются. Чтобы сохранить пробел в конце строки, его защищают через `\s` (он же не даёт снять этот пробел как случайный отступ). Завершающий `\` склеивает строку со следующей без перевода строки, а `\"""` вставляет три кавычки внутрь блока, не закрывая его.

```java
String joined = """
    long line part 1 \
    and part 2""";       // \ убирает перенос: "long line part 1 and part 2"
String pad = """
    key:\s
    """;                 // \s сохраняет пробел после "key:"
```

Следующая таблица сводит поведение форматных escape в обычной строке и в текстовом блоке (по Boyarsky):

| Запись | В обычной строке | В текстовом блоке |
|---|---|---|
| `\"` | `"` | `"` |
| `\"""` | ошибка | `"""` |
| пробел в конце строки | пробел | отбрасывается |
| `\s` | пробел | пробел (защищает хвостовой) |
| `\` в конце строки | ошибка | убирает перевод строки |

## Order of Transformations

Значение текстового блока — не буквальная последовательность символов контента, а результат трёх преобразований, применяемых строго в этом порядке: сначала (1) переводы строк нормализуются к `\n` (CR LF и одиночный CR → LF); затем (2) удаляется общий отступ (incidental whitespace), как если бы вызвали `String.stripIndent()`; и только потом (3) интерпретируются escape-последовательности, как `String.translateEscapes()`. Порядок практически важен: раз escape раскрываются последними, `\r`, записанный в блоке, не участвует в нормализации переводов строк, а `\t` и `\s` не мешают шагу удаления отступа — то есть вертикальным и горизонтальным форматированием через escape можно управлять, не ломая выравнивание.

```java
String s = """
    a\r
    b""";
// шаг 1: реальный LF после "a\r" → LF; сам \r (два символа) не тронут
// шаг 2: общий отступ в 4 пробела снят → "a\r\nb"
// шаг 3: \r превращается в CR → значение "a" + CR + LF + "b"
```

## String Templates: Withdrawn

Строковые шаблоны (String Templates, `STR."..."`) для интерполяции выражений были preview-возможностью в Java 21–22 (JEP 430, 459), но затем **изъяты из языка** и в Java SE 25 недоступны — соответствующего синтаксиса нет. Для подстановки значений используют конкатенацию, `String.format`, `formatted` или `StringBuilder` (стандартный API, Part V). Упоминается здесь, чтобы снять частое заблуждение, что интерполяция «уже в языке».

## Common Mistakes

1. **Незакрытая строка или перевод строки внутри `"..."`.** `"line1<Enter>line2"` → ошибка. Правильно: `"line1\nline2"` или текстовый блок.
2. **Неэкранированные `"` и `\`.** `"C:\temp"` трактует `\t` как табуляцию, а `"say "hi""` не компилируется. Правильно: `"C:\\temp"`, `"say \"hi\""`.
3. **Контент на строке открывающих `"""`.** `"""text"""` в одну строку → ошибка. Правильно: перенести содержимое на следующую строку.
4. **Ожидание, что отступ блока попадёт в значение.** Ведущие пробелы выравнивания (incidental whitespace) отбрасываются; значимые пробелы задавайте через `\s`.
5. **Хвостовые пробелы в строке текстового блока отбрасываются.** Чтобы сохранить пробел в конце строки, используйте `\s`.
6. **Неожиданный `\n` в конце текстового блока.** Закрывающие `"""` на отдельной строке добавляют завершающий перевод строки; если он не нужен — ставьте `"""` в конец последней строки контента.
7. **Три кавычки внутри блока.** Последовательность `"""` в контенте закрывает блок раньше времени; чтобы вставить тройную кавычку, экранируйте хотя бы одну: `\"""`.
