# 4.2.5 long

`long` — 64-битный знаковый целочисленный тип, диапазон примерно ±9,2·10¹⁸. Это выбор, когда `int` перестаёт вмещать значение: время в миллисекундах и наносекундах, крупные идентификаторы, размеры и позиции в больших файлах, денежные суммы в минимальных единицах. Общая целочисленная механика — [[4.2.1 Integral Types]]; здесь — специфика `long`: суффикс литерала, границы применимости и то, что `long` всё-таки не «бесконечное» число.

## The L suffix is not optional

Целочисленный литерал по умолчанию `int`, даже если вы присваиваете его в `long`. Пока значение влезает в `int`, это незаметно; как только выходит за ~2,1 млрд — нужен суффикс `L`, иначе литерал не скомпилируется ещё до того, как «узнает» о `long`:

```java
long ok    = 100;               // ок: int 100 расширяется до long
long big   = 3_000_000_000L;    // L обязателен: без него — integer number too large
long badMul = 1_000_000 * 1_000_000;      // int*int переполняется → -727379968, ПОТОМ в long
long okMul  = 1_000_000L * 1_000_000;     // 1000000000000: один операнд long → всё в long
```

Второй-третий примеры — та же ловушка продвижения из [[4.2.1 Integral Types]]: тип выражения определяется до присваивания, поэтому «сделать long» надо операнд, а не переменную слева. Суффикс пишут заглавной `L`: строчная `l` визуально сливается с единицей (`1l` против `11`).

## long is wide, not infinite

Важно не переоценивать `long`: он лишь отодвигает переполнение, но не отменяет его — арифметика по-прежнему по модулю 2⁶⁴, и `Long.MAX_VALUE + 1` так же молча уходит в минимум. Когда нужны действительно произвольно большие целые (криптография, комбинаторика, точные денежные расчёты без риска переполнения), берут `BigInteger` — но это уже объектный тип с собственной семантикой, его дом Ch. 49/50, сюда он вынесен ссылкой.

```java
long max = Long.MAX_VALUE;
System.out.println(max + 1);        // -9223372036854775808 — переполнение никуда не делось
System.out.println(Math.addExact(max, 1)); // ArithmeticException, если нужна страховка
```

Значение по умолчанию — `0L` ([[4.2.14 Default Values and Initialization]]); обёртка — `Long` ([[4.2.13 Boxing and Unboxing]]).

## Common Mistakes

- Забыть суффикс `L` в выражении, которое «должно быть long».

```java
long micros = 24 * 60 * 60 * 1000 * 1000;   // считается в int, переполняется
```
  Правильно: `24L * 60 * 60 * 1000 * 1000`.

- Считать `long` защитой от переполнения. Правильно: для больших диапазонов `long` откладывает проблему, но при риске выхода за 2⁶³ — `Math.*Exact` или `BigInteger` (Ch. 49/50).
