# 5.9 Assignment Contexts

Контекст присваивания (assignment context) возникает всюду, где значение выражения кладётся в объявленную «ячейку»: правая часть `=`, инициализатор переменной или поля, значение в `return`, элемент инициализатора массива `{…}`, и значение элемента аннотации (в том числе default). Правило простое: выражение **присваиваемо (assignment compatible)** к цели, если его тип приводится к типу цели одним из преобразований (или их разрешённой цепочкой), допустимых в этом контексте, — расширением примитива, упаковкой/распаковкой, расширением ссылки, unchecked, но **не** сужением переменной. У правила есть знаменитое исключение, которое и делает раздел нужным: **сужение константного целочисленного выражения** выполняется неявно, без каста, если значение помещается в целевой тип.

## What assignment allows

Из таблицы контекстов ([[5.8 Conversion Contexts — Overview]]) в присваивании неявно работают: тождественное, расширение примитива, упаковка и распаковка, расширение ссылки, unchecked. Сужения переменной — и примитивного, и ссылочного — здесь нет: их надо писать кастом (то есть переводить в casting-контекст).

```java
long a = 10;            // widening primitive int→long
double b = a;           // widening long→double
Integer c = 10;         // boxing int→Integer
int d = c;              // unboxing Integer→int
Object o = "text";      // widening reference String→Object

int big = 100_000;
short s = big;          // DOES NOT COMPILE: narrowing переменной в assignment нельзя
short s2 = (short) big; // ок: явный каст
```

Присваивание допускает и **цепочки** из нескольких родов по фиксированным шаблонам (§5.2): распаковку с последующим расширением примитива и упаковку с последующим расширением ссылки. «Расширение примитива + упаковка» за один шаг не комбинируется никогда (отсюда `Long x = 8;` не компилируется — см. [[5.4 Boxing and Unboxing Conversion]]).

```java
Integer boxed = 5;
long widened = boxed;   // цепочка: unboxing Integer→int, затем widening int→long
```

## The constant narrowing exception

Ключевая тонкость: если правая часть — **константное выражение времени компиляции** (compile-time constant, §15.29: литералы и `final`-константы примитивов/`String`, соединённые операциями) типа `int` (или `byte`/`short`/`char`), и её значение **влезает** в целевой тип `byte`, `short`, `char`, компилятор выполняет сужение сам, без каста. Значение известно на компиляции, компилятор проверяет попадание в диапазон — и опасности «тихой потери» нет. Это исключение и позволяет писать `byte b = 42;`, хотя `42` — это `int`.

```java
byte b = 42;            // ок: константа 42 влезает в byte, неявное сужение
short sh = 30_000;      // ок: влезает в short
char c = 65;            // ок: 65 в диапазоне char
byte over = 200;        // DOES NOT COMPILE: 200 > Byte.MAX_VALUE (127), не влезает

final int n = 100;
byte fromFinal = n;     // ок: n — compile-time constant, значение известно и влезает

int m = 100;            // не final
byte fromVar = m;       // DOES NOT COMPILE: m — переменная, не константа, значение «неизвестно»
```

Граница исключения жёсткая. Оно действует только для целочисленных константных выражений и целей `byte`, `short`, `char`; на `long`-константу, на переменную (даже со значением в диапазоне) и на вещественные типы оно не распространяется.

```java
final long big = 5;
int x = big;            // DOES NOT COMPILE: источник long — исключение не про long-константы
float f = 1.0;          // DOES NOT COMPILE: 1.0 — double-константа, к float нужен суффикс f или каст
```

## The exception extends to boxing

Если константа влезает в `byte`, `short` или `char`, её можно присвоить не только примитиву, но и **соответствующей обёртке** — компилятор выполнит сужение, а следом упаковку. Это единственный случай, когда упаковка комбинируется с числовым сужением; расширение с упаковкой (`Long x = 8;`), наоборот, не комбинируется никогда.

```java
Byte b = 12;            // ок: сужение int→byte (12 влезает) + упаковка в Byte
Character c = 65;       // ок: int→char + упаковка в Character
Short s = 30_000;       // ок: int→short + упаковка в Short
Byte over = 200;        // DOES NOT COMPILE: 200 не влезает в byte
Long big = 8;           // DOES NOT COMPILE: это расширение int→long, а не сужение
```

## Reference assignment, arrays, and null

Для ссылочных типов присваивание допускает расширение (подтип → надтип) и `null` — любому ссылочному типу. Сужение (надтип → подтип) требует каста. Массивы при присваивании **ковариантны**: `String[]` присваивается переменной `Object[]` — но безопасность такого присваивания проверяется уже при записи в элемент, в runtime (см. раздел ниже).

```java
Number n = Integer.valueOf(5);  // widening Integer→Number
Object o = n;                   // widening Number→Object
Integer back = (Integer) o;     // narrowing: нужен каст, проверка в runtime
String str = null;              // null присваивается любому ссылочному типу
Object[] arr = new String[1];   // ковариантность массивов: компилируется
```

## Unchecked assignment and its runtime consequences

Присваивание разрешает **unchecked**-преобразование — из «сырого» типа в параметризованный — но с предупреждением (Mughal, §11.6 «Unchecked Warnings»): компилятор не может гарантировать типобезопасность, и ответственность переходит к программисту. Это открывает дверь **heap pollution** — ситуации, когда переменная параметризованного типа фактически ссылается на объект с несовместимыми элементами, что позже проявляется `ClassCastException` в неожиданном месте.

```java
List raw = new ArrayList();        // сырой тип
List<String> ls = raw;             // unchecked warning: компилятор не ручается
raw.add(42);                       // heap pollution: внутри «список строк» лежит Integer
// String first = ls.get(0);       // ClassCastException при чтении — далеко от места ошибки
```

Само присваивание — момент, где срабатывают и другие runtime-исключения, скрытые за неявными преобразованиями:

```java
Integer boxed = null;
int prim = boxed;                  // NullPointerException: распаковка null в присваивании

Object[] objs = new String[1];     // ковариантность — компилируется
objs[0] = Integer.valueOf(1);      // ArrayStoreException: фактический тип массива — String[]
```

Оба случая компилируются без нареканий: проверка переносится на время выполнения. Это цена неявности — присваиваемость на компиляции не всегда означает безопасность в runtime.

## Common Mistakes

- Считать, что «раз значение маленькое, присвоится»: правило про **константу**, а не про величину.

```java
int code = 65;
char c = code;          // DOES NOT COMPILE: code — переменная, хоть и равна 65
```
  Правильно: сделать источник константой (`final int code = 65;`) или добавить каст (`(char) code`).

- Забыть суффикс у вещественного/длинного литерала.

```java
float ratio = 3.14;     // DOES NOT COMPILE: 3.14 — double, сужение к float неявно нельзя
long big = 3_000_000_000; // DOES NOT COMPILE: литерал int переполнен ещё до присваивания
```
  Правильно: `float ratio = 3.14f;`, `long big = 3_000_000_000L;`.

- Игнорировать unchecked-предупреждение при присваивании из сырого типа: оно предвещает `ClassCastException` в отрыве от места ошибки.

- Ждать константного сужения при вызове метода — оно только про присваивание (см. [[5.10 Invocation Contexts]]).
