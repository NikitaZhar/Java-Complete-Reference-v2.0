# 4.2.9 double

`double` — 64-битный вещественный тип IEEE 754, около 15–16 значащих десятичных цифр, и тип вещественных чисел по умолчанию в Java. Общая механика (приближённость, `NaN`, бесконечности, запрет `==`, деньги → `BigDecimal`) — в [[4.2.7 Floating-Point Types]]; здесь — почему `double` выбор по умолчанию и где даже его точности не хватает.

## Why double is the default

Вещественный литерал без суффикса — `double`, и это оправдано: 64 бита дают вдвое больше значащих цифр, чем `float`, при той же скорости на современном железе (аппаратура считает `double` нативно). Поэтому для научных расчётов, координат, физики, статистики берут `double`, а `float` — лишь когда критична память (см. [[4.2.8 float]]).

```java
double d = 3.14;           // без суффикса — double
double area = Math.PI * r * r; // все Math-константы и функции возвращают double
float f = (float) d;       // сужение double → float требует приведения и теряет точность
```

## Even double is approximate

Больший размер не отменяет фундаментальной приближённости: `double` — те же двоичные дроби, и `0.1 + 0.2 != 0.3` для него так же истинно (см. [[4.2.7 Floating-Point Types]]). 15–16 цифр лишь отодвигают проблему, но не устраняют накопление погрешности в длинных вычислениях и не делают `double` пригодным для точных денежных сумм. Правило прежнее: сравнение — через эпсилон, деньги — `BigDecimal` или целые минимальные единицы.

Значение по умолчанию — `0.0` ([[4.2.14 Default Values and Initialization]]); обёртка — `Double` ([[4.2.13 Boxing and Unboxing]]).

## Common Mistakes

- Считать, что `double` «достаточно точен для денег».

```java
double total = 0.0;
for (int i = 0; i < 10; i++) total += 0.1;
System.out.println(total);   // 0.9999999999999999, а не 1.0
```
  Правильно: `BigDecimal` с масштабом или целые центы (Ch. 49/50).

- Сравнивать `double` на равенство `==` (см. [[4.2.7 Floating-Point Types]]). Правильно: `Math.abs(a - b) < eps`.
