Грамматика задаёт форму программы. Правила разрешения имён, типов, определённого присваивания и достижимости добавляют ограничения, которых одна успешная проверка формы не подтверждает. Поэтому синтаксически допустимая программа может быть отвергнута компилятором. Здесь различаются виды правил, а не устанавливается обязательный порядок внутренних фаз реализации.

## A Syntactically Valid, Semantically Rejected Program

Полный исходный файл; `x` объявлена локально внутри метода.

```java
class UninitializedExample {
    void test() {
        int x;
        System.out.println(x); // ошибка компиляции: x не присвоено значение
    }
}
```

Синтаксис корректен, но проверка определённого присваивания отвергает чтение локальной переменной. Исправление этого примера: заменить `int x;` на `int x = 0;`. Полные правила — Part I, Ch. 16.

Грамматике здесь не к чему придраться: объявление переменной и вызов метода построены по правилам. Отвергает код семантическая проверка определённого присваивания — она требует, чтобы локальная переменная была гарантированно присвоена до чтения. Это и есть граница: разбор пройден, но смысл некорректен.

## Where Each Semantic Rule Lives

Семантический слой велик, и каждое его правило раскрывается в своей главе — здесь только карта, чтобы видеть картину целиком. Никакая из этих тем в главе о грамматиках не разбирается по существу; при необходимости переходите по указанному адресу.

| Семантическое ограничение      | Что проверяет                                                                      | Дом               |
| ------------------------------ | ---------------------------------------------------------------------------------- | ----------------- |
| Система типов и преобразования | Совместимость типов при присваивании, вызове, возврате; boxing/unboxing            | Part I, Ch. 4–5   |
| Имена и области видимости      | Разрешение имён с учётом области видимости, `shadowing/hiding`                     | Part I, Ch. 6     |
| Определённое присваивание      | Переменная присвоена до чтения; правила для `final`                                | Part I, Ch. 16    |
| Достижимость операторов        | Допустимость операторов по правилам достижимости, в том числе после `return/throw` | Part I, Ch. 14    |
| Исключения                     | Объявление или обработка checked-исключений                                        | Part I, Ch. 17    |
| Управление доступом            | Соблюдение `private`/`protected`/`public`/package-private                          | Part I, Ch. 6, 8  |
| Перегрузка и переопределение   | Применимость и выбор перегруженного метода; ограничения переопределения            | Part I, Ch. 8, 15 |
| Sealed-иерархии                | Наследники в `permits`, статус `final`/`sealed`/`non-sealed`                       | Part I, Ch. 8–9   |
| Generics и вывод типов         | Инвариантность, wildcard, стирание, вывод параметров                               | Part I, Ch. 20    |

Используйте эту карту, чтобы выбрать раздел с правилом, на которое указывает диагностика. Сообщения о токенах и структуре разбираются с помощью глав 2–3; правила типов, имён, инициализации, исключений и доступа — в указанных выше главах.
