Грамматика задаёт форму программы, но не её смысл. Контекстно-свободная грамматика не умеет выражать зависимости между удалёнными частями кода: совпадают ли типы, объявлено ли имя, инициализирована ли переменная, достижим ли оператор. Эти правила — семантические ограничения; компилятор проверяет их уже после успешного разбора, по дереву. Поэтому существует целый класс программ, синтаксически безупречных, но отвергаемых компилятором.

## A Syntactically Valid, Semantically Rejected Program

```java
int x;
System.out.println(x); // ошибка компиляции: variable x might not have been initialized
```

Грамматике здесь не к чему придраться: объявление переменной и вызов метода построены по правилам. Отвергает код семантическая проверка определённого присваивания — она требует, чтобы локальная переменная была гарантированно присвоена до чтения. Это и есть граница: разбор пройден, но смысл некорректен.

## Where Each Semantic Rule Lives

Семантический слой велик, и каждое его правило раскрывается в своей главе — здесь только карта, чтобы видеть картину целиком. Никакая из этих тем в главе о грамматиках не разбирается по существу; при необходимости переходите по указанному адресу.

| Семантическое ограничение | Что проверяет | Дом |
|---|---|---|
| Система типов и преобразования | Совместимость типов при присваивании, вызове, возврате; boxing/unboxing | Part I, Ch. 4–5 |
| Имена и области видимости | Разрешение имён, объявление до использования, shadowing/hiding | Part I, Ch. 6 |
| Определённое присваивание | Переменная присвоена до чтения; правила для `final` | Part I, Ch. 16 |
| Достижимость операторов | Недостижимый код после `return`/`throw`, пустые ветки | Part I, Ch. 14 |
| Исключения | Объявление или обработка checked-исключений | Part I, Ch. 17 |
| Управление доступом | Соблюдение `private`/`protected`/`public`/package-private | Part I, Ch. 6, 8 |
| Перегрузка и переопределение | Различие по сигнатуре; совместимость при `@Override` | Part I, Ch. 8 |
| Sealed-иерархии | Наследники в `permits`, статус `final`/`sealed`/`non-sealed` | Part I, Ch. 8–9 |
| Generics и вывод типов | Инвариантность, wildcard, стирание, вывод параметров | Part I, Ch. 20 |

Практический вывод для чтения ошибок компилятора: если сообщение про структуру, скобки или неожиданный токен — причина в грамматике (главы 2–3); если про типы, имена, инициализацию, исключения или доступ — причина в семантике, и искать её надо в соответствующей главе выше.
