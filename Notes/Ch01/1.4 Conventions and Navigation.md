Этот подраздел описывает соглашения оформления справочника и то, как ориентироваться в нём и в первоисточниках.

## Text and Code Conventions

Заголовки разделов и подразделов даются на английском, а текст изложения — на русском: так с материалом проще работать и сопоставлять его со спецификацией. Идентификаторы кода — классы, методы, ключевые слова — оформляются моноширинным начертанием: `String`, `hashCode()`, `sealed`. Версии языка обозначаются единообразно: «Java 21», «SE 25». Термин при первом появлении в главе даётся парой «русский (english)», далее используется один выбранный вариант последовательно.

## Example Conventions

Примеры могут быть полными исходными файлами или фрагментами кода. Контекст размещения, необходимые импорты и условия запуска указываются там, где без них пример неоднозначен. Если демонстрируется результат выполнения, рядом приводится ожидаемый вывод или исключение.

Пометки «ошибка компиляции» и `DOES NOT COMPILE` обозначают намеренно некорректный код. Пометки «ошибка времени выполнения», `runtime` или имя ожидаемого исключения с пояснением обозначают код, который компилируется, но завершается ошибкой в показанных условиях. Причина и способ исправления объясняются рядом с примером.

Базовая версия примеров — Java SE 25. Использование preview- или incubator-возможностей отмечается отдельно с указанием релиза и необходимых параметров компиляции или запуска. Пометка «Java N+» обозначает минимальную версию, с которой доступна рассматриваемая возможность, и сама по себе не меняет базовую версию справочника.

Работа с инструментами компиляции и запуска предусмотрена в Part III, Chapter 30; экспериментальные возможности — в Part I, Chapter 22.

## Note Status

У каждой заметки есть статус готовности: `todo` — не начато, `draft` — черновик, `expand` — нужно расширить, `format` — нужна вёрстка, `check` — нужна сверка, `done` — соответствует эталону. Статус виден в свойствах заметки и помогает отслеживать состояние справочника по мере его роста.

## Cross-References

Перекрёстные ссылки ведут к соответствующим заметкам и терминам глоссария. Отсылка к другой главе даётся одной строкой, без пересказа: «подробнее см. Part X, Y.Z». В ссылках на спецификации используется отдельное обозначение: «JLS SE 25, §4.2» или «JVMS SE 25, §2.3». Номера глав справочника и спецификаций могут различаться.

## Navigating the Primary Sources

Для проверки правил и семантики языка обращайтесь к JLS; формата class-файла и выполнения инструкций виртуальной машины — к JVMS; контрактов стандартных библиотек — к Java SE API; работы инструментов — к руководствам JDK. В таблице ниже номера глав относятся к JLS SE 25, а не к нумерации этого справочника.

| Вопрос | Где искать |
|---|---|
| Разрешён ли такой синтаксис? | JLS: грамматики (Ch. 2), лексика (Ch. 3), операторы и выражения (Ch. 14–15) |
| Какой тип и значение у выражения? | JLS: типы и преобразования (Ch. 4–5), выражения (Ch. 15) |
| Почему код не компилируется? | Правило JLS соответствующей главы плюс определённое присваивание (definite assignment), разрешение перегрузки (overload resolution), вывод типов (type inference) |
| Почему такое поведение во время выполнения? | JLS (семантика) и при необходимости JVMS (верификация, исполнение) |
| Какими классами это делается? | Java SE API |
| Когда появилась фича и каков её статус? | JEP и Release Notes (Preview / Incubator / Standard) |
