# 4.2.12 Promotions and Conversions

Между примитивными типами постоянно происходят преобразования — часто неявно, и именно неявные чаще всего и подводят. Здесь — практический минимум про числовое продвижение и расширение/сужение, которого хватает при работе с примитивами. Полные правила всех контекстов преобразования (присваивание, приведение, вызов метода, конкатенация строк) — дом Ch. 5, сюда вынесено ссылкой, чтобы не раздваивать теорию.

## Widening versus narrowing

Расширяющее преобразование (widening) идёт к «более ёмкому» типу (`byte→short→int→long→float→double`, `char→int`) и выполняется **неявно**: данные не теряются по величине (хотя `long→float`/`double` может терять младшие значащие цифры). Сужающее (narrowing) идёт в обратную сторону, требует **явного приведения** и может молча потерять и биты, и знак.

```java
int i = 100;
long l = i;          // widening: неявно
double d = l;        // widening: неявно

int back = (int) d;  // narrowing: нужен каст
byte b = (byte) 300; // narrowing: 300 не влезает → 44 (младшие 8 бит)
```

## Numeric promotion recap

Перед арифметикой действует числовое продвижение: одиночные `byte`, `short`, `char` продвигаются к `int` (unary promotion), а в бинарной операции оба операнда — к более широкому из участвующих (binary promotion). Механизм и его причина (у JVM нет инструкций уже́ `int`) разобраны в [[4.2.1 Integral Types]]; практическое следствие — сумма двух `byte` имеет тип `int`, и присвоить её обратно в `byte` без приведения нельзя.

Одно исключение стоит запомнить: при присваивании **константы** компилятор сам проверяет, влезает ли она, и разрешает без каста — но только если это константа и она в диапазоне.

```java
byte ok = 10;        // ок: константа 10 влезает в byte, каст не нужен
int n = 10;
byte bad = n;        // compile-time error: n — переменная, не константа; нужен (byte)
byte over = 200;     // compile-time error: 200 не влезает в byte даже как константа
```

## Common Mistakes

- Считать сужение безопасным, «раз компилятор пропустил каст».

```java
long big = 10_000_000_000L;
int i = (int) big;   // молча теряет старшие биты: 1410065408
```
  Правильно: сужать только когда старшие биты не нужны; иначе проверять диапазон (`Math.toIntExact(big)` бросит исключение при потере).

- Ждать неявного `int→byte`/`long→int` при присваивании переменной. Правильно: неявно идёт только расширение; сужение — всегда явным приведением, с пониманием риска.
