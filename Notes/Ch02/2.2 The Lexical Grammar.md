Лексическая грамматика описывает первый переход: как поток Unicode-символов исходного файла превращается в поток токенов, с которым дальше работает синтаксическая грамматика. Её целевой символ — `Input`. Здесь важен именно механизм перехода и правило, по которому лексер режет поток на токены; полный каталог самих токенов (идентификаторы, ключевые слова, все виды литералов, операторы) — предмет главы 3, и здесь он не повторяется. Подробнее см. [[Chapter 3. Lexical Structure]].

## Input Processing in Three Steps

Сначала допустимые Unicode-escape вида `\uXXXX` переводятся в кодовые единицы UTF-16. Затем выделяются входные символы и терминаторы строк CR, LF и CRLF; CRLF считается одним терминатором. После этого выделяются входные элементы: пробельные символы, комментарии и токены. Пробельные символы и комментарии отбрасываются.

Порядок преобразований принципиален: допустимый Unicode-escape перевода строки может завершить строчный комментарий ещё до разбора комментариев. Оставшаяся часть исходной строки затем разбирается как код; её исполнимость зависит от синтаксиса и семантики. Подробный пример и правила допустимости escape — [[3.3 Unicode Escapes]].

## The Longest-Match Rule

На каждом шаге лексической трансляции действует правило наибольшего совпадения (longest match / maximal munch): выбирается самый длинный допустимый вариант, даже если результат делает программу некорректной. Есть исключения для последовательных обратных косых на шаге 1 и для контекстных ключевых слов и соседних `>` на шаге 3. Детали — [[3.3 Unicode Escapes]] и [[3.5 Input Elements and Tokens]].

Два независимых фрагмента тела метода; `a` и `b` — заранее объявленные переменные типа `int`.

```java
int r = a--b;   // токены выражения: a, --, b; ошибка синтаксиса
int r = a- -b;  // токены выражения: a, -, -, b; корректная разность
```

В первом случае `--` — один токен; полученная последовательность не образует выражение Java. Во втором два `-` — отдельные токены, и выражение означает `a - (-b)`. При `a = 5`, `b = 2` результат равен `7`.

Без пробела `--` собирается в один токен-декремент, и выражение перестаёт компилироваться как разность. Тот же принцип объясняет, почему для двух унарных минусов подряд нужен разделитель. Это чисто лексический эффект: он решается на уровне токенов, до синтаксического разбора.

## What the Lexical Grammar Produces

На выходе — поток токенов пяти категорий (идентификаторы, ключевые слова, литералы, операторы, разделители), который синтаксическая грамматика (2.3) принимает уже как терминалы, ничего не зная о том, как они были собраны.
