# 5.1 Kinds of Conversion — Overview

Преобразование (conversion) — это правило, связывающее тип выражения-источника с типом, который требуется в данном месте программы. Java — язык со строгой статической типизацией: компилятор в каждой точке знает объявленный тип выражения и тип, который там ожидается, и должен решить, допустим ли переход и что с значением произойдёт. Все допустимые переходы образуют закрытый **каталог родов преобразований**; никаких «преобразований вообще» вне этого каталога не существует. Этот раздел перечисляет роды и вводит вторую ось — контекст, — потому что один и тот же род в разных местах программы то разрешён неявно, то требует явного каста, то запрещён вовсе.

## The catalogue of conversion kinds

JLS (§5.1) выделяет фиксированный набор родов. Практически значимые из них — семь; ещё несколько существуют для полноты или живут в других главах.

Тождественное преобразование (identity conversion) — переход типа в самого себя; всегда разрешён и ничего не меняет. **Расширяющее примитивное (widening primitive)** — из более узкого числового типа в более широкий (`int`→`long`, `int`→`double`). **Сужающее примитивное (narrowing primitive)** — из широкого в узкий (`long`→`int`, `double`→`byte`), с возможной потерей информации. **Упаковка и распаковка (boxing / unboxing)** — примитив↔обёртка (`int`↔`Integer`). **Расширяющее и сужающее ссылочное (widening / narrowing reference)** — вверх и вниз по иерархии типов (`String`→`Object` и обратно). **Строковое (string)** — любое значение → `String` в конкатенации. **Преобразование множеств значений (value set)** — выбор представления вещественного значения.

Ещё два рода — **unchecked** (между «сырым» и параметризованным типом) и **capture** (захват wildcard) — обслуживают дженерики; их дом Ch. 20, здесь они только названы. Отдельно стоит **запрещённое преобразование (forbidden)** — не отдельная операция, а обозначение пар типов, между которыми перехода нет (например, `boolean` и любой числовой тип): попытка приводит к ошибке компиляции.

| Род преобразования | Пример | Потеря информации | Проверка в runtime |
|---|---|---|---|
| Identity | `int`→`int` | нет | нет |
| Widening primitive | `int`→`long`, `int`→`double` | возможна (точность) | нет |
| Narrowing primitive | `long`→`int`, `double`→`byte` | да | нет |
| Boxing | `int`→`Integer` | нет | нет |
| Unboxing | `Integer`→`int` | нет | да (`null`→NPE) |
| Widening reference | `String`→`Object` | нет | нет |
| Narrowing reference | `Object`→`String` | нет | да (`ClassCastException`) |
| String | `int`→`String` (в `+`) | нет | нет |

## The second axis: contexts

Знать род недостаточно: разрешённость перехода зависит от **контекста** — синтаксического места, где стоит выражение. JLS различает несколько контекстов; практически важны пять: присваивание, вызов метода, каст, конкатенация строк и числовой контекст (операнды арифметики). Каждый контекст допускает **своё подмножество** родов.

```java
int i = 100;
long a = i;            // assignment context: widening primitive — неявно ок
Integer b = i;         // assignment context: boxing — неявно ок
byte c = 100;          // assignment context: narrowing КОНСТАНТЫ — исключение, ок без каста
byte d = i;            // ошибка компиляции: narrowing переменной в assignment запрещено неявно
byte e = (byte) i;     // casting context: narrowing разрешено явным кастом
```

Одно и то же сужение `int`→`byte` здесь то запрещено (`d`), то разрешено как исключение для константы (`c`), то разрешено кастом (`e`). Именно пересечение «род × контекст» задаёт правило, а не род сам по себе. Полная карта «контекст → допустимые роды» — в [[5.8 Conversion Contexts — Overview]].

## Implicit versus explicit

Преобразование бывает **неявным** (компилятор применяет его сам, если контекст позволяет) или **явным** (программист пишет каст `(Type)`). Как правило, расширяющие переходы неявны, сужающие требуют явного каста. Каст не только разрешает сужение — он же служит подсказкой при разрешении перегрузки и при работе с обёртками; подробнее — [[5.11 Casting Contexts]].

```java
double x = 5;          // неявное widening: int-литерал 5 → double
int y = (int) 5.9;     // явное narrowing: нужен каст, дробная часть отбрасывается → 5
```

## Common Mistakes

- Считать, что «преобразование либо есть, либо нет» вне зависимости от места. Один и тот же род то неявен, то требует каста, то запрещён — смотреть надо на контекст.

```java
long big = 10;
int small = big;          // DOES NOT COMPILE: narrowing переменной неявно нельзя
```
  Правильно: `int small = (int) big;` — явный каст в casting-контексте (с осознанием возможной потери).

- Путать «расширяющее» с «без потерь»: расширение `int`→`float` или `long`→`double` укладывает значение в тип с большим диапазоном, но точность при этом может теряться (см. [[5.2 Identity and Widening Primitive Conversion]]).
