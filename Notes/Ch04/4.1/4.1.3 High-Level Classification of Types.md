# 4.1.3 High-Level Classification of Types

Верхнеуровневое деление типов в Java — на **примитивные** и **ссылочные** — определяет практически всё: как значение хранится, копируется, сравнивается, допускает ли `null` и годится ли в аргумент generics. Этот раздел собирает различия в одном месте; диапазоны и представление примитивов — в [[4.2 Primitive Types and Values]], устройство ссылочных типов — в [[4.3 Reference Types and Values]].

## Primitive types

Примитивных типов ровно восемь, они встроены в язык и не определяются пользователем: `byte`, `short`, `int`, `long`, `float`, `double`, `char`, `boolean`. Примитив — это не объект и не ссылка на объект, а одно значение в памяти (число, символ или булев флаг). У него фиксированный размер, он не входит в иерархию `Object`, не принимает `null` и не может быть аргументом типа в generics.

```java
int n = 42;             // одно значение в памяти
boolean flag = true;
char c = 'A';

Integer boxed = n;      // чтобы попасть в generics/коллекции — обёртка (boxing), см. 4.2
List<Integer> xs = List.of(n); // List<int> невозможен
```

Ошибки, вытекающие из «не-объектности» примитива:

```java
int x = 5;
x.toString();           // compile-time error: у примитива нет методов
int y = null;           // compile-time error: примитив не принимает null
List<int> bad;          // compile-time error: generics только по ссылочным типам
```

## Reference types

Ссылочный тип — тип, значение которого есть ссылка на объект в куче либо `null`. Четыре разновидности: **классы** (`String`, `ArrayList`), **интерфейсы** (`Runnable`, `List`), **массивы** (`int[]`, `String[]`) и **типовые переменные** generics (`T`, `E`). Все они — подтипы `Object` (даже массивы), поддерживают наследование и полиморфизм и допускают `null`.

```java
String s = "text";      // класс
Runnable r = () -> {};  // интерфейс
int[] a = {1, 2, 3};    // массив — тоже объект, подтип Object
Object o = a;           // ок: int[] <: Object
```

Типовые переменные (`T`, `E`, `K`, `V`) — тоже ссылочные типы, но существуют только на компиляции: во время выполнения их информация стёрта (см. Ch. 20). Поэтому `T` нельзя использовать там, где нужен полноценный runtime-тип (`new T()`, `T.class` невозможны).

## Primitive versus reference: the practical table

| Характеристика | Примитивные | Ссылочные |
|---|---|---|
| Что в переменной | само значение | ссылка на объект (или `null`) |
| Размещение | в стеке или внутри объекта | ссылка — в стеке/поле, объект — в куче |
| `null` | нет | да |
| Наследование, полиморфизм | нет | да |
| Аргумент generics | нет (через обёртку) | да |
| Сравнение `==` | по значению | по ссылке (identity), не по содержимому |

Последняя строка — источник самых частых ошибок: `==` для ссылок сравнивает тождество ссылок, а не содержимое объектов; для сравнения по значению нужен `equals` (см. [[4.1.8 Common Pitfalls]] и [[4.3 Reference Types and Values]]).

Отдельно стоит держать в голове перспективу Project Valhalla — **value classes**, объекты без идентичности, которые JVM сможет хранить «плоско», как примитивы, но с объектным интерфейсом. На момент базовой версии книги это ещё не финализированная возможность; на классификацию «примитив/ссылка» на уровне исходного кода она принципиально не влияет.

## Common Mistakes

- Сравнивать объекты через `==`, ожидая сравнения содержимого.

```java
String a = new String("abc");
String b = new String("abc");
System.out.println(a == b);      // false: разные объекты
System.out.println(a.equals(b)); // true: одинаковое содержимое
```
  Правильно: для содержимого — `equals`; `==` оставить примитивам и проверке тождества/`null`.

- Пытаться параметризовать generics примитивом.

```java
Map<int, String> m;     // compile-time error
Map<Integer, String> m2 = new HashMap<>(); // правильно — обёртка
```
