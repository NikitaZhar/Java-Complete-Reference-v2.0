Терминатор строки (`line terminator`) — это символ или пара символов, которыми компилятор делит поток входных символов на строки. Java признаёт три формы: `LF` (`\u000A`, «`newline`»), `CR` (`\u000D`, «`return`») и пару `CR LF`. Практическая ценность понятия в том, что от него зависят три вещи: где заканчивается `//`-комментарий, какие номера строк показывает компилятор в ошибках, и (косвенно) переносимость исходников между Windows, Unix и старыми Mac. Это шаг 2 лексической трансляции ([[3.2 Lexical Translations]]); нормализация переводов строк внутри строковых значений — отдельная тема ([[3.10.5 String Literals]]).

## The Three Forms

```
LineTerminator:
    LF          (перевод строки, \u000A)
    CR          (возврат каретки, \u000D)
    CR LF       (возврат каретки, за которым сразу идёт перевод строки)
```

Ключевая тонкость: пара `CR LF` считается одним терминатором, а не двумя. Это отражает соглашения разных ОС: Unix/Linux/современный macOS используют `LF`, Windows — `CR LF`, классический Mac OS (до X) использовал `CR`. Все три компилятор принимает одинаково, поэтому один и тот же файл, сохранённый с разными окончаниями строк, компилируется идентично.

```java
// Одна строка кода, завершённая CR LF (Windows) или LF (Unix) —
// для компилятора это один терминатор в обоих случаях
int x = 1;
```

Входной символ (`InputCharacter`) определяется как любой Unicode-символ, кроме `CR` и `LF`: то есть терминаторы строк не входят в «тело» строки и обрабатываются отдельно от её содержимого.

## Why It Matters in Practice

Терминатор строки завершает `//`-комментарий ([[3.7 Comments]]): всё от `//` до конца строки игнорируется, а сама строка кончается на ближайшем терминаторе. Отсюда — эффект из [[3.3 Unicode Escapes]]: Unicode-escape перевода строки (`\u000A`), развёрнутый на шаге 1, физически завершает комментарий раньше, чем кажется по виду исходника.

Кроме того, строки, определённые терминаторами, задают номера строк в диагностике компилятора и стек-трейсах. Смешение стилей окончаний в одном файле обычно безвредно для компиляции, но ломает `diff`, аннотации системы контроля версий и иногда номера строк в инструментах — поэтому в проекте окончания строк держат единообразными (например, через `.gitattributes` или `.editorconfig`; это практика инструментов, а не язык).

```java
String a = "x";     // строка 1
                    // строка 2 (пустая с комментарием)
String b = "y";     // строка 3 — номер строки берётся из деления по терминаторам
```
