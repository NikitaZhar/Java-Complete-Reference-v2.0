# 5.6 String Conversion

Строковое преобразование (string conversion) — единственный род, который применяется в очень узком, но повсеместном месте: **оператор конкатенации `+`, когда хотя бы один операнд — `String`**. В этом контексте значение любого другого типа — примитив, ссылка, `null` — автоматически превращается в `String`. Это то, что позволяет писать `"x = " + 42` и `"result: " + obj`, не вызывая `toString()` вручную. Раздел объясняет, во что именно превращается каждый род значений, где у этого удобства острые углы, и заодно очерчивает противоположную границу каталога — **запрещённые преобразования** (forbidden), которых не существует ни в одном контексте.

## The rule — and the exact boundary JLS guarantees

Если в выражении `a + b` хотя бы один операнд имеет тип `String`, второй подвергается строковому преобразованию, и результат — новый `String`, склейка двух. Точная семантика (JLS §5.4):

- **примитив** — превращается в строку через соответствующий `Wrapper.valueOf(...)` → `toString()` (например, `Integer.valueOf(n).toString()`);
- **ссылка `null`** — в строку `"null"`, без `NullPointerException`;
- **ненулевая ссылка** — вызывается её `toString()`; **но если `toString()` вернул `null`, результатом становится строка `"null"`**.

Последний пункт — не мелочь: распространённая модель «строковое преобразование = `String.valueOf(x)`» этот случай **не выражает**. `String.valueOf(Object)` для объекта, чей `toString()` вернул `null`, возвращает **сам `null`-ссылку**, а строковое преобразование JLS — строку `"null"`. Разница проверяется напрямую:

```java
class N { public String toString() { return null; } }

String viaConcat  = "" + new N();               // JLS string conversion → строка "null"
String viaValueOf = String.valueOf((Object) new N()); // → сам null (не строка!)
System.out.println(viaConcat  == null);         // false — это строка "null"
System.out.println(viaValueOf == null);         // true  — это null-ссылка
```

Обычные случаи ведут себя ожидаемо:

```java
int n = 42;
String a = "n = " + n;          // int → "42": "n = 42"
String b = "flag: " + true;     // boolean → "true"
String c = "ch: " + 'A';        // char → "A" (не код!)
Object o = null;
String d = "value = " + o;      // null → "null": "value = null"
int[] arr = {1, 2, 3};
String e = "arr = " + arr;      // toString массива → "arr = [I@1b6d3586" (не элементы!)
```

`char` в конкатенации даёт сам символ (`"A"`), а не его код, — в отличие от числового контекста, где `'A'` продвигается до `65`. Массив печатается как `[I@…`, потому что `toString()` у массивов не переопределён; для содержимого нужен `Arrays.toString(arr)`.

## Forbidden conversions: the closed boundary of the catalogue

Строковое преобразование — самый «всеядный» род (любой тип → `String`). Полезно тут же назвать противоположность: **запрещённые преобразования** (§5.1.12) — пары типов, между которыми перехода нет ни в одном контексте, даже кастом. Это не отдельная операция, а замыкание каталога: всё, что не описано ни одним разрешённым родом, запрещено, и попытка — ошибка компиляции.

| Откуда → куда | Пример | Почему |
|---|---|---|
| `boolean` ↔ любой числовой | `int i = true;`, `boolean b = 1;` | `boolean` не число (см. [[4.2.10 boolean]]) |
| ссылка → примитив (кроме unboxing) | `int i = "5";` | нет ни распаковки, ни числового рода |
| примитив → ссылка (кроме boxing) | `String s = 5;` | `int` не подтип `String`; boxing даёт только обёртку |
| `null` → примитив | `int i = null;` | у примитива нет значения «ничего» |

```java
// все — compile-time error (incompatible / inconvertible types):
// int i = true;
// boolean b = 1;
// int i = "5";
// String s = 5;            // число в строку — только через конкатенацию: "" + 5
// boolean b = (boolean) 1; // даже явный каст не открывает запрещённый переход
```

Важно: `String s = 5;` запрещено, но `String s = "" + 5;` работает — потому что это уже **строковое** преобразование в контексте `+`, а не прямой переход `int`→`String`.

## Precedence: + is left-associative

`+` вычисляется слева направо и имеет одинаковый приоритет для сложения и конкатенации. Как только слева появился `String`, всё дальнейшее становится конкатенацией; но пока строки слева нет, `+` — это арифметика.

```java
System.out.println("Sum: " + 2 + 3);    // "Sum: 23" — ("Sum:"+2)+3, обе конкатенации
System.out.println("Sum: " + (2 + 3));  // "Sum: 5" — скобки делают сложение первым
System.out.println(2 + 3 + " = sum");   // "5 = sum" — 2+3 сложились до появления строки
```

## Under the hood and performance

Начиная с Java 9 компилятор реализует конкатенацию через `invokedynamic` и `StringConcatFactory`, а не через явный `StringBuilder`; одиночная конкатенация эффективна. Но **в цикле** каждая итерация `s = s + x` создаёт новый `String` (строки неизменяемы), давая квадратичную работу. Устройство `String`, неизменяемость и `StringBuilder` — тема глав о строках (Ch. 50); здесь важно лишь, что строковое преобразование скрывает создание объектов.

```java
String s = "";
for (int i = 0; i < n; i++) {
    s = s + i;                  // каждая итерация — новый String: O(n^2) по суммарной работе
}
```

## Common Mistakes

- Ожидать сложение, когда слева уже строка.

```java
String label = "Items: " + 2 + 3;   // "Items: 23", а не "Items: 5"
```
  Правильно: сгруппировать арифметику скобками — `"Items: " + (2 + 3)`.

- Печатать массив (или объект без осмысленного `toString`) через конкатенацию и ждать содержимое.

```java
int[] data = {1, 2, 3};
log("data = " + data);              // "data = [I@…", а не элементы
```
  Правильно: `Arrays.toString(data)` для массива; переопределить `toString()` у своих классов.

- Полагаться на `String.valueOf(obj)` там, где нужна семантика конкатенации: если `obj.toString()` может вернуть `null`, `String.valueOf` вернёт `null`-ссылку, а `"" + obj` — строку `"null"`.

- Строить строку конкатенацией в цикле на горячем пути.

```java
String csv = "";
for (String field : fields) csv = csv + field + ",";  // O(n^2)
```
  Правильно: `StringBuilder` или `String.join(",", fields)` (детали — Ch. 50).
