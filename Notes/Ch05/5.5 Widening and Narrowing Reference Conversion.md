# 5.5 Widening and Narrowing Reference Conversion

У ссылочных типов «шире/уже» задаётся не диапазоном чисел, а **отношением подтипов**: тип-подтип уже своего надтипа, потому что он — специализация. Отсюда два рода ссылочных преобразований. **Расширяющее ссылочное (widening reference, upcasting)** — переход вверх по иерархии, от подтипа к надтипу (`String`→`Object`); всегда безопасно и неявно. **Сужающее ссылочное (narrowing reference, downcasting)** — переход вниз, от надтипа к подтипу (`Object`→`String`); требует явного каста и обычно **проверяется в runtime**, а при несоответствии бросает `ClassCastException`. Механику самого отношения подтипов задаёт [[4.1.6 Subtypes and Supertypes]]; здесь — что происходит со ссылкой, где downcast проверяется полностью, где лишь частично, и когда компилятор отвергает каст сразу.

## Upcasting: always safe, always implicit

Значение подтипа годится везде, где ожидается надтип, поэтому расширение вверх компилятор делает сам, без каста и без проверки во время выполнения. Ссылка при этом не меняет объект — меняется лишь **статический тип**, через который на него смотрят; сужается набор доступных членов, но исполняемый тип объекта прежний (см. [[4.1.5 Static vs Runtime Type]]).

```java
String s = "hello";
Object o = s;               // widening reference: String → Object, неявно
CharSequence cs = s;        // widening: String → интерфейс-надтип
Integer boxed = 42;
Number num = boxed;         // widening: Integer → Number
Object any = new int[]{1};  // массивы тоже подтипы Object
```

## Downcasting: explicit and runtime-checked

Обратный переход — обещание «за этой ссылкой на самом деле лежит более конкретный тип». Компилятор видит лишь статический тип надтипа, поэтому требует явного каста, а JVM в момент выполнения сверяет фактический класс с целевым типом: совпал — ссылка получает новый статический тип; не совпал — `ClassCastException`.

```java
Object o = "hello";
String s = (String) o;      // narrowing reference: проверка в runtime проходит
Object o2 = Integer.valueOf(7);
String bad = (String) o2;   // компилируется, но в runtime ClassCastException
```

Безопасная форма downcast — `instanceof` с образцом (совмещает проверку и приведение); это конструкция testing-контекста ([[5.14 Testing Contexts and Pattern Compatibility]], Ch. 14.7).

```java
if (o instanceof String str) { System.out.println(str.length()); }
```

## Arrays: covariant, narrowing checked at runtime

Массивы ковариантны: `String[] <: Object[]`, поэтому upcast массива неявен, а downcast — явным кастом с проверкой в runtime по фактическому компонентному типу.

```java
Object[] oa = new String[1];
String[] sa = (String[]) oa;    // ок: фактически String[]
Object o = new Integer[1];
String[] bad = (String[]) o;    // компилируется, но ClassCastException: это Integer[]
```

## Checked, partially unchecked, completely unchecked

Ключевая тонкость, которую скрывает формула «downcast проверяется в runtime»: **не всякое** сужение ссылки проверяется JVM полностью. Из-за стирания типов (§5.1.6) JLS различает три степени:

- **Checked** — цель реифицируема (не-обобщённый тип, сырой тип, массив реифицируемого): `(String) o`, `(List) o`, `(String[]) o`. JVM проверяет полностью; несоответствие — `ClassCastException`.
- **Partially unchecked** — цель параметризована: `(List<String>) o`. JVM проверяет только **стирание** (что это `List`), но **не** аргументы типа. Отсюда unchecked-предупреждение и риск heap pollution — нарушение по элементу всплывёт позже и не в месте каста.
- **Completely unchecked** — например каст к **типовой переменной** `(T) o`: она стёрта до своей границы, и осмысленной runtime-проверки нет вовсе.

```java
List<String> ls1 = (List<String>) someObject;   // partially unchecked: проверен только List
<T> T cast(Object o) { return (T) o; }           // completely unchecked: T стёрт до границы
```

Практический вывод: `@SuppressWarnings("unchecked")` — это принятие ответственности за проверку, которую компилятор и JVM выполнить не могут. Полное раскрытие unchecked/capture и generics — Ch. 20.

## Type variables and intersection targets

Целью сужения может быть **типовая переменная** (проверяется по её границе) или **intersection type** — тогда каст утверждает соответствие сразу нескольким типам (`(A & B) x`, см. [[5.11 Casting Contexts]]). Это расширяет, что можно downcast'ить, но проверяемость по-прежнему ограничена стиранием.

## Provably distinct types: rejected at compile time

Если компилятор может **доказать**, что два типа не пересекаются (значение не может быть обоими сразу), каст отвергается сразу — до runtime.

- Два несвязанных класса: `String` и `Integer` — `inconvertible types`.
- **Финальный** класс и несвязанный интерфейс: `String` (final, не реализует `Runnable`) → `(Runnable) s` не компилируется. А вот `(Runnable) someObject` для нефинального типа компилируется — подкласс мог бы реализовать `Runnable`, и решение переносится в runtime.
- **Sealed**-иерархии дают компилятору полный список наследников, и он может доказать непересечение даже там, где обычно ждал бы runtime:

```java
sealed interface Shape permits Circle, Square {}
final class Circle implements Shape {}
final class Square implements Shape {}

void m(Circle c) {
    // Square sq = (Square) c; // DOES NOT COMPILE: Circle и Square заведомо непересекаемы
}
```

`null` — особый случай: приводится к любому ссылочному типу и проходит любой downcast без исключения, проверять нечего.

```java
Object o = null;
String s = (String) o;      // ок, без CCE
```

## Common Mistakes

- Делать downcast без проверки типа.

```java
Object o = config.get("port");
Integer port = (Integer) o;     // ClassCastException, если там оказалась String
```
  Правильно: `if (o instanceof Integer port) { … }`.

- Считать `(List<String>) obj` полностью проверенным: проверен только `List`, тип элементов — нет; несовместимый элемент всплывёт позже как `ClassCastException` при чтении.

- Путать смену статического типа со сменой объекта: upcast не «превращает» объект и не теряет переопределённое поведение.

```java
Object o = new ArrayList<String>();
// o.add("x");                  // DOES NOT COMPILE: у Object нет add — виден только API Object
```
  Правильно: обращаться через подходящий статический тип.

- Кастовать между несвязанными типами, надеясь на runtime.

```java
Number n = 5;
// String s = (String) n;       // DOES NOT COMPILE: Number и String несовместимы
String s = n.toString();        // правильно: преобразовывать значением
```
