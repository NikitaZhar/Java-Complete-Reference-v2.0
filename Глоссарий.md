# Глоссарий

Единый список терминов и их канонического написания для всей книги. Один термин — одно написание везде. Перед тем как объяснять термин в главе, проверь его здесь: если у термина есть «дом» (глава-владелец) — в других главах только ссылка, а не повторное определение. Точка входа проекта: [[00 — Правила и методика (читать первым)]]. Владельцы тем: [[Матрица владения темами]].

## Правила ведения

Новый термин вводится сначала здесь, потом используется в главе. Для каждого термина: каноническое написание, короткое определение (1–2 строки), глава-«дом» и concept-тег. Не заводить синонимы ради разнообразия текста. Если у понятия есть устоявшийся русский и английский вариант — фиксируем оба и используем последовательно. Английские идентификаторы — в `коде`.

Каждому термину соответствует тег `#concept/<slug>` (колонка «Тег»). Он ставится на заметки, где понятие раскрывается или существенно используется, и именно он связывает их в graph view и даёт найти весь материал по термину. Новый термин → сразу задать ему concept-тег здесь.

## Соглашения о написании

Названия классов/методов/ключевых слов — латиницей в `коде`: `String`, `hashCode()`, `sealed`. Русскоязычные термины — строчными, если это не имя собственное. Версии Java — «Java N» / «SE N» (например «Java 21», «SE 25»). Пары «рус. (англ.)» при первом употреблении в главе: «стирание типов (type erasure)», далее — один выбранный вариант последовательно.

## Спорные/несогласованные написания (свести к одному)

Заносить сюда, когда замечено расхождение между главами. Например: generics wildcard — выбрать одно написание «подстановочный тип (wildcard)», не смешивать «варианты»/«типы». Добавлять по мере обнаружения.
