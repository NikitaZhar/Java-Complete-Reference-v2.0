Литерал с плавающей точкой записывает значение типа `float` или `double`. Тип по умолчанию — `double`; суффикс `f`/`F` даёт `float`, суффикс `d`/`D` (необязательный) — `double`.

```java
double pi = 3.1415;      // double по умолчанию
float  e  = 2.71828f;    // float — из-за суффикса f
double d  = 2.0d;        // суффикс d необязателен, но допустим
```

Самая частая ошибка новичков — присвоить `double`-литерал переменной `float` без суффикса. Это ошибка компиляции, потому что `double` шире `float`.

```java
float bad = 3.14;   // ошибка компиляции: 3.14 — это double
float ok  = 3.14f;  // правильно
```

## Decimal and Hexadecimal Forms

Десятичная форма допускает необязательную экспоненту `e`/`E`. Допустимы формы с точкой без дробной части и без целой.

```java
double a = 1.23e3;   // 1230.0  (мантисса × 10^3)
double b = 1.5E-2;   // 0.015
double c = 1.;       // 1.0  — точка без дробной части допустима
double f = .5;       // 0.5  — без целой части тоже допустимо
double g = 1e3;      // 1000.0 — с экспонентой точка не нужна
```

Шестнадцатеричная форма начинается с `0x`, а показатель степени двойки задаётся через `p`/`P` и **обязателен**.

```java
double h = 0x1.8p1;  // 1.5 × 2^1 = 3.0
double bad = 0x1.8;  // ошибка компиляции: у hex-формы нет показателя p
```

Шестнадцатеричная форма нужна редко — она даёт точный контроль над битами и применяется в численных библиотеках и тестах IEEE 754.

## Underscores

`_` допустим только между цифрами.

```java
double ok  = 3.141_592;    // ок
double e1  = 3._14;        // ошибка: сразу после точки
double e5  = 1000_.00;     // ошибка: сразу перед точкой
double e2  = 3.14_;        // ошибка: в конце
double e3  = 1_e3;         // ошибка: рядом с экспонентой
double e4  = 1.0_f;        // ошибка: перед суффиксом
```

## Range, Overflow, and Underflow

В отличие от арифметики во время выполнения, где переполнение даёт `Infinity`, а потеря значимости — `0.0`, **литерал** так вести себя не может. Ненулевой литерал с плавающей точкой, который при округлении к внутреннему представлению превращается в IEEE-бесконечность (слишком велик) или в ноль (слишком мал), — это **ошибка компиляции**, а не тихое `Infinity`/`0.0`.

```java
double big   = 1e309;    // ошибка компиляции: floating point number too large (→ Infinity)
double small = 1e-999;   // ошибка компиляции: floating point number too small (→ 0.0)
double sub   = 4.9e-324; // ок: наименьшее положительное double — субнормальное, но не ноль
double inf   = 1.0 / 0.0;               // так Infinity получить можно — это уже вычисление
double inf2  = Double.POSITIVE_INFINITY; // или через константу
```

Субнормальные (denormal) значения ошибкой не считаются: `4.9e-324` — наименьшее положительное `double`, оно ненулевое, поэтому допустимо. Границы диапазонов `float`/`double` и семантика IEEE 754 — Part I, Ch. 4.

## Common Mistakes

1. **`double`-литерал в переменной `float`.** `float r = 1.0;` → ошибка компиляции. Правильно: `float r = 1.0f;`.
2. **Hex-форма без `p`.** `double x = 0x1.0;` → ошибка. Правильно: `double x = 0x1.0p0;`.
3. **Подчёркивание рядом с точкой/экспонентой/суффиксом.** `1_.0`, `1_e3`, `1.0_f` — все ошибки. Правильно — только между цифрами.
4. **Путаница `l` (long) и `f`.** `float v = 5l;` — это `long` 5, а не `float`. Для `float` нужен `f`: `float v = 5f;`.
