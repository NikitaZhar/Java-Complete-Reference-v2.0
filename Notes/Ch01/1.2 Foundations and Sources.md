Справочник построен на пяти источниках, которые используются вместе. Ни одна тема не выводится из одного источника «по умолчанию»: задача — собрать наиболее полную и точную картину, а не пересказать какой-то один документ.

## The Five Sources

Нормативную основу дают две спецификации Oracle для Java SE 25: *The Java Language Specification* (JLS) — правила самого языка, и *The Java Virtual Machine Specification* (JVMS) — формат class-файла, байткод и исполнение. Практический и учебный слой дают документация Oracle (Java SE API и руководства по инструментам JDK) и две пары экзаменационных руководств: Boyarsky, *OCP Java SE 17/21 Developer* (1Z0-829, 1Z0-830), и Mughal, *OCP Java SE 17/21 Developer* (1Z0-829, 1Z0-830).

## How the Sources Combine

Роли источников распределены не по частям книги, а по типу вклада. JLS и JVMS дают нормативную точность и границы понятий — то, где проходит грань между «корректно» и «ошибка компиляции». Книги Boyarsky и Mughal и документация Oracle дают то, чего в сухой спецификации мало: развёрнутые и более точные определения, объяснения «почему так сделано», продуманные примеры и разбор типичных ошибок и ловушек. Пропорция зависит от материала: организация спецификации и грамматики опираются в основном на JLS, а типы, классы или generics требуют активного привлечения книг. Подразделы «Типичные ошибки» и экзаменационные ловушки по всей книге питаются прежде всего от Boyarsky и Mughal.

## Normative External Standards

Помимо основных источников, язык и платформа опираются на внешние стандарты, к которым справочник обращается там, где это важно. Стандарт Unicode задаёт кодовые точки, классы символов и нормализацию — это основа лексики, идентификаторов и escape-последовательностей. IEEE 754 определяет поведение чисел с плавающей точкой (`float`, `double`): форматы, `NaN` и бесконечности, округление и точность. Отдельные формальные публикации по модели памяти Java (JMM) уточняют многопоточную семантику, на которую ссылается спецификация.
