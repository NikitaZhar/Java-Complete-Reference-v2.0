# 4.2.6 char

`char` — 16-битный **беззнаковый** целочисленный тип, диапазон 0…65 535. Формально он часть целочисленного семейства (общая механика — [[4.2.1 Integral Types]]), но по назначению текстовый: хранит код символа. Эта двойственность — число и символ одновременно — и есть главное, что нужно про `char` понять, вместе с неприятной правдой: один `char` — не всегда целый символ.

## A number and a character at once

`char` — единственный беззнаковый целочисленный тип в Java, и с ним можно делать арифметику: он свободно продвигается к `int` (см. [[4.2.1 Integral Types]]), поэтому `'A' + 1` — это `66` типа `int`, а не `'B'`.

```java
char a = 'A';
int code = a;            // 65 — неявное расширение char → int
char next = (char) (a + 1); // 'B' — обратно в char нужно приведение (результат a+1 имеет тип int)
System.out.println('9' - '0'); // 9 — классический приём: из цифры-символа в число
```

Литерал `char` записывается в одинарных кавычках и всегда содержит ровно одну кодовую единицу: `'A'`, escape `'\n'`, Unicode-escape `'A'`. Значение по умолчанию — `'\u0000'` (NUL), а не пробел ([[4.2.14 Default Values and Initialization]]). Формы литералов и escape — тема Ch. 3.10, здесь не повторяются.

Из «числовой» природы следует и то, что `char` можно использовать в `switch`, сравнивать (`<`, `>`) и складывать — но сравнение идёт по коду UTF-16, а не по «алфавиту», и для настоящей обработки текста (регистр, локали, сортировка) этого недостаточно.

## One char is a UTF-16 code unit, not a code point

Вот ключевое противоречие. `char` хранит **кодовую единицу UTF-16** (code unit), а не символ целиком. Символы из основного диапазона Unicode (U+0000…U+FFFF) укладываются в один `char`, но дополнительные (supplementary, U+10000 и выше — многие эмодзи, редкие иероглифы, часть исторических письменностей) кодируются **двумя** `char` — суррогатной парой. Понятия кодовой точки (code point) и кодовой единицы (code unit) — дом Ch. 3.1; здесь важно практическое следствие: тип `char` физически не способен вместить такой символ.

```java
String s = "🙂";                 // один воспринимаемый символ
System.out.println(s.length());        // 2 — это две char-единицы (суррогатная пара)
System.out.println(s.charAt(0));       // «половина» символа — сам по себе бессмыслен
System.out.println(s.codePointCount(0, s.length())); // 1 — реальных символов один
```

Поэтому «перебрать строку по `char`» безопасно только для текста из основного диапазона; для произвольного Unicode перебирают по кодовым точкам (`codePoints()`, `codePointAt`). Полностью работа с кодировками и текстом — главы строк и I/O (Ch. 3.1, Ch. 54); сюда вынесено лишь то, что определяет сам тип `char`.

Обёртка — `Character` (утилиты `isDigit`, `toUpperCase`, `isLetter` и т. д.); переход примитив↔обёртка — [[4.2.13 Boxing and Unboxing]].

## Common Mistakes

- Считать, что `String.length()` и перебор по `char` дают число символов.

```java
String emoji = "👍";
if (emoji.length() == 1) { }   // false: length() == 2, символ занял суррогатную пару
```
  Правильно: для количества символов и перебора произвольного текста — `codePointCount` / `codePoints()`.

- Ожидать, что `char` со значением по умолчанию — пробел.

```java
char c;               // поле: по умолчанию '\u0000' (NUL), печатается как невидимый символ
```
  Правильно: инициализировать явно; не путать `'\u0000'` с `' '` (пробел, код 32).

- Смешивать `'A'` (char, код 65) и `"A"` (String) — например, `'A' + 'B'` даёт `131` (int), а не `"AB"`. Правильно: для конкатенации использовать строки, для кодов — помнить про продвижение к `int`.
