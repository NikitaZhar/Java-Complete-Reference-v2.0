Обе грамматики Java записаны в одной нотации, и умение её читать — это умение находить точное правило в спецификации и понимать, что именно разрешено. Нотация компактна: несколько метасимволов задают выбор, необязательность и повторение. Здесь разбирается сам аппарат; конкретные правила лексики и синтаксиса — в 2.2 и 2.3.

## Terminals and Nonterminals

Грамматика оперирует двумя видами символов. Терминалы — это готовые токены, дальше не разбираемые: ключевые слова, операторы, разделители, литералы. В JLS они записаны моноширинным начертанием: `if`, `(`, `;`. Нетерминалы — абстрактные категории, которые раскрываются через другие символы; они записаны курсивом: *Expression*, *Statement*, *Block*. Вывод программы — это последовательная замена нетерминалов их определениями, пока не останутся одни терминалы.

## Productions and the Goal Symbol

Правило (продукция) связывает нетерминал слева с последовательностью символов справа:

```
IfThenStatement:
    if ( Expression ) Statement
```

Java описывается контекстно-свободной грамматикой (context-free grammar): слева в каждой продукции стоит ровно один нетерминал, поэтому раскрытие не зависит от окружения. Разбор всегда стартует с выделенного нетерминала — целевого символа (goal symbol). У лексической грамматики это `Input`, у синтаксической — `CompilationUnit`. Программа корректна по форме, если из целевого символа применением правил можно получить именно её токены.

## Notation Metasymbols

Правые части используют небольшой набор метасимволов. Квадратные скобки `[x]` означают необязательный элемент. Фигурные скобки `{x}` — повторение ноль или более раз. Конструкция «(one of)» вводит список взаимоисключающих альтернатив на одной строке. Оговорка «but not …» исключает частные случаи из более широкого правила (так, например, идентификатор определяется как имя, «но не» ключевое слово). В печатной версии JLS вместо `[x]` часто используется нижний индекс *opt* у необязательного нетерминала — это то же самое.

Важно не путать эти метасимволы с синтаксисом самого Java: `[ ]` в грамматике — это «необязательно», а не индексация массива; `|` между альтернативами — это «или», а не побитовая операция.

## Reading a Rule

Необязательный элемент. Правило `break`:

```
BreakStatement:
    break [Identifier] ;
```

Разрешает обе формы — с меткой и без:

```java
break;
break outerLoop;
```

Повторение. Список аргументов:

```
ArgumentList:
    Expression { , Expression }
```

Один или больше элементов через запятую: `f(x)`, `f(x, y)`, `f(x, y, z)`.

Композиция. Базовый `for` сочетает необязательные части:

```
BasicForStatement:
    for ( [ForInit] ; [Expression] ; [ForUpdate] ) Statement
```

Отсюда законны и полный цикл, и вырожденные формы вплоть до `for (;;)`:

```java
for (int i = 0; i < n; i++) { ... }
for (; i < n; i++) { ... }
for (;;) { ... }
```

Ключевой навык чтения — различать «элемент необязателен» и «элемент подразумевается по умолчанию». Отсутствие необязательной части не означает подстановку какого-то значения: семантика отсутствия задаётся отдельно (например, у абстрактного метода тело отсутствует, и это не «пустое тело»). Разбор типичных ошибок чтения — в [[2.5 Common Mistakes]].
