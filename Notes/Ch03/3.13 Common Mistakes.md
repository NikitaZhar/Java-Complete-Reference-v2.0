Сводный блок характерных ошибок уровня лексики — тех, что возникают до всякой семантики, при разборе исходника на токены. Ошибки, привязанные к конкретным формам литералов (строчная `l`, ведущий ноль, подчёркивания), собраны в своих подразделах ([[3.10.1 Integer Literals]], [[3.10.5 String Literals]]); здесь — общие для всей главы. Формат: проблема → код → как правильно.

## Common Mistakes

1. **Unicode-escape срабатывает там, где не ждут.** `\u000A` внутри `//`-комментария разворачивается в перевод строки на шаге 1 и «оживляет» остаток строки как код.
   ```java
   // конец строки \u000A doSomethingDangerous();  // escape стал LF → вызов исполнится
   ```
   Правильно: для переводов строк в тексте использовать строковые escape `\n`, а не Unicode-escape ([[3.3 Unicode Escapes]]).

2. **Жадная склейка операторов (maximal munch).** Соседние символы без пробела собираются в самый длинный оператор.
   ```java
   int r = a--b;   // токены a, --, b → не компилируется как разность
   ```
   Правильно: разделять пробелом там, где нужен другой разбор — `a - -b` ([[3.2 Lexical Translations]]).

3. **Одиночное подчёркивание как имя.** С Java 9 `_` — ключевое слово.
   ```java
   int _ = 5;      // трактуется как неименованная переменная, а не имя '_'
   ```
   Правильно: дать переменной осмысленное имя или, если значение не нужно (Java 21+), сознательно использовать `_` как unnamed variable ([[3.9 Keywords]]).

4. **Контекстное ключевое слово как имя типа.** `var`, `record`, `sealed`, `permits`, `yield` нельзя использовать как имя класса/интерфейса.
   ```java
   class record {}   // ошибка компиляции: имя типа не может быть 'record'
   ```
   Правильно: переименовать тип; как имя обычной переменной эти слова допустимы ([[3.8 Identifiers]]).

5. **Попытка вложить комментарии.** Первый `*/` закрывает весь традиционный комментарий.
   ```java
   /* внешний /* внутренний */ дальше уже код */   // хвост ломает компиляцию
   ```
   Правильно: не вкладывать `/* */`; для временного отключения блока с комментариями внутри — построчные `//` ([[3.7 Comments]]).

6. **Пропущенный пробел склеивает ключевые слова и имена.** `staticvoid` — один идентификатор, а не `static void`.
   ```java
   staticvoid main(String[] a) {}   // 'staticvoid' — имя типа возвращаемого значения → ошибка
   ```
   Правильно: разделять токены пробелом — `static void` ([[3.5 Input Elements and Tokens]]).

7. **`true`, `false`, `null` как имена.** Это литералы, а не ключевые слова, но именами быть не могут.
   ```java
   boolean true = false;   // ошибка компиляции
   ```
   Правильно: выбрать другое имя ([[3.9 Keywords]]).

8. **`$` в рукописном коде.** Знак доллара допустим, но зарезервирован под сгенерированный код и внутренние имена.
   ```java
   int price$USD = 10;   // компилируется, но нарушает соглашения
   ```
   Правильно: не использовать `$` в обычных идентификаторах ([[3.8 Identifiers]]).
