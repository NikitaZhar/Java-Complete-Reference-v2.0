# 4.11 Where Types Are Used

Тип в Java появляется не только слева от имени переменной. Умение узнавать все позиции, где стоит тип, — часть навыка читать чужой код: одно и то же имя типа в разных местах играет разные роли. Раздел перечисляет эти позиции; правила, специфичные для generics-позиций (аргументы типов, границы, wildcards), — Ch. 20.

## The positions where a type appears

Типы встречаются в объявлениях переменных, полей и параметров, в типе возвращаемого значения метода; в создании объектов (`new String(...)`) и массивов (`new int[10]`); в приведениях (`(String) o`) и проверках `instanceof`; как аргументы типов (`List<String>`) и границы типовых переменных (`<T extends Number>`); в `extends`/`implements`; как тип элемента массива; и, начиная с механизма аннотаций типов, в аннотированных позициях самого типа (`@NonNull String`).

```java
class Box<T extends Number> {          // граница типовой переменной
    private T value;                   // тип поля
    Box(T value) { this.value = value; } // тип параметра
    List<T> asList() {                 // тип возврата + аргумент типа
        return List.of(value);
    }
}

Object o = new Box<>(3);               // создание объекта
if (o instanceof Box<?> b) { }         // проверка типа (wildcard)
String s = (String) "x";               // приведение
```

## Two practical notes

Не всякая «типо-подобная» запись — тип. `var` в объявлении локальной переменной **не тип**, а указание вывести тип из инициализатора; в позициях полей, параметров и возврата `var` недопустим. Полностью вывод типов — Ch. 20.

В части позиций тип обязан быть **ссылочным**: аргументы типов generics не принимают примитивы (`List<int>` невозможен — нужна обёртка), а `instanceof` и приведения к параметризованному типу ограничены реифицируемостью (см. [[4.4–4.9 Generic Types in the Type System]]).

## Common Mistakes

- Пытаться использовать `var` не как локальную переменную.

```java
var x = 10;              // ок: локальная переменная
// var field;            // compile-time error: var нельзя без инициализатора и не как поле
// void m(var p) { }     // compile-time error: не для параметров
```
  Правильно: `var` — только локальная переменная с инициализатором; в остальных позициях указывать тип явно.

- Ставить примитив в позицию аргумента типа.

```java
Map<int, String> m;      // compile-time error
```
  Правильно: обёртка — `Map<Integer, String>` (см. [[4.2.13 Boxing and Unboxing]]).
