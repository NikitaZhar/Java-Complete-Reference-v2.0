# 5.11 Casting Contexts

Контекст каста (casting context) — это оператор `(Type) expression`. Он самый широкий из всех: разрешает не только всё, что делают присваивание и вызов, но и то, чего те не делают неявно, — **сужения примитивов и сужения ссылок**. Каст — это способ сказать компилятору «я беру ответственность за это преобразование». Но широта не означает вседозволенность: между несовместимыми типами каст запрещён на этапе компиляции, а сужение ссылок компилятор пропускает лишь под проверку во время выполнения. Раздел разграничивает три исхода каста: разрешён неявно и без риска, разрешён явно но проверяется в runtime, запрещён компилятором.

## Casting is the widest context

Всё, что доступно в присваивании и вызове (тождество, расширение примитива, упаковка/распаковка, расширение ссылки), доступно и в касте. Сверх того каст добавляет два сужающих рода.

```java
long l = 10L;
int i = (int) l;                // narrowing primitive — только каст
double d = 9.99;
int t = (int) d;                // narrowing primitive: → 9 (к нулю)

Object o = "text";
String s = (String) o;          // narrowing reference — только каст, проверка в runtime

Integer boxed = (Integer) 5;    // boxing тоже допустим (обычно избыточен)
int back = (int) boxed;         // unboxing
```

Часто каст стоит не ради самого преобразования, а чтобы направить арифметику или разрешение перегрузки; в примере `(double) total / count` каст меняет тип операнда до деления (см. [[5.2 Identity and Widening Primitive Conversion]]).

## Three outcomes of a cast

Каст примитивов **никогда** не бросает исключение: результат может быть испорчен переполнением или усечением (см. [[5.3 Narrowing Primitive Conversion]]), но выполнение продолжится. Каст ссылок вниз по иерархии **проверяется в runtime**: если фактический класс объекта не совместим с целевым типом — `ClassCastException`. Каст между заведомо несовместимыми типами компилятор **отвергает сразу**.

```java
// 1) Примитивное сужение: без исключения, с возможной потерей
int x = (int) 3_000_000_000L;   // молча → -1294967296

// 2) Ссылочное сужение: проверка в runtime
Object o = Integer.valueOf(7);
String bad = (String) o;        // компилируется; в runtime ClassCastException

// 3) Несовместимые типы: ошибка компиляции
String s = "x";
Integer n = (Integer) s;        // DOES NOT COMPILE: inconvertible types
```

Разница между (1) и (2) существенна для отладки: испорченный примитив не выдаёт себя ничем, а неверный downcast честно падает с `ClassCastException`, называя классы.

## What casting still cannot do

Каст не соединяет принципиально несовместимые миры. Нельзя кастовать `boolean` в число и обратно; нельзя кастовать примитив в несвязанный ссылочный тип (кроме упаковки) и наоборот; нельзя кастовать между несвязанными классами. Литерал `null` при этом кастуется к любому ссылочному типу и downcast с `null` не бросает исключения — проверять нечего.

```java
boolean flag = true;
int n = (int) flag;             // DOES NOT COMPILE: boolean и int несовместимы

Object o = null;
String s = (String) o;          // ок: null → любой ссылочный тип, без CCE
```

## Common Mistakes

- Использовать каст примитива как «безопасное укорачивание», не думая о переполнении.

```java
int millis = (int) System.currentTimeMillis(); // молча переполнится — значение уже > Integer.MAX_VALUE
```
  Правильно: `Math.toIntExact(...)` — бросит `ArithmeticException` вместо тихой порчи.

- Делать downcast без проверки, полагаясь на «здесь точно нужный тип».

```java
Object o = queue.poll();
Message m = (Message) o;        // ClassCastException, если в очереди оказалось иное
```
  Правильно: `if (o instanceof Message m) { … }` (см. [[5.5 Widening and Narrowing Reference Conversion]]).

- Пытаться кастом обойти несовместимость типов вместо преобразования значением.

```java
Object o = 42;
String s = (String) o;          // ClassCastException: Integer не String
```
  Правильно: `String s = String.valueOf(o);` или `o.toString()`.
