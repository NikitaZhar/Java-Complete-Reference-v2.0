# 4.2.0 Overview

Примитивных типов восемь. Числовые примитивы имеют заданные языком форматы и диапазоны, boolean — два значения без установленного языком размера хранения. Примитивное значение не является объектом и не может быть null. Таблица ниже — справка по значениям; физическая раскладка и работа GC относятся к реализации JVM. Этот раздел — точка входа в 4.2: сводная таблица и деление на группы; различие примитивных и ссылочных типов — [[4.1.3 High-Level Classification of Types]].

## The eight primitives at a glance

| Тип       | Формат значения   | Диапазон значений                         | По умолчанию | Обёртка     |
| --------- | ----------------- | ----------------------------------------- | ------------ | ----------- |
| `byte`    | 8 бит             | −128 … 127                                | `0`          | `Byte`      |
| `short`   | 16 бит            | −32 768 … 32 767                          | `0`          | `Short`     |
| `int`     | 32 бита           | −2³¹ … 2³¹−1                              | `0`          | `Integer`   |
| `long`    | 64 бита           | −2⁶³ … 2⁶³−1                              | `0L`         | `Long`      |
| `char`    | 16 бит            | 0 … 65 535 (U+0000 … U+FFFF), беззнаковый | `'\u0000'`   | `Character` |
| `float`   | 32 бита           | IEEE 754, ≈ ±3.4·10³⁸                     | `0.0f`       | `Float`     |
| `double`  | 64 бита           | IEEE 754, ≈ ±1.8·10³⁰⁸                    | `0.0`        | `Double`    |
| `boolean` | не специфицирован | `true` / `false`                          | `false`      | `Boolean`   |

Размер `boolean` спецификацией не задан и зависит от JVM — полагаться на «1 бит» или «1 байт» нельзя. Точные значения по умолчанию и когда они применяются (поля против локальных переменных) — [[4.2.14 Default Values and Initialization]].

## Why Java keeps primitives at all

Java — объектно-ориентированный язык, но примитивное значение не является объектом. Для самого значения отдельный объект-обёртка, его заголовок и ссылка не требуются; это делает примитивы удобным выбором для чисел и флагов, когда объектная форма не нужна. Однако примитивное поле или компонент массива могут быть частью объекта, управляемого GC. Объектные расходы и выгода от примитивов зависят от JVM: упаковка может использовать кэш, а JIT — устранить часть объектов. Регистры, стек, раскладка полей и машинные инструкции — детали реализации, а не обещание языка. Поэтому различать примитив и обёртку нужно прежде всего по семантике; фактическую стоимость конкретного кода проверяют на используемой JVM.

Платой за эту эффективность становятся ограничения, которые и порождают большинство ловушек 4.2: примитив нельзя сделать `null`, положить в generics, вызвать у него метод; он не участвует в полиморфизме. Отдельно стоит `boolean`: в отличие от C, он **не** число — не существует неявного превращения `true`/`false` в `1`/`0` и обратно, и `if (x)` требует именно булева выражения. Это намеренное сужение, убирающее целый класс ошибок вида `if (x = 0)`.

## Three groups

Целочисленные — `byte`, `short`, `int`, `long`, `char`: целые числа и символьные коды; общая механика (представление, переполнение, промоушены, сдвиги) собрана в [[4.2.1 Integral Types]]. С плавающей точкой — `float`, `double`: вещественные числа по IEEE 754, со своими ловушками (`NaN`, бесконечности, потеря точности) — [[4.2.7 Floating-Point Types]]. Логический — `boolean`: только `true`/`false`, без числовых преобразований — [[4.2.10 boolean]].

`char` формально целочисленный (беззнаковый 16-битный код), но по назначению текстовый; его двойственную природу разбирает [[4.2.6 char]], а понятия кодовой точки и кодовой единицы — Ch. 3.1.

## Primitive versus wrapper: when each

Примитив выбирают по умолчанию для вычислений, счётчиков, флагов — для самого примитивного значения отдельный объект не требуется. Обёртка (`Integer`, `Double`, …) нужна там, где требуется объект: элементы коллекций и generics, возможность `null` как «значение не задано». Механика перехода между ними — [[4.2.13 Boxing and Unboxing]].

Практическое следствие: обёртка в цикле вызывает повторные распаковку и упаковку. Упаковка может использовать кэш, а JIT — устранить часть аллокаций; число новых объектов не гарантируется. В этом примере также переполняется int.

```java
Integer sum = 0;
for (int i = 0; i < 1_000_000; i++) {
    sum += i; // unbox → сложение int → box; новый объект не гарантирован
}
```

Чтобы получить математическую сумму 499999500000 без переполнения int, считайте в long. Это также устраняет повторную упаковку; изменение типа здесь исправляет две разные проблемы.

```java
long sum = 0;                    // примитив: без аллокаций
for (int i = 0; i < 1_000_000; i++) {
    sum += i;
}
```

Ещё одно следствие «не-объектности» примитива — его нельзя положить в generics напрямую и у него нет методов:

```java
List<int> xs;        // compile-time error: только ссылочные типы
int x = 5;
x.hashCode();        // compile-time error: у примитива нет методов
```
