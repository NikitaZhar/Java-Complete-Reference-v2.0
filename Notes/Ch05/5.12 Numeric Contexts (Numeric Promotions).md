# 5.12 Numeric Contexts (Numeric Promotions)

Числовой контекст (numeric context) возникает у операндов операторов, работающих с числами: арифметических `+ - * / %`, сравнения `< <= > >=`, числового равенства `== !=`, условного `? :`, сдвигов, унарных `+`/`-`. Операторы допускают только операнды определённых типов, поэтому к операндам применяется **числовое продвижение (numeric promotion)** — набор преобразований, приводящий их к общему подходящему типу. Продвижение бывает **унарным** (один операнд) и **бинарным** (два). Разрешённые здесь роды — распаковка и расширение примитива; упаковки в числовом контексте нет. Понимание этого раздела снимает почти все «почему `byte + byte` вдруг `int`» и «почему результат не того типа, что операнды».

## Unary numeric promotion

Применяется к единственному операнду — например, к операнду унарного `+`/`-`, к выражению размерности массива `new int[expr]`, к индексу `arr[expr]`. Правило: если операнд — обёртка (`Byte`, `Short`, `Character`, `Integer`, `Long`, `Float`, `Double`), он сначала распаковывается; затем, если тип **уже** `int` — ничего не меняется, а если он `byte`, `short` или `char`, то **расширяется до `int`**. Типы `long`, `float`, `double` остаются собой. Короче: результат унарного продвижения — всегда `int` или шире.

```java
byte b = 10;
var x = -b;             // унарное продвижение: byte → int, тип x — int
System.out.println(((Object) x).getClass().getSimpleName()); // Integer (int → Integer при boxing в Object)

char c = 'A';
var y = +c;             // char → int: y == 65, тип int

Integer boxed = 7;
var z = -boxed;         // распаковка Integer→int, затем как int: тип int
```

Именно поэтому индекс и размер массива, заданные `char` или `byte`, работают — они продвигаются до `int`, который и требуется.

## Binary numeric promotion

Применяется, когда у оператора два числовых операнда. Сначала каждый при необходимости распаковывается. Затем выбирается **самый широкий** из двух типов, но не уже `int`, и **оба** операнда приводятся к нему: если один операнд `double` — оба к `double`; иначе если один `float` — оба к `float`; иначе если один `long` — оба к `long`; иначе — **оба к `int`** (даже если оба были `byte`/`short`/`char`). Результат оператора имеет этот общий тип.

```java
int i = 1;
long l = 33;
var a = i * l;          // бинарное: int→long, оба long; тип a — long

short s1 = 10, s2 = 3;
var b = s1 * s2;        // оба short → оба int; тип b — int (не short!)

byte b1 = 100, b2 = 100;
int sum = b1 + b2;      // оба byte → int; 200 помещается в int без переполнения

double d = 2.0;
var c = i + d;          // int→double; тип double
```

Третье правило — источник самого частого сюрприза: `byte + byte` даёт `int`, поэтому результат нельзя сразу присвоить обратно в `byte` без каста. Унарные `++`/`--` из этого правила исключены — `b++` над `byte` остаётся `byte`.

## Promotion meets assignment: the classic non-compile

Числовое продвижение объясняет, почему арифметика над узкими типами не присваивается обратно без каста: оператор вернул `int`, а цель уже, — и это сужение переменной, запрещённое в присваивании ([[5.9 Assignment Contexts]]).

```java
short m = 10, n = 3;
short prod = m * n;     // DOES NOT COMPILE: m*n имеет тип int, присвоение int→short — сужение
short ok = (short)(m * n); // ок: явный каст результата
```

Отдельная тонкость — `char` в конкатенации против `char` в арифметике: `"" + 'A'` даёт `"A"` (строковое преобразование), а `0 + 'A'` даёт `65` (бинарное продвижение). Контекст решает всё.

## Shifts and casts: two things not to over-generalize

Сдвиги `<< >> >>>` — тоже числовой контекст, но **не бинарное** продвижение: их операнды продвигаются **раздельно и унарно**, а тип результата равен типу **левого** операнда. Поэтому `long`-счётчик справа не расширяет сдвигаемое значение слева.

```java
long a = 1L << 2;       // тип long — по левому операнду
int  b = 1 << 33L;      // тип int: левый операнд int; правый (long) продвигается сам по себе,
                        // сдвиг идёт на 33 & 31 = 1 → результат 2
```

Каст же **унарен** — он цепляется к ближайшему операнду, а не ко всему выражению; после него бинарный оператор снова продвигает результат до `int`.

```java
short m = 10, n = 3;
short bad = (short) m * n;   // DOES NOT COMPILE: каст только к m, дальше m*n снова int
short ok  = (short)(m * n);  // ок: скобки делают каст к результату
```

## Common Mistakes

- Ждать, что результат `byte`/`short`-арифметики останется узким.

```java
byte a = 10, b = 20;
byte c = a + b;         // DOES NOT COMPILE: a+b имеет тип int
```
  Правильно: `byte c = (byte)(a + b);` — с пониманием возможного переполнения при больших значениях.

- Смешивать обёртку и `null` в числовом операторе.

```java
Integer x = null;
int y = x + 1;          // NullPointerException: распаковка null в числовом контексте
```
  Правильно: проверить на `null` перед арифметикой (см. [[5.4 Boxing and Unboxing Conversion]]).

- Забывать, что деление двух целых — целочисленное, и продвижение до `double` происходит уже после.

```java
double half = 1 / 2;    // 0.0: 1/2 в int = 0, потом widening
```
  Правильно: `1.0 / 2` — сделать операнд `double` до деления (см. [[5.2 Identity and Widening Primitive Conversion]]).
