# 4.2.2 byte

`byte` — 8-битный знаковый целочисленный тип, диапазон −128…127. На практике его почти никогда не используют как «маленькое число» для арифметики; его настоящая роль — единица хранения сырых двоичных данных: содержимое файлов, сетевых пакетов, буферов, результатов шифрования — всё это в Java `byte[]`. Общая целочисленная механика (дополнительный код, продвижение, сдвиги) — в [[4.2.1 Integral Types]]; здесь — что специфично для `byte` и почему он источник характерных ловушек.

## Why byte is signed, and why that hurts

В двоичных форматах байт часто интерпретируют как 0…255. В Java byte — знаковый; unsigned-вариантов byte, short, int и long нет, хотя char является беззнаковым целочисленным типом. Литерал 0xFF имеет тип int и значение 255; после (byte) 0xFF получаем -1.

```java
byte b = (byte) 0xFF;   // нужно приведение: 0xFF (=255) не влезает в byte как есть
System.out.println(b);          // -1
System.out.println(b & 0xFF);   // 255 — маска восстанавливает беззнаковое прочтение
```

Механизм тот же, что и в [[4.2.1 Integral Types]]: перед `&` `byte` продвигается к `int` (знаково — из `-1` получается `0xFFFFFFFF`), а `& 0xFF` отсекает младшие 8 бит обратно к 255. Читаемее — стандартный метод:

```java
int unsigned = Byte.toUnsignedInt(b); // 255
```

Это и есть главный практический смысл `byte`: помнить, что «байт как число» в Java знаковый, и при беззнаковой интерпретации явно применять маску или `Byte.toUnsigned*`.

## Assignment needs a cast more often than you expect

Поскольку целочисленные литералы имеют тип `int`, присваивание `byte` вне диапазона −128…127 требует явного сужения, и оно молча срезает старшие биты:

```java
byte ok = 100;          // ок: влезает
byte over = (byte) 200; // 200 не влезает; результат -56 (биты 1100 1000)
// byte bad = 200;      // compile-time error: incompatible types, possible lossy conversion
```

Значение по умолчанию `byte`-поля — `0` (правила и разница с локальными переменными — [[4.2.14 Default Values and Initialization]]).

## Where byte actually appears

Двоичные данные часто хранят в `byte[]`. `InputStream.read()` возвращает `int: 0…255` для прочитанного байта и -1 для конца потока; `read(byte[])` записывает данные в массив знаковых `byte`. `ByteBuffer` работает с байтовыми буферами. Полная механика потоков, буферов и кодировок — главы I/O и текста; здесь важно различать знаковый элемент `byte[]` и результат чтения одного байта.

Обёртка `byte` — `Byte`; переход примитив↔обёртка и кэш — [[4.2.13 Boxing and Unboxing]].

## Common Mistakes

- Ожидать, что `byte` беззнаковый (0…255).

```java
byte b = (byte) 0xFF;
if (b == 255) { /* никогда */ }   // b == -1; сравнение с 255 всегда false
```
  Правильно: сравнивать беззнаковое прочтение — `(b & 0xFF) == 255` или `Byte.toUnsignedInt(b)`.

- Ждать, что сужение к `byte` предупредит о потере данных в runtime.

```java
byte hash = (byte) largeInt;   // молча берёт младшие 8 бит
```
  Правильно: сужать осознанно, только когда старшие биты действительно не нужны; иначе держать значение в `int`/`long`.
