# 4.1.2 Definition of Value

Если тип задаёт форму, то значение — конкретное её проявление во время выполнения. Значение всегда принадлежит ровно одному типу: «просто 5» в Java не бывает — есть «5 типа `int`». Каждое выражение при вычислении либо даёт значение своего типа, либо завершается исключением; промежуточного «ничего» без исключения не существует.

Почему это жёсткое правило «у каждого значения ровно один тип» так важно? Именно оно делает возможной статическую проверку типов: компилятор приписывает тип каждому подвыражению и, ещё не запуская программу, знает, какие операции над результатом допустимы. Если бы значение могло существовать «без типа» или менять тип по ходу вычисления, статических гарантий из [[4.1.1 Definition of Type]] не было бы вовсе. Обратная сторона правила — то, что число `5` в исходном коде это не «абстрактная пятёрка», а значение конкретного типа, и тип этот выбирается по контексту: `5` — `int`, `5L` — `long`, `5.0` — `double`; от выбора зависит и диапазон, и поведение операций.

## Categories of values

Все значения относятся к одной из категорий: **примитивные** (`42`, `3.14`, `true`, `'A'` — хранятся непосредственно), **ссылочные** (ссылка на объект в куче), особое значение **`null`** (ссылочное значение, означающее отсутствие объекта) и **литералы класса** (`String.class`, `int.class` — значения типа `Class`, представляющие сам тип как объект-метаданные).

```java
int prim = 42;               // примитивное значение
String ref = "hi";           // ссылочное значение: ссылка на объект String
String none = null;          // значение null: ссылки на объект нет
Class<String> meta = String.class; // литерал класса — значение типа Class<String>
```

`null` стоит особняком и заслуживает того, чтобы противоречие в нём назвать вслух: это **значение, которое означает отсутствие значения**. Переменная им «занята» (она не «пустая», в ней лежит вполне определённый маркер), но указывает этот маркер в никуда — объекта за ним нет. Отсюда и `NullPointerException` при попытке обратиться к члену: разыменовывать нечего. Тонкость на будущее — у `null` собственный служебный «null-тип», подтип всех ссылочных типов, поэтому `null` присваивается любой ссылочной переменной, но ни одной примитивной (см. [[4.3 Reference Types and Values]]).

## Every expression has a type and a value

У каждого выражения есть тип (определён на компиляции) и значение (появляется при вычислении). Если вычисление прерывается исключением, значение не создаётся, и управление уходит по механизму исключений.

```java
int x = 5 + 3;          // выражение 5 + 3: тип int, значение 8
String s = "a" + "b";   // тип String, значение "ab"

int bad = 10 / 0;       // значение не создаётся: ArithmeticException (/ by zero)
```

## Primitive values versus reference values

Практическая разница между двумя родами значений сводится к таблице:

| Свойство | Примитивное значение | Ссылочное значение |
|---|---|---|
| Что хранит переменная | само значение | ссылку на объект в куче (или `null`) |
| Допускает `null` | нет | да |
| Копирование при присваивании/передаче | копируется значение | копируется ссылка, объект общий |
| Участие в generics | нет (только через обёртки) | да |

Следствие для копирования разбирается в [[4.1.7 Runtime Representation of Values]]: две ссылки могут указывать на один объект, и тогда изменение объекта видно через обе.

## Common Mistakes

- Считать `null` «пустым объектом», у которого можно что-то вызвать.

```java
String s = null;
int len = s.length();   // NullPointerException
```
  Правильно: проверять на `null` или проектировать так, чтобы вместо `null` возвращался, например, пустой объект (`Optional`, пустая коллекция).

- Ожидать, что при исключении переменной присвоится «частичное» значение.

```java
int[] a = new int[2];
int v = a[5];           // ArrayIndexOutOfBoundsException; v не получает значения
```
  Правильно: помнить, что прерванное исключением выражение значения не даёт вовсе.
