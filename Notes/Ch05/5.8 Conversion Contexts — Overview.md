# 5.8 Conversion Contexts — Overview

Роды преобразований из Part A сами по себе не отвечают на вопрос «скомпилируется ли этот код» — ответ даёт **контекст**: синтаксическое место, где стоит выражение. Каждый контекст разрешает применять неявно **своё подмножество** родов, и подмножества эти разные: каст — почти всё, присваивание — меньше, вызов метода — ещё меньше. Этот раздел сводит контексты в одну карту, чтобы дальше (5.9–5.14) разбирать каждый предметно.

## The contexts of Java SE 25

JLS SE 25 различает **шесть крупных семейств** контекстов; если strict и loose invocation считать раздельно, видов **семь**:

- **Assignment** — правая часть `=`, инициализатор поля/переменной, `return`, элемент инициализатора массива, значение по умолчанию элемента аннотации.
- **Invocation** — каждый аргумент приводится к типу параметра; существует в двух режимах: **strict** (фаза 1, без упаковки) и **loose** (фаза 2, с упаковкой/распаковкой).
- **String** — операнд бинарного `+`, когда второй операнд — `String`.
- **Casting** — оператор `(Type)` применяет преобразование явно.
- **Numeric** — операнды арифметики/сравнений/сдвигов, индексы и размерности массива, а также result-выражения условного `?:` и `switch` (numeric choice context).
- **Testing** — тип в паттерне `instanceof` и в pattern `switch` (появился для pattern matching).

Фраза «пять контекстов» для SE 25 неполна: в ней пропущен **Testing**, а strict и loose invocation не различены.

## Which kinds each context allows

Таблица показывает, какие роды контекст применяет **неявно**. Пустая клетка не значит «невозможно вообще» — часто это достижимо явным кастом (то есть в casting-контексте).

| Род \ Контекст | Assignment | Strict inv. | Loose inv. | String | Casting | Numeric | Testing |
|---|---|---|---|---|---|---|---|
| Identity | да | да | да | да | да | да | да |
| Widening primitive | да | да | да | — | да | да | — |
| Narrowing primitive | только конст. | — | — | — | да (явно) | конст. в choice¹ | — |
| Widening-and-narrowing (`byte`→`char`) | — | — | — | — | да (явно) | — | — |
| Widening reference | да | да | да | — | да | — | да |
| Narrowing reference | — | — | — | — | да (явно) | — | checked² |
| Boxing | да | — | да | — | да | — | — |
| Unboxing | да | — | да | — | да | да | — |
| String | — | — | — | да | — | — | — |
| Unchecked | да³ | — | да³ | — | да³ | — | — |

¹ В numeric **choice** context (`?:`, `switch`-выражение) допускается сужение **константного** `int` к `byte`/`short`/`char`; в arithmetic/array context — нет.
² Только **checked** narrowing reference; unchecked narrowing в testing-контексте не допускается (он «менее инклюзивен, чем casting»).
³ С unchecked-предупреждением, если результат — raw-тип.

## Reading the matrix

Четыре вывода читаются прямо из таблицы.

**Casting — самый широкий контекст:** только он разрешает сужения примитивов, `byte`→`char`, сужения ссылок и unchecked — всё явным кастом.

**Assignment щедрее invocation ровно в одном месте — сужение константного целочисленного выражения.** Это ключевое различие, и оно подтверждается компилятором:

```java
static void f(byte b) {}

byte ok = 100;          // assignment: narrowing КОНСТАНТЫ 100 → byte, ок без каста
// f(100);              // DOES NOT COMPILE: invocation не сужает даже константу, влезающую в byte
f((byte) 100);          // нужен явный каст
```

JLS прямо фиксирует: «ни strict, ни loose invocation не включают неявное сужение целочисленных констант, разрешённое в assignment» — чтобы не усложнять разрешение перегрузки.

**Numeric context распаковывает, но не упаковывает:** обёртки распаковываются, примитивы расширяются, но обратно в обёртки ничего не заворачивается — арифметика идёт над примитивами.

```java
Integer a = 5;
long sum = a + 1L;      // numeric: unboxing Integer→int, затем widening int→long; boxing нет
```

**Testing инклюзивнее assignment/loose, но уже casting:** он добавляет narrowing reference (которого нет в присваивании и вызове), но только **checked** — без unchecked и без примитивных сужений.

```java
Object o = "x";
boolean t = o instanceof String; // testing: narrowing reference (checked)
```

## How contexts compose conversions

Внутри одного контекста может примениться **цепочка** из нескольких родов, но по строго заданным шаблонам (из §5.2/5.3/5.5). Например: распаковка допускает последующее расширение примитива (`Integer`→`int`→`long`); упаковка — последующее расширение ссылки (`int`→`Integer`→`Object`); расширение ссылки — последующую распаковку (`Integer` через `Number`→`int`). Но «расширение примитива + упаковка» за один шаг запрещено во всех контекстах — отсюда невозможность `Long x = 8;` (`8` это `int`, а `int`→`Long` требует widening-then-boxing). Обратная асимметрия: сужение целочисленной **константы** с упаковкой (`Byte b = 12;`) в присваивании разрешено. Эти шаблоны и отличают контексты друг от друга; детально — в разделах ниже.

```java
Integer boxed = 5;
long widened = boxed;   // unboxing Integer→int, затем widening int→long
Object obj = 5;         // boxing int→Integer, затем widening Integer→Object
Byte b = 12;            // assignment: сужение константы + boxing
// Long x = 8;          // DOES NOT COMPILE: widening primitive + boxing не комбинируются
```

## Common Mistakes

- Переносить интуицию присваивания на вызов метода для константного сужения.

```java
void ship(short s) {}
short ok = 100;         // assignment: ок
// ship(100);           // DOES NOT COMPILE: invocation не сужает даже константу
```
  Правильно: `ship((short) 100)` — явный каст в вызове.

- Ждать, что числовой контекст вернёт обёртку.

```java
Integer a = 5, b = 7;
Integer c = a + b;      // a,b распакованы, сложены как int; УПАКОВКА происходит уже в assignment (Integer c = <int>)
```
  Понимать, где именно род применяется, — ключ к предсказуемости.

- Считать, что «пять контекстов» покрывают всё: для SE 25 есть ещё Testing, а invocation делится на strict и loose (см. [[5.10 Invocation Contexts]], [[5.14 Testing Contexts and Pattern Compatibility]]).
