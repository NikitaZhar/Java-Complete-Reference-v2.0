# 4.3 Reference Types and Values

Ссылочный тип — тип, значение которого есть **ссылка** на объект в куче либо `null`; всё, что в Java не примитив, — ссылочный тип. Этот раздел собирает каталог ссылочных типов и разбирает две вещи, которые в 4.1 были обещаны, но отложены сюда: устройство null-типа и различие тождества и равенства. Теория каждого конкретного рода (массивы, перечисления, записи, строки) живёт в своей главе — здесь на них указатели, а не пересказ. Как ссылочное значение физически представлено и почему передаётся по значению — [[4.1.7 Runtime Representation of Values]].

## The four kinds of reference types

Ссылочные типы бывают четырёх родов. **Классы** (`class`, в том числе абстрактные, вложенные, локальные, анонимные, а также `enum` и `record`) — носители состояния и поведения. **Интерфейсы** (`interface`, включая функциональные и `@interface`-аннотации) — контракты. **Массивы** — упорядоченные наборы элементов одного типа, сами являющиеся объектами. **Типовые переменные** (`T`, `E`) — параметры generics, существующие только на компиляции. Все они — подтипы `Object` (даже массивы), и значение любого из них может быть `null`.

```java
String s = "text";       // класс
Runnable r = () -> {};   // интерфейс (функциональный)
int[] a = {1, 2, 3};     // массив — тоже объект, подтип Object
Object o = a;            // ок: int[] <: Object
```

Механику подтипирования между ссылочными типами задаёт [[4.1.6 Subtypes and Supertypes]]; здесь важно, что перечисленные роды образуют единую иерархию с корнем `Object`.

## Objects live in the heap; the value is the reference

Значение ссылочного типа — не сам объект, а ссылка на него. Объект создаётся в куче (оператором `new`, литералом строки или массива, фабричным методом) и живёт, пока на него есть ссылки; переменная же хранит лишь «путь» к нему. Отсюда — возможность нескольких ссылок на один объект и передача по значению-копии-ссылки, подробно разобранные в [[4.1.7 Runtime Representation of Values]].

## The null type

`null` — единственное значение особого **null-типа**, у которого нет имени и который нельзя объявить. В иерархии он занимает нижнюю позицию: null-тип является подтипом всех ссылочных типов, поэтому `null` присваивается переменной любого ссылочного типа — и ни одной примитивной.

```java
String s = null;         // ок
Runnable r = null;       // ок
int[] a = null;          // ок: массив — ссылочный тип
int x = null;            // compile-time error: примитив не принимает null
```

`null` означает «ссылка ни на что». Любая попытка разыменовать его — вызвать метод, обратиться к полю, взять `length` массива — даёт `NullPointerException`, потому что объекта за ссылкой нет. С Java 14+ сообщения об NPE стали «подробными» (helpful NPE) и прямо называют, какая именно ссылка была `null`, — это заметно ускоряет отладку.

```java
String s = null;
int len = s.length();    // NullPointerException: Cannot invoke "String.length()" because "s" is null
```

## Identity versus equality

Для ссылочных значений различают **тождество** (это один и тот же объект?) и **равенство** (объекты равны по содержимому?). Оператор `==` сравнивает тождество ссылок, метод `equals` — содержимое (если класс его осмысленно переопределяет). Смешение этих двух — одна из самых частых ошибок, особенно со строками, из-за пула строковых литералов.

```java
String a = "hi";              // из пула литералов
String b = "hi";              // та же ссылка из пула
String c = new String("hi");  // явно новый объект
System.out.println(a == b);      // true  — одна ссылка (пул)
System.out.println(a == c);      // false — разные объекты
System.out.println(a.equals(c)); // true  — одинаковое содержимое
```

Практический вывод: содержимое ссылочных значений сравнивают через `equals`, а `==` оставляют проверке тождества и сравнению с `null`. Полный контракт `equals`/`hashCode` (симметричность, согласованность, связь с `hashCode`) и кэш обёрток — дом Ch. 49; здесь важно само различие уровней.

## The catalogue of reference types and their homes

Отдельные роды ссылочных типов раскрываются в своих главах, и дублировать их здесь незачем: массивы — Ch. 13; перечисления (`enum`) — Ch. 10; записи (`record`) — Ch. 12; интерфейсы, в том числе функциональные, — Ch. 9 и Ch. 15.6; строки (`String`, неизменяемость, пул) — главы строк; generics и типовые переменные — Ch. 20. Особый ссылочный тип `Class<T>` представляет сам тип как объект-метаданные: литерал класса `String.class` даёт объект `Class`, а `obj.getClass()` — фактический тип значения (см. [[4.1.5 Static vs Runtime Type]]). Наконец, `Void` — ссылочный тип-маркер, применяемый как аргумент типа там, где значение не нужно (`Callable<Void>`), в отличие от `void`, который вообще не тип.

## Common Mistakes

- Сравнивать строки (и другие объекты) через `==`.

```java
String input = new String("yes");
if (input == "yes") { }   // false: разные объекты
```
  Правильно: `input.equals("yes")` или, безопаснее от `null`, `"yes".equals(input)`.

- Разыменовать `null`.

```java
Map<String, String> m = new HashMap<>();
int n = m.get("k").length();   // get вернул null → NullPointerException
```
  Правильно: проверять `null` или `getOrDefault`; помогает helpful NPE-сообщение, называющее пустую ссылку.

- Путать `void` и `Void`: `void` нельзя использовать как аргумент типа. Правильно: там, где generic требует ссылочный тип, а значение не нужно, — `Void` (и возвращать `null`).
