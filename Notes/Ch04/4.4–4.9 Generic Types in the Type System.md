# 4.4–4.9 Generic Types in the Type System

Система типов Java включает целое семейство форм, связанных с обобщениями (generics): типовые переменные, параметризованные типы, стирание типов, реифицируемость, «сырые» типы и пересечения. В классификации типов они занимают своё место, и этот раздел даёт их короткие определения — чтобы, встретив `List<String>`, `T extends A & B` или «сырой» `List`, вы понимали, что это за род типа. Полная теория обобщений (объявления, wildcards, вывод типов, ограничения, мосты) — единая большая тема и её дом Ch. 20; здесь только карта понятий, без пересказа.

## The six forms in one pass

**Типовая переменная** (type variable) — параметр-заполнитель в объявлении обобщённого класса или метода (`class Box<T>`, `<E> void add(E e)`). Существует только на компиляции: во время выполнения `T` неизвестен.

**Параметризованный тип** (parameterized type) — применение обобщённого типа к аргументам: `List<String>`, `Map<Integer, User>`. Именно с ними работают в коде чаще всего.

**Стирание типов** (type erasure) — механизм, которым компилятор удаляет параметры типов, приводя обобщённый тип к «сырой» форме в байткоде. Поэтому `List<String>` и `List<Integer>` в runtime — один и тот же класс `List`.

**Реифицируемый тип** (reifiable type) — тип, информация о котором полностью доступна в runtime: необобщённые классы, безграничный wildcard `List<?>`, массивы примитивов, `String[]`. Параметризованные типы вроде `List<String>` — **не** реифицируемы (их аргумент стёрт), и это ограничивает `instanceof` и создание массивов.

**«Сырой» тип** (raw type) — имя обобщённого типа без аргументов: `List` вместо `List<String>`. Оставлен ради совместимости с дообобщённым кодом; его использование небезопасно и вызывает unchecked-предупреждения.

**Пересечённый тип** (intersection type) — тип, удовлетворяющий сразу нескольким границам: в `<T extends Comparable<T> & Serializable>` ограничение `T` есть пересечение `Comparable<T> & Serializable`.

## Why the theory lives in Ch. 20

Разносить эти понятия по отдельным подразделам здесь было бы дублированием: они не автономны, а грани одной системы — обобщений, — где определения переплетены с wildcards, выводом типов и правилами вариантности. Поэтому в Ch. 4 они лишь названы как рода типов, а разбираются вместе в Ch. 20.

Практический след, который эти формы оставляют уже на уровне типов и значений, — стирание. Из него следуют два ограничения, о которые спотыкаются постоянно:

```java
List<String> list = new ArrayList<>();
System.out.println(list.getClass());     // class java.util.ArrayList — без <String>
// if (list instanceof List<String>) — compile-time error: недопустимая проверка
// T[] arr = new T[10];                 — compile-time error: тип T не реифицируем
```
Почему так — потому что аргумента типа в runtime уже нет; подробности и обходные приёмы (`List<?>`, `Class<T>`-токены, `@SafeVarargs`) — Ch. 20.

## Common Mistakes

- Ждать, что тип элемента generic доступен во время выполнения.

```java
if (obj instanceof List<String> l) { }   // compile-time error
```
  Правильно: проверять `instanceof List<?>`; сам тип элемента в runtime недоступен (стирание) — см. Ch. 20.

- Использовать «сырой» тип, теряя проверки.

```java
List raw = new ArrayList();
raw.add(1); raw.add("x");     // компилируется, но ломает типобезопасность
```
  Правильно: всегда указывать аргументы типа (`List<Integer>`); raw-типы — только при вынужденной совместимости со старым кодом.
