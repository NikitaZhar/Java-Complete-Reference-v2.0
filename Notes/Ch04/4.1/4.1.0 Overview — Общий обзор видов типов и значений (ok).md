## 4.1.0.1 Ключевые принципы системы типов Java
Java является **строго типизированным** (`strongly typed`) и **статически типизированным** (`statically typed`) языком.

- Каждый элемент программы (переменная, выражение, параметр, поле, результат метода) **обязан иметь тип**, известный на этапе компиляции.
- Каждое выражение имеет `compile-time type`, а его вычисление либо приводит к значению, совместимому с этим типом, либо завершается выбрасыванием исключения.
- Тип определяет:
    - множество допустимых значений;
    - набор операций, разрешённых для этих значений;
    - совместимость с другими типами;
    - гарантии поведения на этапе компиляции и выполнения.

> **Тип** — это формальная абстракция.  
> **Значение** — это конкретная сущность, существующая во время выполнения программы.

**Номинальная типизация.** Совместимость типов в Java определяется **декларациями** `extends` / `implements` (номинальная система типов), а не совпадением формы (набора членов). 

Язык не поддерживает `union-типы` общего назначения на уровне синтаксиса; для моделирования альтернатив обычно используют иерархии классов и интерфейсов (в том числе `sealed`).
См. [[4.1.6 Subtypes and Supertypes]] и последующие разделы о ссылочных типах.

## 4.1.0.2 Цели и гарантии системы типов Java
Система типов Java предназначена для обеспечения:
- **Безопасности типов (type safety):** предотвращение использования значений в несовместимом контексте.
- **Предсказуемости выполнения:** большинство ошибок типов выявляется на этапе компиляции, до запуска программы.
- **Совместимости и расширяемости:** наследование и интерфейсы обеспечивают безопасную подстановку (принцип Лисков).
- **Оптимизации времени выполнения:** примитивные типы имеют фиксированные представления, а обобщения стираются до базовых типов (`type erasure`).

> Типовая система Java — это баланс между строгой статической безопасностью и практической гибкостью.  
> Она допускает контролируемые преобразования (`casts`), сохраняя гарантии корректности через верификацию байткода.

## 4.1.0.3 Взаимосвязь типа и значения
- Тип задаёт допустимую форму и поведение данных.
- Значение является экземпляром (представителем) множества, определяемого типом.
- Тип может существовать независимо от значения (например, тип `int` существует, даже если переменная не инициализирована).
- Значение не может существовать без типа (нельзя иметь «просто 42»; в Java это всегда «42 типа `int`»).

> На уровне байткода каждый тип имеет фиксированное представление и сигнатуру, что обеспечивает однозначность при загрузке и проверке классов JVM.

## 4.1.0.4 Формальная структура системы типов (согласно JLS)
Согласно _Java Language Specification_, система типов Java включает несколько уровней:

|Уровень|Категория типов|Примеры|Ключевые главы|
|---|---|---|---|
|**Базовый**|Примитивные типы|`int`, `boolean`, `char`, `double`|4.2|
|**Объектный**|Ссылочные типы|классы, интерфейсы, массивы|4.3|
|**Обобщённый**|Параметризованные типы, wildcard-типы|`List<String>`, `T extends Number`|4.4, 4.5|
|**Выведенные**|Intersection, capture, inferred types|типы, выведенные из контекста|18.4|
|**Специальные**|`null`, `var`, `record`, `sealed`|служебные и структурные типы|4.12, 12, 8.5|

> На практике большинство программ работает с комбинацией объектных и обобщённых типов.  
> Обобщения и wildcards создают _расширенное множество типов_, известное как _parameterized type space_, которое существует только во время компиляции.

## 4.1.0.5 Высокоуровневая классификация
В Java различаются два основных рода типов:

|Категория типов|Характеристика|Определены в|Примеры|
|---|---|---|---|
|**Примитивные (Primitive Types)**|Представляют непосредственные значения|Раздел 4.2|`int`, `double`, `boolean`|
|**Ссылочные (Reference Types)**|Представляют ссылки на объекты или `null`|Раздел 4.3|классы, интерфейсы, массивы, обобщённые переменные типов|

> Все сложные структуры данных (включая строки, массивы, записи `record`, перечисления `enum` и типы обобщений) относятся к ссылочным типам.

## Примечание о `null`
Значение `null` не принадлежит ни одному конкретному типу, но **совместимо со всеми ссылочными типами**.  
Это единственное значение, представляющее отсутствие объекта.  
JVM хранит `null` как специальный маркер, не связанный с реальной областью памяти.

> В спецификации `null` описан как _единственное значение null-type_, существующее вне иерархии типов, но допустимое в контексте любого ссылочного типа.

### Краткое резюме
- Каждое значение в Java имеет тип, и каждый тип определяет множество допустимых значений.
- Система типов гарантирует статическую проверку совместимости и безопасность исполнения.
- Типы делятся на примитивные и ссылочные, с расширениями через обобщения и дополнительные структуры.
- Значение `null` — особый случай, существующий вне типовой иерархии, но совместимый с любым ссылочным типом.
