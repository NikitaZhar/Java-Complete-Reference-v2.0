# Журнал аудита

Краткая фиксация результатов заключительного аудита глав: что исправлено, что делегировано и куда, чем верифицированы примеры, что осталось открытым. Точка входа: [[00 — Правила и методика (читать первым)]].

## Chapter 5. Conversions and Contexts — 2026-08-13 → draft (написана заново)

Глава написана с нуля. **Структура пересобрана** по согласованию с автором: вместо перемешанной нумерации из оглавления (5.1 Conversion Contexts, 5.2 Assignment, 5.3 Casting, 5.4 String, 5.5 Numeric Promotions, 5.6 Unboxing, 5.7 Value Set, 5.8 Reference) принята **двухосевая** схема «роды × контексты». Part A — роды (5.1 Overview, 5.2 Identity+Widening primitive, 5.3 Narrowing primitive, 5.4 Boxing/Unboxing, 5.5 Reference, 5.6 String, 5.7 Value Set); Part B — контексты (5.8 Overview, 5.9 Assignment, 5.10 Invocation, 5.11 Casting, 5.12 Numeric promotions); 5.13 Common Mistakes. Закрыты пробелы заявленного оглавления: **widening/narrowing primitive** (не были выделены вовсе), **boxing** (была только распаковка), **invocation context** (отсутствовал). Дом `#concept/narrowing-conversion` в глоссарии (Ch. 5.3) совпал с новой нумерацией.

Источники: сверка по всем четырём книгам (grep). Основной каркас — Mughal (гл. 2 «Type Conversions and Contexts», 1Z0-829 и 1Z0-830): роды, ссылочные конверсии, boxing/unboxing, identity/string/unchecked, контексты, правила унарного/бинарного числового продвижения. Boyarsky (1Z0-830) — 4 правила numeric promotion, ловушки «boxing+widening не комбинируются» (`Long x = 8;`), распаковка `null`→NPE, invocation-примеры (climb/swing/jump), overflow, скрытый каст в compound assignment. JLS §5 — нормативные границы (каталог родов, forbidden, constant narrowing). Oracle/JEP 306 — статус `strictfp` после Java 17 (5.7). Теги `#src/*` проставлены по фактически использованным источникам.

Верификация примеров — **машинная, реальным JDK 21** (`javac`/`java` в рабочем окружении; для конверсий разница 21↔25 несущественна). Прогнаны три набора: 31 значение-claim (значения преобразований — `(byte)260==4`, `(int)3.99==3`, `(int)1e20==Integer.MAX`, `(int)NaN==0`, потеря точности `int→float`, кэш `Integer`, результаты конкатенации, промоушены) — все PASS; 26 claim'ов компиляции (каждый «DOES NOT COMPILE» реально отвергнут `javac`, каждый рабочий — компилируется) — все PASS; 8 runtime-исключений (CCE при downcast, NPE при распаковке `null`/`switch(null)`/тернар, `Math.toIntExact` overflow, выбор перегрузки `m(5)→long`, varargs) — все PASS.

Исправлено в ходе верификации: **два неточных тезиса про тернарный оператор**. Было заявлено, что смешение примитива и обёртки роняет `null`-ветку «даже когда не выбрана» — `javac`/`java` показали, что невыбранная ветка не вычисляется; NPE даёт именно **выбранная** `null`-ветка, а сюрприз в том, что тип всего выражения становится примитивным (`int`) даже при `Integer`-цели, из-за чего обёртка распаковывается. Формулировки в 5.13 и 5.4 переписаны на проверенную версию (`Integer result = true ? count : 0;` → NPE).

Служебные файлы обновлены: в [[Глоссарий]] добавлено 6 терминов (conversion, conversion context, widening primitive conversion, numeric promotion, string conversion, value set conversion) с concept-тегами, синхронно проставленными в frontmatter соответствующих заметок; в [[Матрица владения темами]] — строка «Преобразования и контексты» с домом Ch. 5; в [[Backlog — перенос материала]] пункт про промоушены помечен размещённым (5.2/5.4/5.12).

**Владение boxing/unboxing перенесено в Ch. 5.4** (решение автора 2026-08-13). Раньше домом «механики упаковки» был Ch. 4.2.13; теперь полный разбор — в [[5.4 Boxing and Unboxing Conversion]] (зачем обёртки, механика, комбинирование с другими преобразованиями, стоимость аллокаций, NPE при распаковке `null`), а 4.2.13 ужат до короткой ссылки. Ценный материал 4.2.13 (why-wrappers, allocation cost) не выброшен, а перенесён в 5.4. В [[Глоссарий]] дом термина «autoboxing / unboxing» изменён Ch. 4 → Ch. 5.4; в матрице строка «Примитивы, wrappers, autoboxing» разделена на «Примитивы и wrappers (типы) → Ch. 4» и «Boxing / unboxing (преобразование) → Ch. 5.4»; concept-тег `#concept/autoboxing` снят с 4.2.13 (осталась ссылка), дом тега — 5.4. Попутно устранена та же ошибка в тернарном примере, что и в 5.13, — она ушла вместе с делегированием 4.2.13.

Осталось открытым: глава в статусе `draft` — не прогнан отдельный «свежий взгляд» заключительный аудит построчно по чек-листу другим проходом; примеры верифицированы машинно, но узкие места (value set/`strictfp` на Java 17+, поведение `switch(null)` в 21) стоит перепроверить на JDK 25 при доступности. Мастер-оглавление [[Java Complete Full Reference]] обновлено под новую структуру.

**Проход на полноту покрытия источников — 2026-08-13.** По запросу автора сверил главу построчно с самими книгами (Mughal 1Z0-829/830 §2.3–2.4, Boyarsky 1Z0-829/830 гл. 2 и 5), не только с JLS. Каркас и примеры совпали с источниками плотно (перегрузка climb/swing/jump и Gorilla `rest(8)` — прямо из Boyarsky; таблица контекстов и precision/magnitude — из Mughal Table 2.17). Найдены и **добавлены три пропуска из цитируемых источников**: (1) константное сужение **с упаковкой** (`Byte b = 12;`, `Character c = 65;`) — явный пункт Mughal Table 2.17 «narrowing … with optional boxing» и его пример `Character space1 = 32;` против `Character.valueOf(32)` (ошибка компиляции) — внесено в 5.9, 5.10, отражено в 5.4 и 5.8 (таблица + текст асимметрии); (2) `==`/`!=` над **обёрткой и примитивом** распаковывает и сравнивает по значению (`Integer x=1000; int y=1000; x==y` → true) — Mughal/Boyarsky относят `==` к бинарному продвижению — внесено в 5.4 и 5.13; (3) **сдвиги** используют унарное продвижение по каждому операнду (не бинарное), тип результата = тип левого операнда; плюс унарность каста (`(short)m*n` не компилируется) — внесено новой секцией в 5.12. Мелочи: в 5.9 цели константного сужения уточнены до `byte/short/char` (int — тождество); опечатка «versión» в 5.10 исправлена. Все новые сниппеты прогнаны через `javac`/`java` (JDK 21): компилируемые — компилируются, «DOES NOT COMPILE» — реально отвергнуты (в т. ч. `Character.valueOf(32)` → lossy int→char, как у Mughal).
