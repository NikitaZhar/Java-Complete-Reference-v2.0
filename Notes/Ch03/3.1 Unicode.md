Исходный код на Java пишется в Unicode: и компилятор, и спецификация языка работают не с байтами конкретной кодировки файла, а с потоком Unicode-символов. Практическое следствие — идентификаторы, строки и комментарии можно писать на любом языке, а не только латиницей. Этот раздел фиксирует три понятия, которыми спецификация пользуется дальше по всей главе: code point, UTF-16 code unit и «символ»; их различие становится важным ровно там, где речь идёт о представлении текста. Здесь — только модель символов; байтовые кодировки файла (`UTF-8`, `windows-1251`) и флаг `-encoding` компилятора — это практика JDK (Part III), а не язык.

## Code Points, Code Units, and Characters

Unicode присваивает каждому символу числовой номер — code point (кодовую точку) в диапазоне от `U+0000` до `U+10FFFF`. Внутренне Java хранит текст в кодировке UTF-16: там каждая единица хранения — это UTF-16 code unit (кодовая единица), 16-битное значение. Символы из диапазона `U+0000..U+FFFF` (Basic Multilingual Plane) занимают одну кодовую единицу; дополнительные символы (supplementary characters, `U+10000..U+10FFFF`) кодируются парой кодовых единиц — суррогатной парой: первая из диапазона high-surrogates (`U+D800..U+DBFF`), вторая из low-surrogates (`U+DC00..U+DFFF`). В диапазоне BMP значения кодовой точки и кодовой единицы совпадают. Точную версию стандарта Unicode для конкретного релиза указывает документация класса `Character`.

Спецификация использует термин `code point` там, где важен номер символа, `UTF-16` `code unit` — там, где важно представление, и общий термин «символ» там, где представление неважно. Это различие не абстрактно: тип `char` — это ровно одна `UTF-16` кодовая единица, поэтому один `char` не всегда равен одному «символу» для пользователя.

```java
String s = "𝄞";              // скрипичный ключ, code point U+1D11E (supplementary)
System.out.println(s.length());          // 2  — это число UTF-16 code units, не символов
System.out.println(s.codePointCount(0, s.length())); // 1 — один code point
```

Здесь `length()` возвращает 2, потому что символ вне `BMP` занимает две кодовые единицы. Семантика типов `char`/`String`, суррогатные пары и работа с кодовыми точками во время выполнения — это глава 4; здесь важно лишь, что модель символов языка — `Unicode`, а внутреннее представление — `UTF-16`.

## ASCII as a Subset

Первые 128 символов `Unicode` совпадают с `ASCII`. Это существенно для лексики: за исключением комментариев ([[3.7 Comments]]), идентификаторов ([[3.8 Identifiers]]) и содержимого символьных, строковых литералов и текстовых блоков, все входные элементы программы ([[3.5 Input Elements and Tokens]]) состоят только из ASCII-символов (или из Unicode-escape, дающих ASCII-символы, — [[3.3 Unicode Escapes]]). Иначе говоря, ключевые слова, операторы и разделители всегда пишутся ASCII; «свобода Unicode» распространяется только на имена, тексты и комментарии.

```java
int café = 1;   // ок: не-ASCII буквы допустимы в идентификаторе
int × = 2;      // ошибка компиляции: '×' (U+00D7) — не буква, а знак умножения; в операторе Unicode недопустим
```

Первая строка компилируется, потому что `é` — буква и годится для идентификатора; вторая — нет, потому что оператор умножения записывается только ASCII-символом `*`, а `×` буквой не является.
