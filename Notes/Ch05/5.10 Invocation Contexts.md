# 5.10 Invocation Contexts

Контекст вызова (invocation context) возникает при передаче аргументов в метод или конструктор: значение каждого аргумента приводится к типу соответствующего формального параметра. Набор разрешённых преобразований почти совпадает с присваиванием — расширение примитива, упаковка/распаковка, расширение ссылки, — но с одним принципиальным отличием: **в вызове нет исключения для сужения константы**. То, что в присваивании проходит (`byte b = 100;`), при передаче в метод `f(byte)` уже требует каста. Кроме того, именно в этом контексте живёт **разрешение перегрузки** — выбор одного из нескольких одноимённых методов; полные правила и три его фазы — дом Ch. 8.4.4, здесь показано, как преобразования аргументов на этот выбор влияют.

## Invocation differs from assignment in one place

Единственная содержательная разница с присваиванием: метод-инвокация **не** выполняет неявное сужение константного целочисленного выражения. Диапазон значения роли не играет — важно, что это вызов, а не присваивание.

```java
void ship(short qty) {}

short s = 100;          // assignment: константное сужение int→short, ок
ship(100);              // DOES NOT COMPILE: invocation не сужает даже константу 100
ship((short) 100);      // ок: явный каст
```

То же и с упаковкой: сокращение «сужение константы + упаковка», разрешённое в присваивании (`Character c = 32;`), в вызове не действует.

```java
Character a = 32;                    // assignment: сужение константы int→char + упаковка, ок
Character b = Character.valueOf(32); // DOES NOT COMPILE: сигнатура valueOf(char), 32 — int,
                                     // а в вызове константа не сужается
Character d = Character.valueOf((char) 32); // ок: явный каст до char
```

Всё остальное как в присваивании: расширение и упаковка/распаковка работают неявно.

```java
void log(long id) {}
void put(Object o) {}

log(42);                // widening int→long при передаче
put("text");            // widening reference String→Object
put(42);                // boxing int→Integer, затем widening Integer→Object
```

## How conversions shape overload resolution

Когда методов с одним именем несколько, компилятор выбирает применимый по трём фазам, и на каждой фазе разрешён свой набор преобразований (детально — Ch. 8.4.4):

Фаза 1 — без упаковки/распаковки и без varargs: только тождество и расширение. Фаза 2 — добавляется упаковка/распаковка. Фаза 3 — добавляются varargs. Компилятор берёт **первую** фазу, на которой находится применимый метод; поэтому «более точное» примитивное расширение выигрывает у упаковки.

```java
static void m(long x)    { System.out.println("long"); }
static void m(Integer x) { System.out.println("Integer"); }

m(5);   // печатает "long": фаза 1 (widening int→long) находит метод раньше,
        // чем фаза 2 (boxing int→Integer). Расширение приоритетнее упаковки.
```

Отсюда практический пример из книг: разные методы выбираются в зависимости от того, какое преобразование аргумента возможно.

```java
static void climb(long t)    {}   // int пройдёт widening
static void swing(Integer u) {}   // int пройдёт boxing
static void jump(int v)      {}

climb(123);   // ок: widening int→long (фаза 1)
swing(123);   // ок: boxing int→Integer (фаза 2)
jump(123L);   // DOES NOT COMPILE: long→int это сужение, ни в одной фазе не делается неявно
```

## Boxing plus widening does not combine here either

Правило «упаковка не комбинируется с расширением примитива» (см. [[5.4 Boxing and Unboxing Conversion]]) действует и в вызове: аргумент `int` не доедет до параметра `Long` сам.

```java
static void rest(Long x) {}
rest(8);        // DOES NOT COMPILE: нужно int→long И →Long за раз — нельзя
rest(8L);       // ок: long-литерал → одна упаковка Long
```

## Varargs as the last resort

Метод с переменным числом аргументов (`T...`) применяется только в фазе 3 — после того как исчерпаны варианты с фиксированной арностью. Поэтому при наличии точного не-varargs метода varargs проигрывает.

```java
static void f(int a, int b)   { System.out.println("pair"); }
static void f(int... nums)    { System.out.println("varargs"); }

f(1, 2);        // "pair": фиксированная арность (фаза 1/2) раньше varargs (фаза 3)
f(1, 2, 3);     // "varargs": пары нет, подходит только версия с varargs
```

## Common Mistakes

- Переносить константное сужение из присваивания в вызов.

```java
void setAge(byte age) {}
setAge(30);             // DOES NOT COMPILE, хотя byte age = 30; было бы легально
```
  Правильно: `setAge((byte) 30);`.

- Ждать, что перегрузка выберет упакованный вариант, когда возможно расширение.

```java
// при m(long) и m(Integer) вызов m(5) уйдёт в m(long), а не в m(Integer)
```
  Правильно: если нужен именно `Integer`-вариант — передать `Integer.valueOf(5)` или объявить аргумент как `Integer`.

- Рассчитывать, что `int`-аргумент подойдёт к параметру-обёртке шире своего типа (`Long`, `Double`).

```java
static void rest(Long x) {}
rest(8);                // DOES NOT COMPILE
```
  Правильно: `rest(8L)` или `rest(Long.valueOf(8))`.
