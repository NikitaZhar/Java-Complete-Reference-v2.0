Символьный литерал заключён в одинарные кавычки и содержит ровно один символ или одну escape-последовательность; его тип — `char`.

```java
char c       = 'A';        // обычный символ
char omega   = 'Ω';        // любой символ Unicode прямо из исходника
char newline = '\n';       // escape-последовательность
```

## Escape Sequences

Escape-последовательность — это запись специального символа через обратную косую. Один и тот же набор escape действует в символьных литералах, строковых литералах ([[3.10.5 String Literals]]) и текстовых блоках; здесь он приводится полностью, дальше на него ссылаются. Каждой escape соответствует конкретная кодовая точка, поэтому `'\t'` и табуляция, вписанная в исходник напрямую, — один и тот же символ.

| Escape | Значение | Кодовая точка |
|---|---|---|
| `\b` | забой (backspace) | `U+0008` |
| `\s` | пробел (space), с Java 15 | `U+0020` |
| `\t` | горизонтальная табуляция (HT) | `U+0009` |
| `\n` | перевод строки (LF) | `U+000A` |
| `\f` | подача страницы (form feed) | `U+000C` |
| `\r` | возврат каретки (CR) | `U+000D` |
| `\"` | двойная кавычка | `U+0022` |
| `\'` | одинарная кавычка | `U+0027` |
| `\\` | обратная косая | `U+005C` |
| `\`‹перевод строки› | склейка со следующей строкой — только в текстовом блоке | — |
| `\ddd` | октальный код: одна–три восьмеричные цифры, не больше `\377` | — |

```java
char tab   = '\t';
char quote = '\'';   // одинарную кавычку внутри '' обязательно экранировать
char back  = '\\';   // и обратную косую тоже
char space = '\s';   // пробел (с Java 15); эквивалент ' '
char oct   = '\101'; // 'A' через октальный код
```

Октальная форма `\ddd` покрывает только первые 256 кодовых точек (`\000`–`\377`): не более трёх цифр, старшая — не больше 3, иначе ошибка. Escape склейки строк `\`‹перевод строки› и значимый пробел `\s` осмысленны прежде всего в текстовых блоках (перенос без `\n` и защита хвостового пробела) — детали в [[3.10.5 String Literals]]; в одиночном `char` перевод строки записать нельзя в принципе, только `'\n'`.

Недопустимая escape-последовательность — ошибка компиляции. Разрешены только перечисленные выше.

```java
char bad  = '\x41';  // ошибка компиляции: \x не является допустимым escape
char bad2 = '\d';    // ошибка компиляции: \d не escape (частая привычка из regex)
```

## The \uXXXX Escape Is Special

`\uXXXX` обрабатывается не так, как `\n` и остальные escape. Обычные escape раскрываются на лексической стадии, внутри литерала, а `\uXXXX` — раньше, ещё до токенизации. Поэтому Unicode-escape кавычки или перевода строки способен «схлопнуть» литерал до того, как компилятор начнёт его разбирать, и вызвать неожиданную ошибку. Механизм и разбор таких ловушек — в разделе 3.3 Unicode Escapes; в символьных литералах достаточно помнить: для кавычки и перевода строки используйте обычные escape `'\''` и `'\n'`, а не Unicode-коды.

## One char Is One UTF-16 Code Unit

Символьный литерал вмещает ровно одну кодовую единицу UTF-16, а не «один символ пользователя». Символы из BMP (`U+0000..U+FFFF`, например `'Ω'`) помещаются, но **дополнительный символ** вне BMP (`U+10000..U+10FFFF`, например скрипичный ключ `𝄞`, `U+1D11E`) занимает две кодовые единицы (суррогатную пару) и в `char` не влезает — это ошибка компиляции. Такой символ хранят в `String` (там он даёт `length() == 2`) или в `int`-кодовой точке. Связь `char` ↔ UTF-16 ↔ суррогатные пары — [[3.1 Unicode]] и Part I, Ch. 4.

```java
char bmp = 'Ω';       // ок: один code unit
char sup = '𝄞';       // ошибка компиляции: символ вне BMP — две кодовые единицы
String ok = "𝄞";      // правильно: в String (length() == 2)
int cp = 0x1D11E;     // или как код-пойнт
```

## Errors

```java
char empty = '';     // ошибка: символьный литерал не может быть пустым
char two   = 'AB';   // ошибка: допустим только один символ
// char nl = '<перевод строки>';  — «сырой» перевод строки внутри '' запрещён, нужен '\n'
```

## Common Mistakes

1. **Пустой или многосимвольный литерал.** `char c = '';` или `'AB'` → ошибка. Для нескольких символов нужен `String`: `"AB"`.
2. **Неэкранированные `'` и `\`.** `char q = ''';` → ошибка. Правильно: `'\''` и `'\\'`.
3. **«Сишные» или regex-escape.** `'\x41'`, `'\d'` недопустимы. Правильно: `'A'` или октальный `'\101'`.
4. **Unicode-escape для кавычки или перевода строки.** Раскрывается до токенизации и ломает литерал. Правильно: обычные `'\''` и `'\n'` (см. 3.3).
