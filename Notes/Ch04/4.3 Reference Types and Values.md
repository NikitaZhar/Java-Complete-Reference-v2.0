# 4.3 Reference Types and Values

Ссылочные типы бывают четырёх родов. **Классы** (`class`, в том числе абстрактные, вложенные, локальные, анонимные, а также `enum` и `record`) — носители состояния и поведения. **Интерфейсы** (`interface`, включая функциональные и `@interface`-аннотации) — контракты. **Массивы** — упорядоченные наборы элементов одного типа, сами являющиеся объектами. **Типовые переменные** (`T`, `E`) — параметры generics, не задающие отдельный runtime-класс каждой подстановки. Все они — подтипы `Object` (даже массивы), и значение любого из них может быть `null`.

## The four kinds of reference types

Ссылочные типы бывают четырёх родов. **Классы** (`class`, в том числе абстрактные, вложенные, локальные, анонимные, а также `enum` и `record`) — носители состояния и поведения. **Интерфейсы** (`interface`, включая функциональные и `@interface`-аннотации) — контракты. **Массивы** — упорядоченные наборы элементов одного типа, сами являющиеся объектами. **Типовые переменные** (`T`, `E`) — параметры generics, существующие только на компиляции. Все они — подтипы `Object` (даже массивы), и значение любого из них может быть `null`.

```java
String s = "text";       // класс
Runnable r = () -> {};   // интерфейс (функциональный)
int[] a = {1, 2, 3};     // массив — тоже объект, подтип Object
Object o = a;            // ок: int[] <: Object
```

Механику подтипирования между ссылочными типами задаёт [[4.1.6 Subtypes and Supertypes]]; здесь важно, что перечисленные роды образуют единую иерархию с корнем `Object`.

## The value is the reference, not the object

Ссылочная переменная хранит ссылку на объект либо null. Объекты получают через создание экземпляра или массива, строковый литерал, инициализатор массива, фабричный метод и другие выражения. Объект и ссылка — разные сущности; модель копирования значений — [[4.1.7 Runtime Representation of Values]]. Физическое представление — тема JVM.

Наличие ссылок внутри изолированной группы объектов не гарантирует её достижимость от корней. Время жизни объекта нельзя выводить только из лексической области видимости переменной. Подробные правила достижимости и сборки мусора — Ch. 43.

## The null type

`null` — единственное значение особого **null-типа**, у которого нет имени и который нельзя объявить. В иерархии он занимает нижнюю позицию: null-тип является подтипом всех ссылочных типов, поэтому `null` присваивается переменной любого ссылочного типа — и ни одной примитивной.

```java
String s = null;         // ок
Runnable r = null;       // ок
int[] a = null;          // ок: массив — ссылочный тип
int x = null;            // compile-time error: примитив не принимает null
```

`null` означает «ссылка ни на что». Попытка вызвать экземплярный метод, обратиться к экземплярному полю, компоненту или length массива через null — даёт `NullPointerException`, потому что объекта за ссылкой нет. С Java 14+ сообщения об NPE стали «подробными» (helpful NPE): они указывают **null-производящую часть выражения** (какое обращение провалилось), что заметно ускоряет отладку. Точного имени исходной локальной переменной сообщение не гарантирует во всех случаях — оно описывает путь доступа в выражении.

```java
String s = null;
int len = s.length();    // NullPointerException: Cannot invoke "String.length()" because "s" is null
```

## Identity versus equality

Для ссылочных значений различают **тождество** (это один и тот же объект?) и **равенство** (объекты равны по содержимому?). Оператор `==` сравнивает тождество ссылок, метод `equals` — содержимое (если класс его осмысленно переопределяет). Смешение этих двух — одна из самых частых ошибок, особенно со строками, из-за пула строковых литералов.

```java
String a = "hi";              // из пула литералов
String b = "hi";              // та же ссылка из пула
String c = new String("hi");  // явно новый объект
System.out.println(a == b);      // true  — одна ссылка (пул)
System.out.println(a == c);      // false — разные объекты
System.out.println(a.equals(c)); // true  — одинаковое содержимое
```

Практический вывод: содержимое ссылочных значений сравнивают через `equals`, а `==` оставляют проверке тождества и сравнению с `null`. Полный контракт `equals`/`hashCode` (симметричность, согласованность, связь с `hashCode`) и кэш обёрток — дом Ch. 49; здесь важно само различие уровней.

## Generic-related type forms: a boundary overview

Раздел (и вся глава) пользуется несколькими понятиями из мира обобщений, и их стоит определить как **границу** — рабочим минимумом, без полной теории, дом которой Ch. 20. Это нужно, чтобы классификация ссылочных типов, тождество типов и подтипирование были логически замкнуты.

- **Типовая переменная** (type variable) — имя-заполнитель (`T`, `E`), вводимое обобщённым объявлением; это ссылочный тип, используемый в статической проверке и стираемый для исполнения; метаданные generic-объявления могут сохраняться.
- **Параметризованный тип** (parameterized type) — обобщённый тип с подставленными аргументами: `List<String>`.
- **Сырой тип** (raw type) — использование generic-типа без аргументов: `List`. Присваивание `List<String>` в `List` не требует `unchecked conversion`; обратное присваивание `List` в `List<String>` обычно сопровождается unchecked-предупреждением. Подробности — Ch. 20.
- **Стирание** (erasure) — отображение generic-типов в типы без параметризации для исполнения. `List<String>` и `List<Integer>` стираются в `raw List`. Это не означает, что объекты этих статических типов имеют одинаковый класс реализации: один может быть `ArrayList`, другой `LinkedList`. Метаданные generic-объявлений могут сохраняться; полный механизм — Ch. 20.
- **Реифицируемый тип** (reifiable type) — тип, информация о котором полностью доступна во время выполнения. Например, `String`, `raw List`, `List<?>` и массив с реифицируемым компонентным типом. Для вложенного типа также должны быть реифицируемыми составляющие его типы; тип-пересечение не реифицируем. Это пограничный обзор: полное определение — Ch. 20. Создание массива требует реифицируемого элементного типа, а допустимость instanceof определяется отдельными правилами оператора: некоторые проверки нереифицируемой параметризации разрешены без `unchecked conversion`.
- **Тип-пересечение** (intersection type) — `A & B`: подтип обоих; возникает из нескольких границ (`<T extends Number & Comparable<T>>`) и из intersection-каста.

```java
List<String> xs = new ArrayList<>(); // параметризованный тип
List raw = xs; // переход в raw List без unchecked conversion; использование raw может дать отдельное rawtypes-предупреждение
boolean ok = xs instanceof List<?>;   // reifiable: безграничный wildcard — можно

Object o = xs;
// boolean bad = o instanceof List<String>; // compile-time error: проверка Object на List<String> потребовала бы unchecked conversion
```

## The catalogue of reference types and their homes

Отдельные роды ссылочных типов раскрываются в своих главах, и дублировать их здесь незачем: массивы — Ch. 13; перечисления (`enum`) — Ch. 10; записи (`record`) — Ch. 12; интерфейсы, в том числе функциональные, — Ch. 9 и Ch. 15.6; строки (`String`, неизменяемость, пул) — главы строк; generics и типовые переменные — Ch. 20. Особый ссылочный тип `Class<T>` представляет сам тип как объект-метаданные: литерал класса `String.class` даёт объект `Class`, а `obj.getClass()` — фактический тип значения (см. [[4.1.5 Static vs Runtime Type]]). Наконец, `Void` — ссылочный тип-маркер, применяемый как аргумент типа там, где значение не нужно (`Callable<Void>`), в отличие от `void`, который вообще не тип.

## Common Mistakes

- Сравнивать строки (и другие объекты) через `==`.

```java
String input = new String("yes");
if (input == "yes") { }   // false: разные объекты
```

Правильно: `input.equals("yes")` или, безопаснее от `null`, `"yes".equals(input)`.

- Разыменовать `null`.

```java
Map<String, String> m = new HashMap<>();
int n = m.get("k").length();   // get вернул null → NullPointerException
```

Правильно: проверить результат get на null перед вызовом length(). getOrDefault подходит, когда ключ отсутствует, но если ключ связан с null, метод возвращает null; это не универсальная защита от NPE.

- Считать, что объект с взаимными ссылками не соберётся. Правильно: решает достижимость от корней, а не наличие ссылок вообще (Ch. 43).

- Путать `void` и `Void`: `void` нельзя использовать как аргумент типа. Правильно: там, где generic требует ссылочный тип, а значение не нужно, — `Void` (и возвращать `null`).
