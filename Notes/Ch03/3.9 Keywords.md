Ключевое слово — это последовательность ASCII-букв, зарезервированная языком за особым значением. Java различает два вида: зарезервированные ключевые слова, которые нельзя использовать как имена нигде, и контекстные ключевые слова, которые являются ключевыми только в определённых синтаксических позициях, а в остальных остаются обычными идентификаторами. Отдельно стоит запомнить, что `true`, `false` и `null` — не ключевые слова, а литералы, хотя именами их сделать тоже нельзя. Правила распознавания важны на практике: они объясняют, почему `var` можно назвать переменную, но нельзя — класс.

## Reserved Keywords

Зарезервированных ключевых слов пятьдесят, плюс одиночное подчёркивание `_` — итого 51 форма, которую нельзя использовать как идентификатор ни в каком контексте.

```
abstract   continue   for          new         switch
assert     default    if           package     synchronized
boolean    do         goto         private     this
break      double     implements   protected   throw
byte       else       import       public      throws
case       enum       instanceof   return      transient
catch      extends    int          short       try
char       final      interface    static      void
class      finally    long         strictfp    volatile
const      float      native       super       while
_ (подчёркивание)
```

Все ключевые слова записываются строчными буквами, поэтому имя, отличающееся регистром (`Goto`, `Class`), остаётся допустимым идентификатором — хотя так писать не стоит. Два слова зарезервированы, но языком не используются: `const` и `goto`. Они держатся в резерве, чтобы приходящие из C/C++ не применяли их по ошибке и на случай будущего использования. Одиночный `_` стал ключевым словом начиная с Java 9 (раньше — допустимое имя); с Java 21 он обозначает неименованную переменную (unnamed variable) в позициях объявления.

```java
int class = 1;      // ошибка компиляции: class — зарезервированное слово
int Goto = 2;       // ок: Goto с большой буквы — не ключевое слово (регистр важен), но так не пишут
int _ = compute();  // трактуется как неименованная переменная (Java 21+), а не как имя '_'
```

## Contextual Keywords

Контекстных ключевых слов семнадцать. Каждое является ключевым только в своей синтаксической позиции, а вне её — обычный идентификатор.

```
exports   opens    requires   uses    yield
module    permits  sealed     var
non-sealed provides to        when
open      record   transitive with
```

Распознавание идёт по контексту: `module`, `open`, `requires`, `exports`, `opens`, `provides`, `uses`, `to`, `with`, `transitive` — ключевые в объявлении модуля и директивах (Part I, Ch. 7; Part VI, Ch. 60); `var` — в объявлении локальной переменной и параметрах лямбды; `yield` — в операторе `yield`; `record` — в объявлении записи; `sealed`, `non-sealed`, `permits` — в объявлении класса/интерфейса; `when` — в guard-условии `switch`.

```java
var list = new ArrayList<String>();   // var — контекстное ключевое слово
int var = 3;                          // var — обычное имя: допустимо
int record = 42;                      // record как имя переменной — тоже допустимо
record Point(int x, int y) {}         // а здесь record — ключевое слово (объявление записи)
```

Особый случай — `non-sealed`: это единственное ключевое слово с дефисом. Как модификатор класса или интерфейса оно распознаётся только целиком, записанным с дефисом и без внутренних пробелов; вне позиции модификатора те же символы разбираются обычным образом (например, `non - sealed` как вычитание идентификаторов).

## Not Keywords: the Literals true, false, null

`true` и `false` — булевы литералы ([[3.10.3 Boolean Literals]]), `null` — литерал `null` ([[3.10.6 The null Literal]]). Формально это не ключевые слова, но использовать их как имена тоже нельзя — по правилу токенизации идентификатор не может совпадать с литералом ([[3.5 Input Elements and Tokens]]).

```java
boolean true = false;   // ошибка компиляции: true — литерал, не имя
Object null = new Object();  // ошибка компиляции: null — литерал, не имя
```
