# 5.14 Testing Contexts and Pattern Compatibility

Проверочный контекст (testing context, JLS §5.7) — самый новый из контекстов преобразования: он возникает, когда значение выражения проверяется на соответствие типу, заданному **образцом** (pattern) — в операторе `instanceof` и в pattern-`switch`. Его добавили ради pattern matching (`instanceof` с образцом — Java 16, pattern-`switch` — Java 21), и в классической «модели пяти контекстов» его нет. По инклюзивности JLS помещает его между loose invocation и casting: он допускает больше, чем присваивание и вызов (в частности, сужение ссылки), но меньше, чем каст (не допускает unchecked). Полная семантика самих образцов — дом Ch. 14.7; здесь — только слой преобразований: какие переходы значения к типу образца разрешены и чем это отличается от явного каста.

## What conversions a testing context allows

К значению, проверяемому образцом типа `T`, применимы три рода (и только они):

- **identity** — тип образца совпадает со статическим типом выражения (образец совпадает всегда, кроме `null`);
- **widening reference** — тип образца является надтипом (тоже всегда истинно для ненулевого значения);
- **narrowing reference, но только checked** — тип образца является подтипом; вот здесь проверка и содержательна.

Unchecked narrowing (как в касте к параметризованному типу) **не** допускается — это и делает testing строго менее инклюзивным, чем casting.

```java
Object o = "hi";
if (o instanceof String s) {        // narrowing reference (checked): String — подтип Object
    System.out.println(s.length()); // 2 — s привязана только при успехе
}
```

## instanceof binds on success, never throws on mismatch

Ключевое отличие от каста: `instanceof` **проверяет и связывает**, но при несоответствии не бросает исключение — ветка просто не выполняется. Каст на том же несоответствии дал бы `ClassCastException`.

```java
Object x = Integer.valueOf(5);
boolean isStr = x instanceof String;   // false — без исключения
// String s = (String) x;              // а это бросило бы ClassCastException
```

`null` образцу типа **никогда** не соответствует: `null instanceof T` — всегда `false`, поэтому образец-переменная не свяжется с `null`. Это защищает тело ветки от `NullPointerException`.

```java
System.out.println(((Object) null) instanceof String); // false
```

## No unchecked narrowing: the sharp line against casting

Testing-контекст отказывается проверять то, что невозможно проверить в runtime из-за стирания. Каст к `List<String>` компилятор пропустит с unchecked-предупреждением, а `instanceof List<String>` — **отвергнет на компиляции**: JVM не может проверить тип элементов, а testing (в отличие от casting) unchecked не допускает. Проверять можно только реифицируемую форму — с безграничным wildcard.

```java
Object lst = new ArrayList<String>();
boolean ok = lst instanceof List<?>;       // ок: безграничный wildcard реифицируем
// boolean bad = lst instanceof List<String>; // DOES NOT COMPILE: Object cannot be safely cast to List<String>
```

Это удобная граница: если `instanceof` с обобщённым типом не компилируется, значит и «проверка» была бы фиктивной — компилятор заставляет либо взять `List<?>`, либо признать, что типобезопасность здесь не обеспечена.

## Pattern switch

Тот же контекст работает в `switch` с образцами: селектор проверяется против типа каждого `case`-образца теми же преобразованиями. Добавляется обработка `null` (только через явный `case null`) и проверка полноты (exhaustiveness) — особенно с sealed-иерархиями, где компилятор знает полный список наследников.

```java
static String describe(Object o) {
    return switch (o) {
        case String str -> "str:" + str.length();   // narrowing reference + связывание
        case Integer i  -> "int:" + i;
        case null       -> "null";                  // null не матчится образцом типа — нужен явный case
        default         -> "other";
    };
}
```

Полнота с sealed-типами позволяет обойтись без `default`, когда перечислены все наследники (record-образцы и вложенная деструктуризация — тоже здесь); всё это — конструкции Ch. 14.7, здесь важно лишь, что проверка типа в каждом `case` идёт по правилам testing-контекста. (Образцы для **примитивных** типов — preview-возможность SE 25, полагаться на неё в основном коде не стоит.)

## Testing versus explicit cast

| | Testing (`instanceof` / pattern) | Явный каст `(T)` |
|---|---|---|
| При несоответствии | ветка не матчится (нет исключения) | `ClassCastException` |
| Unchecked narrowing | запрещён на компиляции | разрешён с предупреждением |
| `null` | не матчится (кроме `case null`) | проходит без исключения |
| Результат | проверка + связывание переменной | смена статического типа |

Практический вывод: `instanceof`-образец — это **безопасный downcast**, совмещающий проверку и приведение; там, где раньше писали `if (o instanceof T) { T t = (T) o; … }`, теперь `if (o instanceof T t) { … }` — без отдельного каста и без риска `ClassCastException`.

## Common Mistakes

- Ожидать, что `instanceof` с параметризованным типом «проверит элементы».

```java
Object o = getList();
// if (o instanceof List<String> ls) { } // DOES NOT COMPILE
if (o instanceof List<?> ls) { }          // максимум, что проверяемо: что это List
```
  Правильно: проверять `List<?>`, а тип элементов подтверждать при чтении или проектировать без сырых значений.

- Забыть, что `null` не матчится образцом типа, и удивляться, что `null` уходит в `default` (или роняет `switch` без `case null` — см. [[5.4 Boxing and Unboxing Conversion]] про распаковку и [[5.13 Common Mistakes and Pitfalls]]).

- Дублировать каст после `instanceof`-образца.

```java
if (o instanceof String s) { String again = (String) o; } // лишний каст: s уже String
```
  Правильно: пользоваться связанной переменной `s` напрямую.
