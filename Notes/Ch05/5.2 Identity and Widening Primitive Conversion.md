# 5.2 Identity and Widening Primitive Conversion

Тождественное преобразование — вырожденный случай: переход типа в себя, всегда разрешён и ничего не делает; он упомянут лишь потому, что формально каждое выражение «преобразуется» к своему же типу, и это нужно правилам контекстов. Практически важное здесь — **расширяющее примитивное преобразование (widening primitive conversion)**: переход от более узкого числового типа к более широкому. Именно оно позволяет присваивать `int` переменной `long` или подставлять `byte` туда, где ждут `double`, без единого каста. Ключевая тонкость, которую раздел разбирает подробно: «расширяющее» означает «в тип с большим диапазоном», но **не** всегда «без потери информации» — переход в `float`/`double` может огрубить значение.

## The widening chain

Расширения между примитивами образуют цепочку по возрастанию диапазона. Разрешены (неявно) переходы вправо по ней:

`byte` → `short` → `int` → `long` → `float` → `double`

Плюс отдельно `char` → `int` (и дальше по цепочке к `long`, `float`, `double`). Переходы транзитивны: `int` можно преобразовать сразу в `double`, не проходя через `long` и `float`. Тип `boolean` в цепочке не участвует вовсе — он не число и не преобразуется ни в один числовой тип и обратно.

```java
byte b = 42;
int i = b;          // widening byte → int
long l = i;         // widening int → long
double d = l;       // widening long → double (транзитивно допустимо и напрямую)
char c = 'A';       // 'A' == 65
int code = c;       // widening char → int: code == 65
```

`char` беззнаковый (диапазон 0..65535), поэтому его расширение всегда идёт через `int` и даёт неотрицательное число. Обратного неявного перехода нет: `int`→`char` — сужение (см. [[5.3 Narrowing Primitive Conversion]]).

## Widening that loses precision

Диапазон целевого типа при расширении всегда шире, но у вещественных типов ограничено число **значащих бит** (точность), и оно меньше, чем у широких целых. Поэтому три расширения — `int`→`float`, `long`→`float`, `long`→`double` — формально расширяющие, но способны вернуть лишь **корректно округлённое приближение** исходного целого. `float` хранит ~24 значащих бита мантиссы, `double` — ~53; `int` имеет 31 значащий бит, `long` — 63, и они не помещаются.

```java
int n = 123_456_789;
float f = n;                 // widening int → float, но точность теряется
System.out.println((int) f); // 123456792 — не 123456789!

long big = 9_007_199_254_740_993L; // 2^53 + 1
double g = big;                    // widening long → double
System.out.println((long) g);      // 9007199254740992 — младший бит потерян
```

Важно различать: **магнитуда** (насколько велико значение) при расширении не теряется — переполнения не будет; теряется именно **точность** (младшие значащие биты). Расширяющее преобразование **никогда** не бросает исключение времени выполнения, как бы ни округлилось значение.

## Why widening is implicit and safe to write

Компилятор применяет расширение сам, потому что оно не может «сломать» значение до неузнаваемости: диапазон целевого типа заведомо вмещает источник. Поэтому каст при расширении не требуется — но и не запрещён: `long l = (long) i;` легально, просто избыточно. Явный каст иногда пишут, чтобы направить арифметику в нужный тип (см. пример с делением ниже).

```java
int total = 7, count = 2;
double avg1 = total / count;          // 3.0 — деление целых, потом widening результата 3
double avg2 = (double) total / count; // 3.5 — каст делает деление вещественным
```

Здесь `avg1` даёт `3.0` не из-за расширения, а потому что `total / count` вычисляется в `int` **до** присваивания; расширение применяется уже к готовому `3`. Каст в `avg2` меняет тип операнда, включая бинарное числовое продвижение (см. [[5.12 Numeric Contexts (Numeric Promotions)]]).

## Common Mistakes

- Считать, что расширение в вещественный тип сохраняет целое точно.

```java
long id = 9_007_199_254_740_993L;
double asDouble = id;                 // молча теряет младший бит
if (id == (long)(double) id) { }      // false — round-trip не совпал
```
  Правильно: для точных больших целых не использовать `float`/`double` как промежуточное хранилище; сравнивать в целочисленном типе.

- Ожидать вещественный результат от деления, забыв, что операнды целые.

```java
double ratio = 3 / 4;                 // 0.0, а не 0.75
```
  Правильно: `double ratio = 3.0 / 4;` или `(double) 3 / 4` — сделать хотя бы один операнд вещественным до деления.

- Пытаться расширить `boolean` до числа.

```java
int flag = true;                      // DOES NOT COMPILE: boolean не число
```
  Правильно: `boolean`/число несовместимы; использовать условное выражение `int flag = cond ? 1 : 0;`.
