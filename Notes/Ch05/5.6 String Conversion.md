# 5.6 String Conversion

Строковое преобразование (string conversion) — единственный род, который применяется в очень узком, но повсеместном месте: **оператор конкатенации `+`, когда хотя бы один операнд — `String`**. В этом контексте значение любого другого типа — примитив, ссылка, `null` — автоматически превращается в `String`. Это то, что позволяет писать `"x = " + 42` и `"result: " + obj`, не вызывая `toString()` вручную. Раздел объясняет, во что именно превращается каждый род значений и где у этого удобства острые углы: приоритет `+`, `null` без исключения и лишние объекты в циклах.

## The rule

Если в выражении `a + b` хотя бы один операнд имеет тип `String`, второй подвергается строковому преобразованию, и результат — новый `String`, склейка двух. Для ссылочных типов вызывается `String.valueOf(x)`, который для не-`null` возвращает `x.toString()`, а для `null` даёт строку `"null"` — без `NullPointerException`. Для примитивов используется соответствующий `String.valueOf` (например, `String.valueOf(int)`).

```java
int n = 42;
String a = "n = " + n;          // int → "42": результат "n = 42"
String b = "flag: " + true;     // boolean → "true"
String c = "ch: " + 'A';        // char → "A" (не код!)

Object o = null;
String d = "value = " + o;      // null → "null", без исключения: "value = null"

int[] arr = {1, 2, 3};
String e = "arr = " + arr;      // toString массива → "arr = [I@1b6d3586" (не элементы!)
```

`char` в конкатенации даёт сам символ (`"A"`), а не его код, — в отличие от числового контекста, где `'A'` продвигается до `65`. Массив печатается как `[I@…` (тип + хэш), потому что `toString()` у массивов не переопределён; для содержимого нужен `Arrays.toString(arr)`.

## Precedence: + is left-associative

`+` вычисляется слева направо и имеет одинаковый приоритет для сложения и конкатенации. Как только слева появился `String`, всё дальнейшее становится конкатенацией; но пока строки слева нет, `+` — это арифметика. Отсюда классическая путаница.

```java
System.out.println("Sum: " + 2 + 3);    // "Sum: 23" — ("Sum:"+2)+3, обе конкатенации
System.out.println("Sum: " + (2 + 3));  // "Sum: 5" — скобки делают сложение первым
System.out.println(2 + 3 + " = sum");   // "5 = sum" — 2+3 сложились до появления строки
```

## Under the hood and performance

Начиная с Java 9 компилятор реализует конкатенацию через `invokedynamic` и `StringConcatFactory`, а не через явный `StringBuilder`; для практики это значит, что одиночная конкатенация эффективна. Но **в цикле** каждая итерация `s = s + x` создаёт новый `String` (строки неизменяемы), давая квадратичную работу. Устройство `String`, неизменяемость и `StringBuilder` — тема глав о строках (Ch. 50); здесь важно лишь, что строковое преобразование скрывает создание объектов.

```java
String s = "";
for (int i = 0; i < n; i++) {
    s = s + i;                  // каждая итерация — новый String: O(n^2) по суммарной работе
}
// Правильно для горячего пути — StringBuilder (см. Ch. 50)
```

## Common Mistakes

- Ожидать сложение, когда слева уже строка.

```java
String label = "Items: " + 2 + 3;   // "Items: 23", а не "Items: 5"
```
  Правильно: сгруппировать арифметику скобками — `"Items: " + (2 + 3)`.

- Печатать массив (или объект без осмысленного `toString`) через конкатенацию и ждать содержимое.

```java
int[] data = {1, 2, 3};
log("data = " + data);              // "data = [I@…", а не элементы
```
  Правильно: `Arrays.toString(data)` для массива; переопределить `toString()` у своих классов.

- Строить строку конкатенацией в цикле на горячем пути.

```java
String csv = "";
for (String field : fields) csv = csv + field + ",";  // O(n^2)
```
  Правильно: `StringBuilder` или `String.join(",", fields)` (детали — Ch. 50).
