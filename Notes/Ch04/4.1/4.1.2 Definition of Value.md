# 4.1.2 Definition of Value

Тип описывает допустимые значения и операции; значение — конкретное примитивное или ссылочное содержимое. При выполнении программа вычисляет и передаёт значения, но значения константных выражений могут быть известны уже на компиляции. Раздел связывает род значения, статический тип выражения и фактический класс объекта; границы — [[4.1.5 Static vs Runtime Type]], [[4.1.7 Runtime Representation of Values]] и Ch. 5.

## Types of values

Значения бывают двух родов:

- **примитивные** — числовые и логические значения, включая кодовые единицы `char`;
- **ссылочные** — ссылки на объекты либо `null`. `Null` — особое ссылочное значение, не обозначающее объект.

Ненулевая ссылка обозначает определённый объект; несколько переменных могут хранить ссылки на один объект. Java не предоставляет арифметики указателей и прямого доступа к адресу объекта.

```java
int prim = 42;               // примитивное значение
String ref = "hi";           // ссылочное значение: ссылка на объект String
String none = null;          // null: ссылки на объект нет
```

Литерал класса даёт ссылочное значение — объект `Class`. `String.class` имеет тип `Class<String>`, а `int.class` — `Class<Integer>`; последнее правило не означает упаковку значения `int`. `int.class` представляет примитивный тип и отличается от `Integer.class`. `Integer.valueOf(5)` даёт ссылку на объект `Integer`.

```java
Class<String> meta = String.class; // ссылочное значение типа Class<String>, не отдельный род
```

`null` заслуживает того, чтобы противоречие в нём назвать вслух: это **ссылочное значение, которое означает отсутствие объекта**. Переменная им «занята» — в ней лежит вполне определённый маркер, — но указывает этот маркер в никуда. Отсюда `NullPointerException` при вызове экземплярного метода или доступе к экземплярному полю через `null`: объекта нет. У `null` собственный служебный **null-тип**, подтип всех ссылочных типов, поэтому `null` присваивается любой ссылочной переменной и ни одной примитивной (подробнее — [[4.3 Reference Types and Values]]).

## Value, expression type, and runtime class are three different levels

Наивная формула «значение принадлежит ровно одному типу» звучит удобно, но смешивает три разных уровня. Точная модель такая:

- у каждого **выражения** ровно один тип на компиляции (compile-time тип) — именно он позволяет компилятору проверять операции, не запуская программу;
- **значение**, полученное при вычислении, должно быть совместимо с этим типом, но ссылочное значение может обозначать объект более конкретного **класса времени выполнения**;
- один и тот же объект наблюдаем через выражения разных статических типов.

```java
Number n = Integer.valueOf(5); // выражение n: compile-time тип Number,
                               // значение обозначает объект класса Integer
Object o = n;                  // то же значение под ещё более широким статическим типом
System.out.println(o.getClass().getName()); // java.lang.Integer — класс времени выполнения
```

Поэтому «уникальность типа» корректно приписывать **выражению** (`5` — это `int`, `5L` — `long`, `5.0` — `double`, и от выбора зависят диапазон и поведение операций), а не «значению вообще». Полиморфную диспетчеризацию по классу времени выполнения см. [[4.1.5 Static vs Runtime Type]].

## What an expression yields: value, variable, or nothing

Распространено упрощение «каждое выражение даёт значение или бросает исключение». Точнее (JLS §15.1): при **нормальном** завершении выражение даёт один из трёх результатов.

- **Значение** — самый частый случай: `5 + 3` даёт `8` типа `int`.
- **Переменную** — некоторые выражения обозначают ячейку, а не готовое значение; именно поэтому их можно поставить слева от `=`. `a[i]` и `obj.field` — выражения, обозначающие переменную (в C это назвали бы lvalue).
- **Ничто** — вызов метода с типом `void` завершается нормально, но значения не производит. Такое выражение можно использовать только как оператор-выражение или как тело лямбды; во всех прочих местах требуется, чтобы выражение что-то обозначало.

```java
int[] a = {1, 2, 3};
int v = 5 + 3;          // результат — значение: 8
a[1] = v;               // выражение a[1] обозначает ПЕРЕМЕННУЮ (стоит слева от =)
System.out.println(v);  // вызов void-метода: результат — ничто
```

Отдельно от «ничто» стоит **прерывание исключением**: это не нормальное завершение без значения, а abrupt completion — значение не создаётся, и управление уходит по механизму исключений.

```java
int bad = 10 / 0;       // не «ничто», а ArithmeticException: значение не создаётся вовсе
```

## Common Mistakes

- Присваивать переменной результат `void`-метода, ожидая «какое-то» значение.

```java
static void log() { }
int x = log();          // compile-time error: void cannot be converted to int
```
  Правильно: `void`-вызов — это оператор, а не источник значения; если значение нужно — метод должен его возвращать.

- Считать `null` «пустым объектом», у которого можно что-то вызвать.

```java
String s = null;
int len = s.length();   // NullPointerException
```
  Правильно: проверять на `null` или проектировать так, чтобы вместо `null` возвращался пустой объект (`Optional`, пустая коллекция).

- Присваивать `null` примитиву, думая, что «пусто» подходит любому типу.

```java
int n = null;           // compile-time error: <null> cannot be converted to int
```
  Правильно: `null` — значение null-типа, подтип только ссылочных типов; примитиву нужен либо литерал, либо обёртка (`Integer n = null;` компилируется, но при распаковке даст NPE).

- Ожидать, что при исключении переменной присвоится «частичное» значение.

```java
int[] a = new int[2];
int val = a[5];         // ArrayIndexOutOfBoundsException; val не получает значения
```
  Правильно: помнить, что прерванное исключением выражение значения не даёт вовсе.

- Обобщать «значение принадлежит одному типу» на класс времени выполнения: `Object o = "hi";` — статический тип выражения `o` есть `Object`, но объект остаётся `String`, и `o.getClass()` это покажет.
