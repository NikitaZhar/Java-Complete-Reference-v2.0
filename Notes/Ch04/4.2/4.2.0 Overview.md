# 4.2.0 Overview

Примитивных типов ровно восемь, они встроены в язык, имеют фиксированный размер и диапазон, одинаковые на любой платформе, и хранят значение непосредственно — без объекта, без `null`, без нагрузки на сборщик мусора. Этот раздел — точка входа в 4.2: сводная таблица для быстрой справки и деление на группы; чем примитив отличается от ссылочного типа в принципе — уже разобрано в [[4.1.3 High-Level Classification of Types]], здесь это не повторяется.

## The eight primitives at a glance

| Тип | Размер | Диапазон значений | По умолчанию | Обёртка |
|---|---|---|---|---|
| `byte` | 8 бит | −128 … 127 | `0` | `Byte` |
| `short` | 16 бит | −32 768 … 32 767 | `0` | `Short` |
| `int` | 32 бита | −2³¹ … 2³¹−1 | `0` | `Integer` |
| `long` | 64 бита | −2⁶³ … 2⁶³−1 | `0L` | `Long` |
| `char` | 16 бит | 0 … 65 535 (U+0000 … U+FFFF), беззнаковый | `'\u0000'` | `Character` |
| `float` | 32 бита | IEEE 754, ≈ ±3.4·10³⁸ | `0.0f` | `Float` |
| `double` | 64 бита | IEEE 754, ≈ ±1.8·10³⁰⁸ | `0.0` | `Double` |
| `boolean` | не специфицирован | `true` / `false` | `false` | `Boolean` |

Размер `boolean` спецификацией не задан и зависит от JVM — полагаться на «1 бит» или «1 байт» нельзя. Точные значения по умолчанию и когда они применяются (поля против локальных переменных) — [[4.2.14 Default Values and Initialization]].

## Why Java keeps primitives at all

Java подаётся как объектно-ориентированный язык, и логично было бы ожидать, что «всё — объект». Примитивы — сознательное исключение из этого принципа, а не наследие прошлого. Причина в цене объекта: у каждого объекта есть заголовок (метаданные класса, служебные биты для блокировок и GC), он живёт в куче, доступен только через ссылку и нагружает сборщик мусора. Для числа в цикле или флага в условии это неоправданные накладные расходы. Примитив же ложится прямо в регистр или ячейку стека и отображается на машинные инструкции процессора один в один. Отсюда и правило выбора: примитив — когда важны скорость и предсказуемость, обёртка — когда нужен именно объект.

Платой за эту эффективность становятся ограничения, которые и порождают большинство ловушек 4.2: примитив нельзя сделать `null`, положить в generics, вызвать у него метод; он не участвует в полиморфизме. Отдельно стоит `boolean`: в отличие от C, он **не** число — не существует неявного превращения `true`/`false` в `1`/`0` и обратно, и `if (x)` требует именно булева выражения. Это намеренное сужение, убирающее целый класс ошибок вида `if (x = 0)`.

## Three groups

Целочисленные — `byte`, `short`, `int`, `long`, `char`: целые числа и символьные коды; общая механика (представление, переполнение, промоушены, сдвиги) собрана в [[4.2.1 Integral Types]]. С плавающей точкой — `float`, `double`: вещественные числа по IEEE 754, со своими ловушками (`NaN`, бесконечности, потеря точности) — [[4.2.7 Floating-Point Types]]. Логический — `boolean`: только `true`/`false`, без числовых преобразований — [[4.2.10 boolean]].

`char` формально целочисленный (беззнаковый 16-битный код), но по назначению текстовый; его двойственную природу разбирает [[4.2.6 char]], а понятия кодовой точки и кодовой единицы — Ch. 3.1.

## Primitive versus wrapper: when each

Примитив выбирают по умолчанию для вычислений, счётчиков, флагов — он быстрый и не аллоцирует. Обёртка (`Integer`, `Double`, …) нужна там, где требуется объект: элементы коллекций и generics, возможность `null` как «значение не задано». Механика перехода между ними — [[4.2.13 Boxing and Unboxing]].

Практическое следствие: автоупаковка в горячем цикле незаметно создаёт миллионы объектов.

```java
Integer sum = 0;                 // обёртка
for (int i = 0; i < 1_000_000; i++) {
    sum += i;                    // на каждой итерации: unbox → сложение → box (новый Integer)
}
```
Правильно — считать в примитиве, обёртку брать только когда нужен объект:

```java
long sum = 0;                    // примитив: без аллокаций
for (int i = 0; i < 1_000_000; i++) {
    sum += i;
}
```

Ещё одно следствие «не-объектности» примитива — его нельзя положить в generics напрямую и у него нет методов:

```java
List<int> xs;        // compile-time error: только ссылочные типы
int x = 5;
x.hashCode();        // compile-time error: у примитива нет методов
```
