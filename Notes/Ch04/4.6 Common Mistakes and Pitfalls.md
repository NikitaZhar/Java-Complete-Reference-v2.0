# 4.6 Common Mistakes and Pitfalls

| Проблема | Код и наблюдаемый результат | Как исправить | Дом объяснения |
|---|---|---|---|
| Ожидать, что объявленный Number выберет реализацию toString из Number | `Number n = Double.valueOf(3.5); n.toString();` возвращает `"3.5"`: вызывается переопределение экземплярного метода | Различать доступность метода по статическому типу и выбор переопределения по классу объекта | [[4.1.5 Static vs Runtime Type]] |
| Сравнивать содержимое объектов через == | `String a = new String("x"), b = new String("x"); boolean same = a == b;` даёт false | Для строкового содержимого использовать `a.equals(b)`; == оставить проверке тождества и null | [[4.1.8 Common Pitfalls]] |
| Не заметить распаковку null | `Integer boxed = null; int value = boxed;` даёт NullPointerException | До распаковки обработать null либо использовать примитив, если отсутствие значения не нужно | [[4.2.13 Boxing and Unboxing]] |
| Ожидать предупреждения при переполнении | `int next = Integer.MAX_VALUE + 1;` даёт Integer.MIN_VALUE | Для проверки использовать `Math.addExact(Integer.MAX_VALUE, 1)`; он бросит ArithmeticException | [[4.2.1 Integral Types]] |
| Ожидать точного десятичного результата | `boolean exact = 0.1 + 0.2 == 0.3;` даёт false | Выбрать стратегию сравнения по задаче; для точных десятичных расчётов выбрать соответствующее представление | [[4.2.7 Floating-Point Types]] |
| Считать компиляцию каста гарантией успеха | `Number n = Double.valueOf(1.0); Integer i = (Integer) n;` даёт ClassCastException | Проверить допустимый фактический тип или сохранить точный статический тип | [[4.1.5 Static vs Runtime Type]] |
| Переносить ковариантность массивов на generic-список | `List<Integer> ints = new ArrayList<>(); List<Number> nums = ints;` — ошибка компиляции | Для чтения значений как Number использовать совместимую форму `List<? extends Number>`; полные правила — Ch. 20 | [[4.1.6 Subtypes and Supertypes]] |
| Ждать изменения переменной вызывающего от присваивания параметру | При `static void clear(String s) { s = null; }` вызов `String name = "Nik"; clear(name);` оставляет name равным `"Nik"` | Вернуть новое значение из метода с соответствующим типом результата и явно присвоить его вызывающей переменной | [[4.1.7 Runtime Representation of Values]] |
| Ждать default у обычной локальной переменной | `int local; System.out.println(local);` — ошибка компиляции | До чтения выполнить инициализацию или присваивание; default получают поля и компоненты массивов | [[4.2.14 Default Values and Initialization]] |
| Считать final-ссылку неизменяемым объектом | `final int[] a = {1}; a[0] = 2;` допустимо; `a = new int[]{3};` — ошибка компиляции | Различать запрет переприсваивания переменной и изменяемость объекта | [[4.5 Variables]] |

Код в таблице — отдельные диагностические фрагменты. Объявления переменных выполняются в теле метода, а clear объявляется методом класса; для List и ArrayList нужны импорты java.util. Отрицательные строки проверяются отдельно от правильных. Таблица не повторяет полную теорию и не добавляет нового материала после блока ошибок.
