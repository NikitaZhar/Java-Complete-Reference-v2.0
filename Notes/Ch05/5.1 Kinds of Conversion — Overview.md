# 5.1 Kinds of Conversion — Overview

Преобразование (`conversion`) — это правило, связывающее тип выражения-источника с типом, который требуется в данном месте программы. Java — язык со строгой статической типизацией: компилятор в каждой точке знает объявленный тип выражения и тип, который там ожидается, и должен решить, допустим ли переход и что с значением произойдёт. Все допустимые переходы образуют закрытый **каталог родов преобразований**; никаких «преобразований вообще» вне этого каталога не существует. Этот раздел перечисляет роды и вводит вторую ось — контекст, — потому что один и тот же род в разных местах программы то разрешён неявно, то требует явного каста, то запрещён вовсе.

## The catalogue of conversion kinds

JLS SE 25 (§5.1) фиксирует **двенадцать** нумерованных родов. Это не двенадцать равноправных «операций»: forbidden conversion — это правило замыкания каталога, а не действие; unchecked и capture обслуживают дженерики и подробно живут в Ch. 20. Практически значимых родов — восемь, ниже они и разобраны.

Тождественное преобразование (`identity`) — переход типа в самого себя; всегда разрешён и ничего не меняет (Mughal: «identity conversion — из типа в тот же тип»). **Расширяющее примитивное** (`widening primitive`) — из более узкого числового типа в более широкий (`int`→`long`, `int`→`double`); диапазон только растёт, но `int`/`long`→`float` и `long`→`double` могут терять точность. **Сужающее примитивное** (`narrowing primitive`) — из широкого в узкий (`long`→`int`, `double`→`byte`), с возможной потерей величины и знака. **Расширяющее-и-сужающее примитивное** (`widening and narrowing primitive`) — единственный такой случай `byte`→`char` (§5.1.4): `byte` сперва расширяется до `int`, затем `int` сужается до `char`. **Упаковка и распаковка** (`boxing`/`unboxing`) — примитив↔обёртка (`int`↔`Integer`). **Расширяющее и сужающее ссылочное** (`widening`/`narrowing reference`) — вверх и вниз по иерархии типов (`String`→`Object` и обратно). **Строковое** (`string`) — любое значение → `String` в конкатенации.

Ещё два рода — `unchecked` (между «сырым» и параметризованным типом) и `capture` (захват `wildcard`) — обслуживают дженерики; их дом Ch. 20, здесь они только названы. Отдельно стоит **запрещённое преобразование** (`forbidden`) — не отдельная операция, а обозначение пар типов, между которыми перехода нет (например, `boolean` и любой числовой тип): попытка приводит к ошибке компиляции.

| Род преобразования | Пример | Потеря информации | Проверка в runtime |
|---|---|---|---|
| Identity | `int`→`int` | нет | нет |
| Widening primitive | `int`→`long`, `int`→`double` | возможна (точность) | нет |
| Narrowing primitive | `long`→`int`, `double`→`byte` | да | нет |
| Widening and narrowing primitive | `byte`→`char` | да (знак/диапазон) | нет |
| Boxing | `int`→`Integer` | нет | нет |
| Unboxing | `Integer`→`int` | нет | да (`null`→NPE) |
| Widening reference | `String`→`Object` | нет | нет |
| Narrowing reference | `Object`→`String` | нет | да (`ClassCastException`) |
| String | `int`→`String` (в `+`) | нет | нет |

```java
byte b = 65;
char c = (char) b;     // widening-and-narrowing: byte→int→char, здесь 'A'
byte neg = -1;
char c2 = (char) neg;  // 65535: знаковое расширение до int (-1), затем сужение до char
```

### Historical note: value set conversion

В каталоге Java SE 16 и ранее был тринадцатый род — **преобразование множеств значений** (`value set conversion`), связанный с расширенной экспонентой вещественных на некоторых платформах и ключевым словом `strictfp`. Начиная с Java 17 арифметика с плавающей точкой **всегда строгая**, `strictfp` объявлен устаревшим (Mughal: «strictfp obsolete as of Java SE 17»), и value set conversion из Chapter 5 **удалён**. В актуальном каталоге SE 25 его нет — здесь он упомянут только как историческая заметка, чтобы старые источники не сбивали с толку.

## The second axis: contexts

Знать род недостаточно: разрешённость перехода зависит от **контекста** — синтаксического места, где стоит выражение. JLS SE 25 различает **шесть крупных семейств** контекстов (семь видов, если strict и loose invocation считать раздельно): присваивание (assignment), вызов метода (invocation — strict и loose), строковый (string), каст (casting), числовой (numeric) и **проверочный** (testing — для `instanceof`-паттернов и pattern `switch`). Каждый контекст допускает **своё подмножество** родов.

```java
int i = 100;
long a = i;            // assignment context: widening primitive — неявно ок
Integer b = i;         // assignment context: boxing — неявно ок
byte cc = 100;         // assignment context: narrowing КОНСТАНТЫ — исключение, ок без каста
byte d = i;            // ошибка компиляции: narrowing переменной в assignment запрещено неявно
byte e = (byte) i;     // casting context: narrowing разрешено явным кастом
```

Одно и то же сужение `int`→`byte` здесь то запрещено (`d`), то разрешено как исключение для константы (`cc`), то разрешено кастом (`e`). Именно пересечение «род × контекст» задаёт правило, а не род сам по себе. Полная карта «контекст → допустимые роды» — в [[5.8 Conversion Contexts — Overview]].

## Implicit versus explicit

Преобразование бывает **неявным** (компилятор применяет его сам, если контекст позволяет) или **явным** (программист пишет каст `(Type)`). Как правило, расширяющие переходы неявны, сужающие требуют явного каста. Каст не только разрешает сужение — он же служит подсказкой при разрешении перегрузки и при работе с обёртками; подробнее — [[5.11 Casting Contexts]].

```java
double x = 5;          // неявное widening: int-литерал 5 → double
int y = (int) 5.9;     // явное narrowing: нужен каст, дробная часть отбрасывается → 5
```

## Common Mistakes

- Считать, что «преобразование либо есть, либо нет» вне зависимости от места. Один и тот же род то неявен, то требует каста, то запрещён — смотреть надо на контекст.

```java
long big = 10;
int small = big;          // DOES NOT COMPILE: narrowing переменной неявно нельзя
```
  Правильно: `int small = (int) big;` — явный каст в casting-контексте (с осознанием возможной потери).

- Путать «расширяющее» с «без потерь»: расширение `int`→`float` или `long`→`double` укладывает значение в тип с большим диапазоном, но точность при этом может теряться (см. [[5.2 Identity and Widening Primitive Conversion]]).

- Считать value set conversion действующим родом SE 25 (частая ошибка из старых источников). Его в каталоге больше нет; `byte`→`char`, наоборот, — полноценный отдельный род (§5.1.4).
