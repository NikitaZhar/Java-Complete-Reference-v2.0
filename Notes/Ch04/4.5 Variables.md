# 4.5 Variables

Переменная — типизированная ячейка хранения значения. Поля, параметры и локальные переменные обычно имеют имена; компоненты массива не именованы, а в разрешённых контекстах Java SE 25 допускает неназываемые переменные с _. Раздел описывает виды переменных, final и var; defaults — [[4.2.14 Default Values and Initialization]], definite assignment — Ch. 16.

## The eight kinds of variables

JLS выделяет восемь видов переменных: поля класса, поля экземпляра, компоненты массива, параметры метода, конструктора и лямбды, параметры исключения и локальные переменные. Поле класса создаётся при подготовке класса или интерфейса и получает default; прекращает существовать при их выгрузке. Поле экземпляра и компонент массива создаются с объектом. Параметры метода, конструктора и лямбды создаются при вызове или применении и получают аргументные значения. Параметр исключения создаётся при перехвате исключения и получает ссылку на него. Локальные переменные объявляются операторами, в том числе в for и try-with-resources, либо образцами; их создание и инициализация регулируются соответствующей конструкцией. Этапы подготовки и инициализации класса — Ch. 18.

Переменные образца (pattern variables), вводимые `instanceof`-паттернами и `switch`, — **не девятый вид, а частный случай локальной переменной** (их семантика — Ch. 14.7). Это важно для точного счёта: видов ровно восемь.

Ключевое различие, определяющее поведение, — между полями и компонентами массива, которые при создании получают значение по умолчанию, и локальными переменными и параметрами, которые дефолта не получают.

```java
class User {
    static int count;      // поле класса: по умолчанию 0
    String name;           // поле экземпляра: по умолчанию null
    void greet() {
        int shown;         // локальная: без значения по умолчанию
        System.out.println(shown); // compile-time error: might not have been initialized
    }
}
```

Значения по умолчанию по типам и причину, почему у локальных их нет, разбирает [[4.2.14 Default Values and Initialization]].

## final, blank final, constant, and effectively final

Модификатор `final` фиксирует **переменную**: после первого присваивания её нельзя переприсвоить. Для примитива это неизменное значение, для ссылки — неизменная ссылка (но **не** неизменный объект — см. [[4.1.7 Runtime Representation of Values]]).

```java
final int MAX = 100;
// MAX = 200;            // compile-time error

final List<Integer> xs = new ArrayList<>();
xs.add(1);              // ок: объект изменяем
// xs = List.of();      // compile-time error: ссылку переприсвоить нельзя
```

Форм у `final` несколько, и различать их полезно.

**Blank final** — final-переменная без инициализатора. Значение можно присвоить позже, но не более одного раза на допустимом пути; перед чтением должно быть доказано definite assignment. Локальная blank final, которую не читают, может остаться неприсвоенной. Для blank final полей действуют требования обязательного присваивания; полный анализ — Ch. 16. Например, значение поля можно выбрать в конструкторе, а локальной переменной — по одной из ветвей условия.

```java
// Фрагмент тела метода: boolean fast() определён в классе.
final int limit;
if (fast()) limit = 10; else limit = 100;  // присвоено один раз по любой ветке
```

**Constant variable** — это не просто `final`. По JLS §4.12.4 это `final`-переменная **примитивного типа или `String`**, инициализированная **константным выражением** (§15.29). Такие переменные особенные: их значение известно на компиляции, поэтому оно инлайнится, участвует в constant folding и допускается там, где нужна компилируемая константа — в метках `case`, в аннотациях (Boyarsky: в `case` можно только литералы, enum-константы и константные переменные).

```java
static final int LIMIT = 100;       // constant variable
static final int COMPUTED = compute(); // просто final, НЕ constant: инициализатор не константа

int day = readDay();
switch (day) {
    case LIMIT -> handle();   // ок: LIMIT — константная переменная
    // case COMPUTED -> ...   // compile-time error: не константа
    default -> {}
}
```

**Effectively final** — переменная, которую фактически не переприсваивают после инициализации, даже без слова `final`. Быстрый тест (Boyarsky): мысленно добавить `final` — если код всё ещё компилируется, переменная фактически финальна. Это важно для лямбд и локальных классов: захватывать можно только `final` или фактически финальные локальные переменные. Полностью тема захвата — Ch. 16.

```java
int base = 10;          // не меняется дальше → фактически финальная
Runnable r = () -> System.out.println(base); // ок: захват разрешён
// base = 20;           // если раскомментировать — лямбда выше перестанет компилироваться
```

`final` применим и к **параметрам метода** и **параметру `catch`**: он запрещает переприсваивание внутри тела, но на вызывающего не влияет (аргумент всё равно передаётся по значению, [[4.1.7 Runtime Representation of Values]]).

```java
static int f(final int p) {
    // p = p + 1;       // compile-time error: параметр final
    return p + 1;
}
```

## Local variable type inference: var

С Java 10 локальную переменную можно объявить через `var` — компилятор выводит её тип из инициализатора. Важно не понять это неверно: `var` — **не** динамическая типизация и не «переменная без типа». Тип по-прежнему статический и фиксируется в момент объявления, просто не записан явно. `var list = new ArrayList<String>()` — это ровно `ArrayList<String> list = …`: в такой список можно класть `String` (`list.add("s")` работает), а вот **переприсвоить саму переменную** значением, несовместимым с выведенным типом, нельзя. Для ссылочного выведенного типа допустимы совместимые значения подтипов и null; для примитивного типа null недопустим.

```java
var list = new ArrayList<String>(); // выведен тип ArrayList<String>
list.add("s");                       // ок: String — допустимый элемент
var n = 42;                          // int
var sum = 0L;                        // long
// list = "text";                    // compile-time error: тип переменной уже ArrayList<String>
```

var разрешён для обычной локальной переменной с инициализатором, переменной basic for, переменной enhanced for и ресурса try-with-resources. Инициализатор может занимать несколько строк; в enhanced for тип выводится из перебираемого выражения. Для параметров лямбды есть отдельная форма с Java 11. Для полей, обычных параметров метода и возвращаемого типа var недопустим. Ограничения обычного локального объявления:

```java
// var y;                // нет инициализатора — выводить не из чего
// var z = null;         // из null тип не выводится (был бы Object — почти всегда не то, что нужно)
// var a = { 1, 2 };     // массивный инициализатор без типа — нельзя (нужно new int[]{...})
// var a = 1, b = 2;     // несколько переменных в одном объявлении с var — нельзя
// var self = self;      // ссылка на себя в инициализаторе — тип ещё не выведен
// class C { var f = 1; } // не для полей
```

Единственное послабление среди нелокальных позиций — параметры лямбды: `(var a, var b) -> …` допустимо с Java 11, но по принципу «всё или ничего» и в основном ради аннотаций на параметрах.

Выбор `var` — вопрос читаемости, а не экономии символов. Он уместен, когда тип очевиден из правой части (`var users = userRepository.findAll()`), и вреден, когда прячет неочевидный тип. Правила вывода типов в целом (обобщённые методы, ромбовидный оператор, целевая типизация poly-выражений) — Ch. 20.

## Common Mistakes

- Считать final-ссылку гарантией неизменяемости объекта. Правильно: final запрещает переприсваивание переменной; изменяемость объекта определяется его API. Record фиксирует ссылки компонентов, но не делает их объекты неизменяемыми. List.copyOf создаёт неизменяемую структуру списка, но не копирует глубоко изменяемые элементы.

- Путать `final` и constant variable: только константная переменная (примитив/`String` из константного выражения) годится в `case` и аннотации.

```java
final int a = 5;            // constant variable → годится в case
final int b = new java.util.Random().nextInt(); // просто final → в case нельзя
```

- Ожидать, что `var` умеет то, чего не умеет.

```java
// var n = null;         // compile-time error: тип не вывести
// var a = 1, b = 2;     // compile-time error: var — не для составного объявления
```
Правильно: обычное локальное объявление var содержит одну переменную с допустимым инициализатором; переносы строк разрешены. Для enhanced for и параметров лямбды действуют отдельные формы (см. основной раздел выше).

- Пытаться захватить в лямбде изменяемую локальную переменную.

```java
int sum = 0;
list.forEach(x -> sum += x);  // compile-time error: sum не (effectively) final
```

Правильно: не мутировать захваченную переменную; использовать поток-редукцию (`list.stream().mapToInt(...).sum()`) или аккумулятор-поле.

Переприсваивать параметр multi-catch.

```java
// В теле метода, с import java.io.IOException:
try {
    if (System.nanoTime() > 0) throw new IOException();
    throw new IllegalArgumentException();
} catch (IOException | IllegalArgumentException e) {
    // e = new IOException(); // compile-time error: параметр multi-catch final
    Exception separate = e;
    separate = new IOException(); // допустимо: отдельная локальная переменная
}
```
