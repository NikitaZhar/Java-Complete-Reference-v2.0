# 4.1.6 Subtypes and Supertypes

Подтипирование — это отношение «где можно подставить одно вместо другого». Если `B` — подтип `A` (пишут `B <: A`), то значение `B` разрешено использовать в любом контексте, ожидающем `A`, без нарушения типобезопасности; `A` при этом надтип `B`. На этом отношении держатся наследование, интерфейсы, полиморфизм и совместимость при присваивании. Здесь — само отношение и его источники; механику преобразований по иерархии (upcast/downcast, контексты) см. Ch. 5, а полиморфную диспетчеризацию — [[4.1.5 Static vs Runtime Type]].

## Nominal subtyping

Java использует номинальную систему типов: подтип возникает только из явных деклараций `extends`/`implements`, а не из совпадения структуры. Совпадение полей и методов ничего не значит без объявленного отношения.

```java
class Point { int x, y; }
class Pixel { int x, y; }   // та же форма

Point p = new Pixel();      // compile-time error: Pixel не подтип Point
```

## Sources of the subtype relation

Отношение `B <: A` возникает из нескольких источников:

Наследование классов — `class B extends A` даёт `B <: A`. Реализация интерфейса — `class C implements I` даёт `C <: I`. Корень иерархии — `Object` является надтипом всех ссылочных типов, включая массивы. Массивы ковариантны — если `T <: S`, то `T[] <: S[]` (удобно, но небезопасно при записи — см. Ch. 13). Нижний элемент — null-тип является подтипом всех ссылочных типов, поэтому `null` присваивается любой ссылочной переменной.

```java
Number n = Integer.valueOf(5); // Integer <: Number  (upcast, без приведения)
Object o = n;                  // Number <: Object
String[] ss = { "a" };
Object[] os = ss;              // String[] <: Object[] (ковариантность массивов)
Runnable r = null;             // null-тип <: любой ссылочный тип
```

Подстановка подтипа вместо надтипа (upcast) неявна и всегда безопасна; обратный переход (downcast) требует явного приведения и проверяется в runtime.

```java
class Deer {}
class Reindeer extends Deer {}

Deer d = new Reindeer();       // upcast — неявно
Reindeer r = (Reindeer) d;     // downcast — нужен каст; выполнится, тип совпал

Deer plain = new Deer();
Reindeer bad = (Reindeer) plain; // компилируется, но ClassCastException в runtime
```

## Generics are invariant

В отличие от массивов, обобщённые типы **инвариантны**: `List<String>` не является ни подтипом, ни надтипом `List<Object>`, хотя `String <: Object`. Так язык закрывает дыру, которую у массивов оставляет ковариантность. Гибкость возвращают wildcards (`? extends T`, `? super T`) — их полный разбор в Ch. 20.

```java
List<String> ls = new ArrayList<>();
List<Object> lo = ls;   // compile-time error: generics инвариантны
List<? extends Object> ok = ls; // так — можно (ковариантный wildcard, только чтение)
```

## Common Mistakes

- Переносить интуицию массивов на generics и ждать ковариантности.

```java
List<Integer> ints = new ArrayList<>();
List<Number> nums = ints;   // compile-time error
```
  Правильно: использовать `List<? extends Number>` для чтения или `List<? super Integer>` для записи (PECS, Ch. 20).

- Полагаться на ковариантность массивов при записи.

```java
Number[] a = new Integer[3];
a[0] = 3.14;   // компилируется, но ArrayStoreException в runtime
```
  Правильно: не смешивать фактический компонентный тип массива с типом переменной; при необходимости — `List<Integer>` вместо `Integer[]`.
