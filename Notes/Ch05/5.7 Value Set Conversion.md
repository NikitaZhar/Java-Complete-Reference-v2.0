# 5.7 Value Set Conversion (historical note)

**Это не действующий род преобразования Java SE 25.** Преобразование множеств значений (value set conversion) было отдельным родом в каталоге JLS до SE 16 включительно, но удалено из Chapter 5 с Java 17. Актуальный каталог родов — в [[5.1 Kinds of Conversion — Overview]]; этот файл оставлен как историческая заметка, чтобы старые источники (и книги, писавшиеся до Java 17) не вводили в заблуждение. Структурно его можно и вовсе убрать, свернув в историческую сноску 5.1.

## What it was

JLS раньше определял для `float` и `double` по два множества значений: стандартное (ровно IEEE 754 для 32/64 бит) и расширенное по экспоненте (та же мантисса, но более широкий диапазон экспоненты — как в 80-битных регистрах x87). Value set conversion описывало момент, когда промежуточный результат, хранившийся с расширенной экспонентой, приводится к стандартному представлению. Оно могло дать другой результат только там, где вычисление шло в расширенной точности и затем «схлопывалось»; на сами битовые представления `float`/`double` в памяти оно не влияло.

## Why it is gone: always-strict since Java 17

До Java 17 поведением управляло ключевое слово `strictfp`: помеченный им класс или метод обязан был использовать только стандартные множества, гарантируя побитово одинаковый результат на любой платформе; без него JVM могла пользоваться расширенной точностью. С Java 17 (JEP 306, «Restore Always-Strict Floating-Point Semantics») вся арифметика с плавающей точкой снова **всегда строгая**: расширенные множества не используются, результат детерминирован независимо от платформы. Поэтому род value set conversion из каталога убран, а `strictfp` объявлен устаревшим (Mughal: «strictfp obsolete as of Java SE 17») — он сохранён лишь для совместимости и ничего не меняет. Компилятор актуального JDK на него даже предупреждает:

```java
strictfp class Calc { }   // warning: as of release 17 ... 'strictfp' is not required
```

Практический вывод: на Java 17+ о value set conversion думать не нужно — вычисления `float`/`double` уже воспроизводимы. Свойства самих вещественных типов (IEEE 754, `NaN`, `Infinity`, потеря точности) — дом [[4.2.7 Floating-Point Types]].

## Common Mistakes

- Ставить `strictfp` в новом коде, считая, что он «повышает точность». На Java 17+ он ничего не даёт (строгость включена всегда) и вызывает предупреждение компилятора. Правильно: не использовать его в новом коде.

- Считать value set conversion действующим родом SE 25 из-за старого источника. Правильно: в актуальном каталоге ([[5.1 Kinds of Conversion — Overview]]) его нет.
