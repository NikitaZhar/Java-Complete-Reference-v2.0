# 4.1.7 Runtime Representation of Values

Тип определяет не только допустимые операции, но и форму, в которой значение существует во время выполнения. Практически важны два факта: примитивная переменная **содержит само значение**, а ссылочная — **ссылку на объект** в куче (или `null`); и то, и другое при присваивании и передаче в метод **копируется**. Из этих двух фактов выводится всё поведение с общими объектами и передачей аргументов. Модель памяти для многопоточности (видимость, happens-before, роль `final` при публикации) — отдельная тема Ch. 19; представление в class-файле и constant pool — Part II.

## What a variable holds

Примитивная переменная хранит значение напрямую. Ссылочная переменная хранит ссылку — путь к объекту в куче; сам объект живёт в куче независимо от того, где объявлена переменная. Несколько ссылок могут указывать на один объект.

```java
int x = 10;             // x содержит само значение 10
String s = "Java";      // s содержит ссылку на объект String в куче

int[] a = {1, 2, 3};
int[] b = a;            // b — копия ссылки; a и b указывают на один массив
b[0] = 99;
System.out.println(a[0]); // 99 — объект общий
```

## Copy on assignment, copy on call: Java is pass-by-value

Java всегда передаёт аргументы **по значению**. Для примитива копируется само значение. Для ссылочного типа копируется **ссылка**, а не объект — поэтому через параметр можно изменить состояние переданного объекта, но нельзя заставить исходную переменную указывать на другой объект.

```java
static void reassign(int[] arr) {
    arr = new int[] {0};   // переназначается только локальная копия ссылки
}
static void mutate(int[] arr) {
    arr[0] = 99;           // меняется общий объект
}

int[] data = {1, 2, 3};
reassign(data);
System.out.println(data[0]); // 1 — исходная ссылка не тронута

mutate(data);
System.out.println(data[0]); // 99 — состояние объекта изменено
```

Тот же принцип объясняет, почему метод не может «обнулить» чужую переменную: присваивание `param = null` внутри метода меняет лишь копию ссылки.

## null is a value too

`null` занимает то же место, где была бы ссылка, но не указывает ни на какой объект. Любое обращение к члену через `null` даёт `NullPointerException`. Подробнее о null-типе — [[4.3 Reference Types and Values]].

```java
String s = null;
System.out.println(s.length()); // NullPointerException
```

## Common Mistakes

- Ждать, что переприсваивание параметра-ссылки изменит переменную у вызывающего.

```java
static void clear(String s) { s = null; }
String name = "Nik";
clear(name);
System.out.println(name); // Nik — не null: менялась копия ссылки
```
  Правильно: чтобы вернуть новое значение — возвращать его из метода (`name = clear(name)`), а не рассчитывать на побочный эффект.

- Считать `final`-ссылку гарантией неизменяемости объекта.

```java
final List<Integer> xs = new ArrayList<>();
xs.add(1);              // ок: сам объект изменяем
// xs = new ArrayList<>(); // compile-time error: нельзя переприсвоить ссылку
```
  Правильно: `final` фиксирует ссылку, а не содержимое; для неизменяемости нужен неизменяемый объект (`List.copyOf`, `List.of`).
