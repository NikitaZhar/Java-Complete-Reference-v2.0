# 4.1.8 Common Pitfalls

Сводка типичных ошибок раздела 4.1. Все они — от смешения уровней: тип против значения, статический тип против исполняемого, ссылка против объекта. Формат: проблема → код → как правильно. Механику каждой темы см. в соответствующем подразделе.

## Reference equality instead of value equality

`==` у ссылок сравнивает тождество (одна ли это ссылка), а не содержимое.

```java
String a = new String("abc");
String b = new String("abc");
boolean same = (a == b);   // false, хотя содержимое одинаковое
```
Правильно: содержимое сравнивать через `equals`; `==` оставить примитивам, проверке `null` и тождества.

## == on boxed values and the cache trap

Автоупаковка кэширует `Integer` в диапазоне −128..127, поэтому `==` иногда «случайно» истинен, а вне диапазона — ложен.

```java
Integer x = 127, y = 127;
Integer p = 128, q = 128;
System.out.println(x == y); // true  (из кэша)
System.out.println(p == q); // false (разные объекты)
```
Правильно: обёртки сравнивать через `equals`. Детали кэша — [[4.2 Primitive Types and Values]] и Ch. 49.

## Unboxing a null

Распаковка `null`-обёртки в примитив падает с `NullPointerException`.

```java
Integer boxed = null;
int n = boxed;             // NullPointerException при распаковке
```
Правильно: проверять на `null` до распаковки или держать значение в примитиве.

## Declared type is expected to change dispatch

Поведение переопределённого метода задаёт фактический тип объекта, а не тип переменной.

```java
Object o = "text";
System.out.println(o.toString()); // берётся String.toString(), не Object
```
Правильно: рассчитывать на исполняемый тип; подробнее — [[4.1.5 Static vs Runtime Type]].

## Cast compiles, therefore it will run

Компиляция приведения не гарантирует его успех в runtime.

```java
Object o = List.of(1);
String s = (String) o;     // ClassCastException
```
Правильно: проверять `instanceof` перед downcast.

## Array covariance abused on write

Массивы ковариантны, но компонентный тип проверяется при записи.

```java
Object[] arr = new String[1];
arr[0] = 42;               // ArrayStoreException
```
Правильно: не смешивать фактический компонентный тип с типом переменной; см. Ch. 13.

## Expecting generics covariance

`List<String>` не подтип `List<Object>` — generics инвариантны.

```java
List<String> ls = new ArrayList<>();
List<Object> lo = ls;      // compile-time error
```
Правильно: wildcards `? extends` / `? super` (PECS, Ch. 20).

## Reassigning a parameter to affect the caller

Аргументы передаются по значению; переприсваивание параметра не меняет переменную вызывающего.

```java
static void clear(String s) { s = null; }
String name = "Nik"; clear(name);
System.out.println(name);  // Nik
```
Правильно: возвращать новое значение из метода; см. [[4.1.7 Runtime Representation of Values]].
