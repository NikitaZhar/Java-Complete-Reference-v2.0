Обе грамматики Java записаны в одной нотации, и умение её читать — это умение находить точное правило в спецификации и понимать, что именно разрешено. Нотация компактна: несколько метасимволов задают выбор, необязательность и повторение. Здесь разбирается сам аппарат; конкретные правила лексики и синтаксиса — в 2.2 и 2.3.

## Terminals and Nonterminals

Грамматика оперирует терминалами и нетерминалами. Терминалы дальше не раскрываются: в лексической грамматике это Unicode-символы, в синтаксической — токены, например `if`, `(`, `;`. Нетерминалы обозначают категории, например *Expression* и *Statement*, и раскрываются через продукции. Вывод последовательно заменяет нетерминалы, пока не останутся терминалы. В JLS терминалы набраны моноширинным шрифтом, нетерминалы — курсивом; обычные текстовые блоки ниже не воспроизводят это различие начертания.

## Productions and the Goal Symbol

Правило (продукция) связывает нетерминал слева с последовательностью символов справа:

```
IfThenStatement:
    if ( Expression ) Statement
```

В контекстно-свободной грамматике (context-free grammar) левая часть продукции — один нетерминал: применимость продукции определяется этим символом, а не его соседями. Вывод начинается с целевого символа (goal symbol): `Input` для лексики, `CompilationUnit` для синтаксиса. Последовательность терминалов должна выводиться из соответствующего целевого символа; семантическая корректность проверяется отдельными правилами.

## Notation Metasymbols

Правые части используют `[x]` для нуля или одного вхождения и `{x}` для нуля или более. Альтернативы располагаются после двоеточия на отдельных строках; перенос длинной правой части с явным отступом продолжения не создаёт новую альтернативу. `(one of)` сокращает перечисление вариантов, `but not` задаёт исключения. Например, правило идентификатора исключает зарезервированные ключевые слова, булевы литералы и `null`. Здесь используется нотация JLS SE 25.

Отдельный случай — нетерминалы, которые непрактично раскрывать перечислением всех альтернатив: их задают повествовательной фразой обычным (не моноширинным) шрифтом. Например, `RawInputCharacter: любой символ Unicode, представимый в UTF-16`. Такое определение читается как обычный текст-описание, а не как формальная продукция, но играет ту же роль — задаёт, что подставляется вместо нетерминала.

Метасимволы отличаются от терминалов языка. Например, `[Identifier]` обозначает необязательный элемент, а моноширинные `[` и `]` в продукции могут обозначать обязательные скобки Java. Значение определяется оформлением и контекстом.

## Reading a Rule

Необязательный элемент. Правило `break`:

```
BreakStatement:
    break [Identifier] ;
```

Это две синтаксические формы `break`; их допустимость зависит от контекста. Первая требует охватывающего цикла или оператора `switch`, вторая — допустимого охватывающего оператора с меткой `outerLoop`. Метка не обязательно принадлежит циклу. Ограничения перехода через вложенные конструкции — Part I, Ch. 14.

```java
break;
break outerLoop;
```

Повторение. Список аргументов:

```
ArgumentList:
    Expression { , Expression }
```

Один или больше аргументов через запятую: `f(x)`, `f(x, y)`, `f(x, y, z)`. Пустая последовательность не выводится из `ArgumentList`: форма `f()` разрешена потому, что правило вызова использует `[ArgumentList]`.

Композиция. Базовый `for` сочетает необязательные части:

```
BasicForStatement:
    for ( [ForInit] ; [Expression] ; [ForUpdate] ) Statement
```

Ниже — три независимых фрагмента тела метода. В первых двух `n` — доступная переменная типа `int`; во втором также заранее объявлена переменная `i` типа `int`.

```java
for (int i = 0; i < n; i++) {}
for (; i < n; i++) {}
for (;;) { break; }
```

Ключевой навык — различать необязательность синтаксического элемента и значение его отсутствия, определяемое отдельным правилом. Например, у абстрактного метода нет исполняемого тела, но в продукции `MethodBody` присутствует терминал `;`; это не пустой блок `{}`. Правила методов — Part I, Ch. 8; ошибки чтения нотации — [[2.5 Common Mistakes]].
